# ドギド サーバー（Mac管理アプリ）

`apps/ドギド サーバー.app` を開き、本体とマイクをそれぞれ起動・停止します。起動済みなら起動元に関係なく状態を表示します。既定の「対話・分類」タブに入力・分類・返答を時刻付きで表示します。分類は川柳8分類／通常対話16分類の区分、日本語名、元のラベル名、確率を表示し、区分内で色分けします。川柳と通常対話の間では同じ色を再利用します。「本体の出力」「マイクの出力」で標準出力・標準エラーを確認できます。ウィンドウを縦に広げるとログ欄が広がります。「発言履歴を開く」で発言だけの画面を開けます。

アプリを開くだけでは本体を起動せず、閉じても稼働中の本体・マイクを停止しません。マイクは本体の稼働を確認してから起動できます。外部ターミナルへ直接出力していてログファイルがないプロセスの過去出力は、起動元で確認します。

## ビルド・検査

macOS 13以降とXcode Command Line Toolsを使います。本体の既存 `dogido-llm` 環境・設定・起動ファイルを利用します。リポジトリのルートから実行してください。

初回だけキーチェーンアクセスの「証明書アシスタント」から、名前 `Dogido Local Code Signing`、固有名のタイプ「自己署名ルート」、証明書のタイプ「コード署名」で、このMac用の証明書をログインキーチェーンへ作成します。以後も同じ証明書を使い、更新をまたいでmacOSのアクセス許可を引き継ぎます。既存の署名証明書を使う場合は `--signing-identity` に名前またはSHA-1を指定できます。

```sh
python3 apps/dogido-server-manager/Tools/build_app.py --output 'apps/ドギド サーバー.app'
python3 apps/dogido-server-manager/Tools/run_tests.py
python3 apps/dogido-server-manager/Tests/test_signing.py
```

ビルドは既存アプリを上書きしません。更新時は別の出力名を指定します。アプリにはビルド元フォルダを登録するため、本体を移動した場合は再ビルドします。検査は一時フォルダと空きポートの模擬プロセスだけを起動・停止します。

署名証明書が未作成・曖昧な場合はビルドを中止します。一時的な試用では `--ad-hoc` を明示できますが、この方式では更新後に書類フォルダなどのアクセス許可が再確認される場合があります。固定署名へ切り替えた初回も許可し直しが必要です。

アプリから起動したログは `.dogido_tools/server-manager/logs/` に追記します。発言履歴は既存 `/dogido?view=utterances` を使い、本体再起動時に消える表示履歴です。仕様と検証範囲は[実装記録](../../docs/2026-10-11-server-manager-and-checks.md)を参照してください。

対話・分類は既存の表示APIから3秒ごとに読み取ります。本体停止・通信失敗時は、管理アプリ内に取得済みの対話とその旨を表示します。本体が再起動すると保持対話は空になります。[対話ログの更新記録](../../docs/2026-10-16-server-manager-dialogue-log.md)を参照してください。

新ラベルの日本語名と色・確率の対応は[2026-10-25の更新記録](../../docs/2026-10-25-server-manager-classifier-labels.md)に記載しています。
