# プレイヤーの視野進入を先読みする試験

既存の診断snapshotから身体とプレイヤーの座標・実視認を収集し、過去2点で進入を予測します。本体へ発話・移動を指示せず、会話のchangesや記憶も変更しません。

**実装済み:** 収集、記録再生、予測の採点、固定生成時間を仮定した待ち時間の比較。  
**初回実測:** [2026-10-21の飛行を含む予備試験](../../docs/research/2026-10-21-vision-entry-run-01.md)。220サンプル・17回の進入を採点済み。
**未実施:** 平地歩行の基準測定、LLM生成の前倒し、TTSを含む実反応の比較。

**合意した方針:** LLMは返答生成の一回だけ、予測・補正・発話タイミングはコード側です。この試験器のLLM呼出しは0回で、実発話との接続はこれからです。[次回の実測手順と接続の境界](../../docs/research/2026-10-21-vision-temporal-integration.md#10-合意した方針と次回の再開手順2026-10-21)から再開します。

## 最初の条件

- 明るく平坦で、壁や木に遮られない場所。立って歩き、最初は走る・泳ぐ・しゃがむ・テレポートを避けます。
- ドギドの視野外から中へ、左右それぞれ5回ずつ入ります。見えた状態と見えない状態をそれぞれ3秒程度保ちます。
- 次に、視野へ入る前に引き返す動きを5回行います。外れる例も必ず記録します。
- 身体の現在の動作設定は保ちます。予測には身体の移動・顔の回転も含め、その予測が外れた結果も残します。

## 収集と採点

試験用診断を含むRust本体とMinecraftを通常どおり起動してから、リポジトリのルートで実行します。接続が一つならsessionは自動選択。複数なら`--session`で対象を指定します。既存ファイルは上書きしません。

```bash
python3 dev_tools/vision_entry_probe/probe.py record \
  --duration 180 --output .dogido_tools/vision-entry/run-01.jsonl

python3 dev_tools/vision_entry_probe/probe.py analyze \
  .dogido_tools/vision-entry/run-01.jsonl \
  --response-ms 1600 --horizon-ms 2500 \
  --output .dogido_tools/vision-entry/run-01-summary.json
```

`response-ms=1600`は比較用の仮定です。以前の画像試験の応答時間帯を参考にしていますが、この試験のLLM実測値ではありません。1600ms後に候補が完成すると仮定し、視認を検知してから生成を始める場合と、先読みで開始する場合を同じ値で比較します。TTS・再生待ち・発話中の優先順位・生成内容の成立は未評価です。

確認する指標:

| 出力 | 意味 |
|---|---|
| `outcomes.hit / miss` | 予測期限内の視認遷移を採取／期限内の遷移を採取できなかった |
| `outcomes.uncertain` | 観測間隔が予測の対象時間の境界をまたぎ、断定できない |
| `outcomes.censored` | 記録末尾・欠損・世代変更で追跡できず、採点しない |
| `precision_interval` | 判定不能分を含めた的中率の下限・上限 |
| `recall_interval` | 観測できた対象の進入のうち、先読みできた割合の下限・上限 |
| `median_entry_bracket_ms` | 進入時刻を絞れた区間の幅。0msの精度とは扱わない |
| `median_estimated_saved_ms_on_confirmed_hits` | 的中例で削減できる生成待ちの試算。実発話の測定ではない |

## 計測の境界

取得先は既存`/api/v1/rust-dialogue/snapshot`の`body_probe`。session instance・owner・body・epoch・dimension・tick・revisionを照合し、重複サンプルを除きます。欠損・順序逆転・2秒を超える間隔を挟んで速度を推定しません。身体・プレイヤーとも12 block/秒、顔の回転180度/秒を超える観測対では予測しません。

既定のadapter送信は通常約1秒、body bridgeは約0.5秒間隔です。GETを100ms間隔にしても、新しい座標は増えません。進入時刻は「直前の不可視サンプル〜初回可視サンプル」の区間で示し、HTTP往復時間ぶんも広げます。age由来の時刻には元の観測・転送時計の誤差が残り、描画フレームや実際に目に入った瞬間を測定したものではありません。

指標の対象は**採取できた視認遷移**です。サンプル間に一瞬だけ入り、すぐ出た場合は捕捉できず、進入数にも入りません。`miss`は「絶対に一度も見えなかった」という意味ではありません。初回は3秒程度の滞在を入れます。短い横切りも含む連続時間の評価には、ゲーム側での進入イベント保持または細かな正解記録が別途必要です。

予測は過去2点の等速・等角速度と、既存の視野角規約を使います。プレイヤーの高さ1.8 blockと身体の眼からの3点を仮定します。しゃがみ・水泳などの姿勢変化は今回の対象外。未来の遮蔽は予測せず、正解には本体から来た実ray判定を使います。一つの不可視区間で候補は最大一件です。外れたあとに繰り返し予測を出して成功件数を増やしません。

JSONLにはこの試験の座標と識別情報だけを保存し、会話本文・全snapshot・画像は保存しません。合成データは`evidence=synthetic`で区別し、実測と同じ集計へ混ぜません。画像を作らないため、一時画像の24時間保持とは別です。

```bash
python3 -m unittest discover -s dev_tools/vision_entry_probe -p 'test_*.py' -v
```

背景と次の接続案は[時系列接続の監査](../../docs/research/2026-10-21-vision-temporal-integration.md)を参照してください。
