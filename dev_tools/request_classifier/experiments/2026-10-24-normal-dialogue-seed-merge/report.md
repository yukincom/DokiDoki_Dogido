# 通常対話578件・seed42/43/44の重み合成（2026-10-24）

**今回比較した13通りの合成は、すべて単体seed43を下回った。** 単体のtestは41/50。合成で最多だった構成でも30/50だった。本体へ採用するモデルは変更していない。

## 比較の進め方

1. 同じ基盤・16分類・教材で学習したseed42/43/44を用意。以前の合成実験の手順に沿い、受領済みの既存 `train.evaluate_checkpoint` と集計処理をそのまま使用。
2. 元の3モデルをMacのCPUで再評価。42＋43、42＋44、43＋44、3つ全部を等重みで混ぜる4構成をdev46件で評価。
3. 4構成ともdevで低下したため、最終分類層の2テンソルだけを構成元seedのまま残す9構成を追加。これもdevだけで比較。
4. 全16候補（単体3＋合成13）のdev macro F1、同点ならloss、事前の候補順で選択を固定。その後にtest50件と学習内追加47件を全候補で評価。test結果を見て比率・構成を変更していない。

## どの組合せが候補だったか

- 合成内でdev macro F1が最も高かったのは、**42＋44の全体平均**。ただし0.5142に留まり、単体seed43の0.8930を大きく下回った。devで固定した総合最良はseed43単体。
- **42＋44の平均にseed44の最終分類層を残す構成**は、合成内のtest正解数が最多の30/50だった。これは全結果を並べた後の記述であり、testを使った採用選択ではない。
- 元の2モデルが互いに補える発話はあったが、その補完関係を今回の重み平均で取り出すことはできなかった。調整前の単体devでは42/43は双方正解36、42のみ2、43のみ3、双方誤り5。42/44も36/2/3/5、43/44は37/2/2/5だった。
- この実験は均等な重み平均と最終分類層保持まで。出力の多数決・確率平均、任意の混合比率、重みの対応付け、追加学習は対象外。今回の13構成の失敗を、あらゆる合成方法の失敗とは扱わない。

## 初期化と原因の範囲

学習コードでは各seedを設定してから16分類モデルを作り、基盤に存在しない最終分類層を新規初期化している。同じ基盤からの学習でも、すべての層が共通の初期重みだったわけではない。

学習後の `classifier.weight` のcosine類似度は42/43が0.0351、42/44が0.0211、43/44が−0.0590。`head.dense.weight` はそれぞれ約0.9992だった。この測定は最終分類層の違いを示すが、合成で低下した原因を単独に特定するものではない。最終分類層を元に戻すだけでも性能は回復しなかった。

今回の結果から言えるのは、保存されたこれらの重みを今回の方法で混ぜると性能が大きく落ちたこと。学習済みの特徴表現と分類層の組合せが崩れた可能性はあるが、因果を確定する実験は行っていない。

## 実行条件・確認

- 全候補を同一Mac CPU・float32・SDPA・batch16・最大128 token・履歴なし・切り詰めなしで評価。Python 3.11.14、torch 2.14.1、transformers 5.19.0、accelerate 1.15.0等、主要依存はColabと同じ。CPUは4 thread、interop 1、決定的アルゴリズムを有効化。
- 元3モデルのdev/test計288予測ラベルはColabと全件一致。確率の最大絶対差は約1.02e-5。CPUへ移したことで単体の正解数が変わった結果ではない。
- 全13保存モデルの全テンソルを再読込みし、指定した平均・最終分類層保持との完全一致を確認。元モデル・tokenizer・設定・教材のhashも維持。
- 全2,288予測（16候補×dev46＋test50＋追加47）について、入力・正解・確率・argmax・正解数・分類別precision/recall/F1・混同行列を独立再計算。保存結果と一致。
- devの選択を再計算し、選択ファイルのhashとtest開始前の固定を確認。追加学習0回、本体モデル差替え0回。
- dev/testは既に教材設計で参照済み。今回の値は固定教材内の診断であり、未知の実機精度ではない。追加9構成は最初のdev結果を見た探索的な比較として記録した。
