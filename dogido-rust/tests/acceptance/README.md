# パート1 — 位置の主語・視点・距離・取得状態

本体の関数を呼び、観測受付 → 共通観測 → 通常返答／環境反応の最終生成要求を検査する。LLM・TTS・Minecraftは起動しない。モデル出力をモックして成功させるテストではない。

## 固定した合格条件

- 既知の配置では、ドギドはプレイヤーの向きを基準に右前・上。プレイヤーはドギドの向きを基準に左・下。
- 片方だけ半回転したら、その側を基準とした方向だけが変わる。上下と距離は変わらない。
- 会話用距離は小数点以下切り捨て。9.38→9、9.99→9、0.99→0、10.01→10ブロック。事前に小数第一位へ丸めてから切り捨てない。
- 位置が分かるが姿が見えない場合と、観測そのものが未取得の場合を区別する。未取得の後で以前の位置・視認を埋め戻さない。
- 通常会話と環境反応へ同じ主語付きの事実が届く。座標やobserver/target配列の選択をモデルに戻さない。
- before/nowも主語付きの事実で表示する。内部比較用の方向データは保つ。

期待方向・距離はテスト側で固定し、本体の計算関数で期待値を作らない。句読点や文の分割は固定しないが、日本語で主語・基準・位置を明示した節を検査する。配置fixtureはここだけのテスト用データ。

## 12件の内訳

| 件数 | 対象 |
| --- | --- |
| 3 | 共通観測／通常返答／環境反応の受け渡し |
| 2 | プレイヤーだけ／ドギドだけの向き変更 |
| 4 | 整数切り捨てと整数境界 |
| 1 | 未取得時の過去位置・視認の除去 |
| 1 | 視認が変わっても位置は維持 |
| 1 | 変化の表示と内部比較データの分離 |

## 実行

リポジトリルートから:

```sh
dogido-rust/tests/acceptance/run_position.sh
```

通常PATHにRustがない場合は既存の`DOGIDO_RUST_TOOLCHAIN_DIR`を設定する。サンドボックス実行では`CARGO_TARGET_DIR`も書込み可能な場所に指定する。テスト本体・fixture・実行補助・説明はすべて`dogido-rust/tests/acceptance/`に置く。本番用scriptsには追加しない。

`dogido-rust/src/dialogue/mod.rs`に必要な配線は次の3行のみ（テスト本文は置かない）。Cargo featureは追加しない。

```rust
#[cfg(test)]
#[path = "../../tests/acceptance/position.rs"]
mod acceptance_position;
```

## 判定の限界

これはモデルへ渡る入力と契約の受入試験。実モデルが「ドギドどこ？」へ正しく返答するか、実ゲーム中の追従や視線、音声品質は未確認。これだけ通っても会話品質改善や実機完了とは扱わない。

他パートのテスト・下書きはこの一式に含めない。
