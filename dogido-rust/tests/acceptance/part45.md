# パート4・5の受入条件

2026-10-29。各Rustテストの直前に、見込み・観測する合格条件・確認範囲を200字以内で記す。実装の出力をそのまま期待値にはせず、現行仕様の区別と、先に保存した画像期待値を使う。

## パート4：聴覚

見込み：通常会話と環境反応へ同じ聴覚事実を一度だけ渡し、保持後も時刻・音の確度・発音者の由来を残せば、重複や取り違えを減らせる。

| 入力・前提 | 合格条件 | 確認範囲 |
| --- | --- | --- |
| 実音IDのある足音 | 通常・環境の要求にIDが各1回。旧音要約の重複なし | 模擬身体観測→実投影→生成要求 |
| 身体age150ms・音age1200ms | 元eventから計算した聴取時刻を10ms以内で復元 | 時計丸めのみ許容。生成準備時刻へ付替えない |
| owner UUID／別UUID | 前者はプレイヤー、後者は本人以外としてconfirmed | UUIDの取得自体は模擬 |
| UUIDなし、同時点の位置・動作・完了調査が一致 | プレイヤー/inferred。足音と破壊音は区別 | Rustの根拠照合。Fabricの採取は対象外 |
| 調査不足・別候補・時点や動作の不一致 | 音を残してemitter=null/unknown | 音を捨てて成功にしない |
| 確定・推定・打切り未確定の音を保持 | 元時刻・low・由来・調査状態が両要求へ継承 | 模擬の二回観測と本体の保持 |
| 身体未取得へ変わる | unavailable。保持音や本人側の音を混ぜない | 共通観測と両要求 |
| ウシを見たが聞いていない | 鳴き声表現は辞書だけ。聴取事実を作らない | 辞書と観測の配置 |

調査打切りの音は、**自発的には反応せず、聞かれたら推測だと分かる返答なら合格**。この選択はモデルの評価であり、入力のunknown確認だけでは合格としない。[実モデル用ケース](part45_model_cases.json)に分け、未実行のまま保持する。別UUIDを「本人以外と同定できた」と扱うのは現行契約への更新であり、本人由来へ格上げするものではない。

## パート5：画像

見込み：画像取得・比較可否・比較結果を分け、現在画像1枚へ説明を一度だけ添えれば、未比較を変化と誤解する材料を減らせる。

| 入力・前提 | 合格条件 | 確認範囲 |
| --- | --- | --- |
| not_compared／unchanged／changed | 全画像を保持。changedだけ通知1回 | Java比較→符号化→実JSON→Rust受信・抽出 |
| 12秒間隔の未比較5枚 | 最新画像は更新、変化通知0回 | 時刻を進めた模擬受信 |
| 4枚前との比較 | 実際の参照ID・時刻・hashとマスを保持 | 直前画像を参照へ置換しない |
| 不正な状態・参照・マス | ACKは返しても画像を保持・通知しない | 実Rust受信 |
| 明示撮影後に移動・観測欠落 | 取得済みの画像は同じ返答で使える | 模擬姿勢、実保持経路 |
| L字3マス・明暗混在 | 行・列の対応と両明暗を保ち、率や強度は説明に出さない | 説明生成。意味理解は対象外 |
| 実画像pair_06の三状態 | 両経路のHTTP要求へ現在PNG1枚・比較説明1回 | 本体の通常／環境生成。未比較・無変化時は安堵反応の契機を与え、HTTP応答を固定 |

Javaの計測は引継ぎ資料の固定13組を使い、64×48の縮小RGBと全624マスを照合する。期待値は試験対象のJavaから再生成しない。保存された元画像hashも検査対象にする。

## 実行と記録

```sh
python3 dogido-rust/tests/acceptance/run.py --part 4 --part 5
```

JDK21以上と既存Gson・JUnitを使う。Rustは既存の`cargo.sh`。必要なら`JAVA_HOME`、`DOGIDO_ACCEPTANCE_GSON`、`DOGIDO_ACCEPTANCE_JUNIT_CP`、`DOGIDO_RUST_TOOLCHAIN_DIR`、`CARGO_TARGET_DIR`を指定する。

`results/latest/`へ一覧・実行ログ・試験対象hashを保存。`payloads/`には聴覚2要求と、実画像の三状態×通常／環境の6要求を保存する。後者は本体経路から採取したHTTP JSONで、試験画像のbase64を含む。実モデルへは送信しない。

自動試験の成功は入力・受信・保持・通知の成功を示す。実モデルの意味理解、Minecraft内の音源採取・撮影・移動、マイク・TTSの成功は含めない。

モデル評価ケースの`input`は、選択した結果ディレクトリからの相対パス。通常実行では評価ケースを送信しない。聴覚の環境要求は既存の安堵反応を試験契機として準備し、契機選択そのものはこの試験で測らない。
