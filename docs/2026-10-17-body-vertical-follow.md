# 縦追従と寄り道の調整

後継: 現在の探索範囲・判断間隔・到着後待機は[0.7.7の注意範囲と集中](2026-10-17-body-attention.md)。以下は0.7.6時点の記録です。

日付: 2026-10-17  
状態: 0.7.6と対応adapterを導入済み。身体136件・adapter187件・Rust764件成功（Rustの既定除外1件）、Clippyと配布・releaseビルドを確認済み。ドギド本体の再起動とゲーム内確認は未実施。

## 変更理由

ユーザーから、FOLLOW自体は動くものの、竪穴・洞窟の上下移動では崖際で止まるとの報告があった。追従開始距離は16から8ブロック、高さは上下4ブロック程度、興味を持って見に行く動きも増やす指定を受けた。

従来はownerの目線付近から横1.75ブロックの候補だけを使っていたため、1ブロック幅の竪穴では全候補が壁内になる。狭い水平通路でも、視点が斜めだと候補が通路軸から外れる。縦方向の移動計算とは別に、着地点の候補が欠けていた。

## 動作

- 既定の追従開始距離を8ブロックへ変更。従来と同じowner足元からの3次元距離で判定する。
- 身体の基準位置がownerの`feet.y + bodyHeight`から上下4ブロックを超えた場合も追従を開始する。ちょうど4ブロックと通常の浮遊・一段の跳躍では、この条件から再開しない。
- 一度追従したら、現在ownerの水平2ブロック以内にある安全な目標の0.2ブロック以内まで接近する。
- 開けた場所では従来の横／後ろを優先。全て塞がる場合だけ、ワールドのX/Z軸に沿った候補、近い横／後ろ、上下の順に調べる。
- 竪穴の上下候補はowner足元から+2.75／-1.25ブロック。現在身体に近い側から試し、ownerを縦に横切る目標を避ける。採掘正面・生体・壁・危険・未ロード範囲の検査は継続する。
- CALLと通常ワープも既存の候補共有処理に接続する。24ブロック超のワープ条件・再実行間隔・退避中の既存候補は維持する。
- 狭い側方候補では、到着許容距離がownerとの隙間より大きくなり得る。CALL／FOLLOWとも到着確定時に、目標に加えて現在の身体位置の空間と危険も再検査する。
- 紙風船のような振幅0.18ブロック・周期120tickの浮遊と、CALL到着直後の解除は0.7.5から継続する。

## 興味を持って見に行く動き

- 既存の`body_interest`による判断間隔を30秒から15秒へ短縮する。移動完了後の8〜12秒の観察、見回し中の判断保留、同じ対象への120秒の再訪待ちは継続する。
- adapterの候補収集、実行直前の対象・身体距離、接近後の停止位置を、固定16ブロックから現在の`follow_distance`へ揃える。
- Rustもモデルへ渡す前に現在範囲内の候補だけに絞る。候補なしでは選択間隔を消費しない。選択後の最新対象・位置・世代・距離の再照合も継続する。
- モデル・プロンプト・inspect／stayの出力契約は変更しない。15秒ごとの移動を強制するものではなく、会話中・危険時・追従中などの既存抑制を通ったときに判断する。
- 公開Body API v7、HTTP姿勢v3・自律制御v1、既存の移動命令を継続する。adapterの識別子は`2026-10-17-body-follow-curiosity`。

観察の停止先は、共有する高さ計算で追従基準高から上下3.2block以内へ収める。到着許容0.4と到着後の浮遊全幅0.36を足しても上下4を超えず、見物途中で距離追従へ切り替わることを防ぐ。身体側も受付時に再照合する。BodyProtocolにはこの計算用の定数・メソッドだけを追加し、record・enum・通信形式は変更しない。

## 検証

- 身体Mod: 136件成功、失敗・除外0。配布ビルド成功。
- adapter: 187件成功、失敗・除外0。配布ビルド成功。
- 新たな移動検査は上下4の境界、1ブロック幅の竪穴、視点が斜めの洞窟通路、上方／下方からのFOLLOW・CALL、通常／退避ワープの候補、安全な実位置での到着を扱う。実移動計算には浮遊・作業正面・生体衝突も含める。
- 寄り道検査は15秒の間隔、範囲外だけなら判断しないこと、フィルタ後の対象ID対応、8ブロックの境界、変更された追従設定、範囲内の停止位置を扱う。
- Rust全体検査の初回は模擬HTTPの待受権限で失敗し、権限を揃えて再実行した。Python補助の取消検査はpyenvの起動ラッパーを介すると子プロセスの準備前に期限が来た。同じPython本体を`DOGIDO_TEST_PYTHON`で直接指定した単体検査は成功。テストや本番の取消期限は変更していない。
- Rust全体は同じPython本体の直接指定で764件成功、失敗0、既定除外1件。模擬通信8件を含む。Clippy（警告をエラー扱い）、releaseビルド、一般起動のソース鮮度検査も成功。
- 到着時の浮遊が谷／山の両方について、到着後2周期の待機でも高さ追従へ切り替わらないことを検査。
- 自動検査の成功と、実ゲーム内での上下移動・見た目・寄り道の頻度は分ける。
