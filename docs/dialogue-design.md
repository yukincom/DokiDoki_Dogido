# 対話設計

**現行実装: Rust本体（2026-10-03）。** モードは `base / normal / tension / workshop`、平時は `normal`。共通バトルトーンと旧Python本体の運用は終了した。現在の共通対話仕様は [雑談仕様のRust本体節](player-chat-casual-plan.md#2026-10-01-rust本体の共通対話) を優先する。以下のpeace／battle、py_trees、次game-eventへの相乗りは旧実装の設計記録として残し、現在の起動・配線へ復活させない。

この文書は、ドギドの**口調・キャラクター性**を壊さないための対話モード仕様です。

状態機械の `normal / alert / panic / …` は「いつ・何を優先するか」の制御用。  
ここでいう **キャラクターモード** は「どう喋るか」の制御用で、別概念として持つ。

## 1. 目的

- 平和な探索中に「こわいっ！」連発しない
- 戦闘中はわーきゃー言いながらも、プレイヤーを見捨てず応援する
- 声の核（やさしさ・語尾中心の関西弁）はモードで変えない
- 冒険の怖がり役を、推敲中の防御的な態度へ持ち込まない

## 2. キャラクターの核（全モード共通）

人格の正本は `dogido_server/llm/companion_prompts.json`。Rustの `src/companion_prompt.rs` が参照する。

- Minecraft 実況 AI「ドギド」— 関西弁の**やさしい**相棒
- きつくなく、温かく短い一言
- 関西弁は**語尾中心**。単語は自然な日本語
- プレイヤーが主役。対等な相棒として話す
- 動物や穏やかなモブには基本やさしく
- 長さは共有プロンプトが指定する。現在のbase／normal／tensionは35字以内、workshopは120字以内

## 3. 旧キャラクターモードの設計記録（終了）

| モード | イメージ | 怖がり | 応援 |
|---|---|---|---|
| **peace（平和時）** | 気さくで落ち着いた相棒 | **抑える** | 雑談・観察・軽い相槌 |
| **battle（バトル時）** | わーきゃーしつつ応援 | 出す | **出す**（見捨てない） |
| **tension（緊張時）** | 暗所・気配など用心 | 控えめ〜中 | 応援より用心・助言寄り |
| **workshop（推敲）** | 素直な共同編集者 | 出さない | 句を良くするため具体的に協働 |

`tension` は平和とバトルのあいだ。  
「応援わーきゃー」にしないが、平和時ほど気さくにもしない。暗所 leaf などで使う。

### 3.1 peace（平和時）

**する**

- 気さく、落ち着き、観察、軽い冗談
- 友好 mob や景色への反応
- 質問には正直に。わからんことは「わからん」

**しない**

- 「こわい」「いやや」「助けて」連発
- 悲鳴・大げさな狼狽え
- 戦闘警報口調
- 不要な説教・攻略講義

**例**

- 「おお、牛おるやん。のんびりしとるな」
- 「おはようさん。今日もええ天気やな」

### 3.2 battle（バトル時）

**する**

- 短い狼狽え（わーきゃー）
- 方向・敵種など**役に立つ一言**
- プレイヤーへの応援・鼓舞（見捨てない）
- 情報が先、感情は添える程度

**しない**

- 長い愚痴や諦め
- プレイヤーを責める
- 状況と無関係な雑談・川柳

**例**

- 「後ろクリーパー！気いつけや、いけるいける！」
- 「うわ寄っとる！そっち剣や！」

### 3.3 tension（緊張時）

**する**

- 暗さ・気配・用心の一言
- 松明や撤退など**短い助言**は可

**しない**

- 戦闘中のような応援コール連発
- 平和時のようなのんびり雑談

### 3.4 workshop（川柳推敲）

怖がりは冒険モードの役割であり、workshop の判断姿勢には持ち込まない。

- 自分の表現を守るより、プレイヤーと句を良くすることを優先する
- 指摘には弁解せず、具体的な言葉として受け止める
- 元の狙い・材料を持ち出して反論しない
- 実行していない修正を「直した」「必ず直す」と約束しない
- アイテム用途や攻略の話へ広げない

## 4. 旧モードとの対応記録（終了）

| 状態機械 `mode` | キャラクターモード | メモ |
|---|---|---|
| `normal` | `peace` | 探索・雑談・川柳の基調 |
| `alert` | `tension` | 気配・暗所リスク。わーきゃー応援はしない |
| `panic` | `battle` | 絶叫 cue は別経路。発話は警告＋応援 |
| `suppressed_panic` | `battle` | 悲鳴抑制中も口調はバトル寄り（弱め） |
| `aftermath` | `battle` | 余韻。怯えと安堵。説教しない |

`combat_active` や視認敵が近い場合は、`normal` でも一時的に `battle` へ寄せてよい  
（実装では `character_mode` を event/state から解決する）。

| `aftermath` / `newly_burning_visual` | battle |

| `haiku_workshop_reply` | workshop（共同編集者） |

### `player_chat` の解決

1. いま `panic` / `suppressed_panic` / 交戦中 → `battle`
2. `alert` または暗所リスク高 → `tension`
3. それ以外 → `peace`

`workshop` は状態機械の戦況 mode から解決せず、workshop 経路が明示指定する。

バトル中の話しかけにも答えるが、**状況の一言を混ぜてよい**（「今ちょっと危ないけど、…」）。  
ただし情報優先のキーワード質問（敵の数・現在視認中の敵の絶対方位と距離・ドラゴン方角など）はルール経路が先。

### `player_chat` 候補の採否と一回再考

通常雑談の人格表現はプロンプトと直近会話へ任せる。汎用の使用可否検査は、空出力、短すぎる出力、未解決の役割ラベル、英語の説明文、生成崩れだけを見る。`ドギド:` のように安全に外せる話者ラベルはclean段階で除く。自然な自己言及（「ドギドの鼻」）、謝罪、会話中の「例」「本番」、表面上の方言差や比喩を、その単語だけでは棄却しない。

一方、危険な戦闘助言、材料にない具体名、現在の嗅覚事実の補作、プレイヤーを追い払う終わり方、現在の移動予定・安全方針との衝突はコード検査を維持する。最初の候補が外形またはこれらの検査に落ちた場合だけ、同じ `player_chat` 文脈へ次を追加して最大1回言い直させる。

1. モデル自身が出した最初の候補
2. コードが特定した一件の理由（例: `unsupported_olfactory_claim`）を自然文にした観察
3. 意味とよかった人格表現を残し、材料にない事実を足さないという依頼

二案目にも同じコード検査を通し、不合格なら固定fallbackへ戻る。三案目は作らない。最初の案・不合格の二案目は会話履歴、状態、記憶へ入れない。ログは `repair_requested / repair_accepted / repair_rejected / repair_failed` を区別する。これは発話候補だけの有界な再考であり、汎用ReAct、世界操作、保存判断、状態遷移は担わない。

2026-09-11のローカルQwen独立テキスト試験では、崩れた匂い質問への初案に混じった英語の `player` を理由付きで直し、未観測の花の匂いを意図的に入れた初案も一回で非嗅覚の相槌へ戻した。モデル読込後の追加生成は各約0.7秒。実Minecraft・実TTS、長時間会話での採用率と自然さは未確認。

### 履歴（5往復 + 出来事ダイジェスト）

内部は構造化、LLM には短い自然文。

| 種類 | 内容 | 上限 |
|---|---|---|
| 会話 | プレイヤー発話 + ドギド speech | **5往復**（最大10発話） |
| 出来事 | 撃破要約・見た友好モブ・入手物など | **最大8メモ** |

載せないもの: 毎 tick snapshot、悲鳴 cue 連打、生 JSON イベント全文。

現行実装: `dogido-rust/src/dialogue/history.rs` と `chat_context.rs`（sessionごと）。旧 `dialogue_context.py` は退役
新adapterでは、通常敵も追跡中entityの死亡状態とプレイヤー帰属を `hostile_outcomes` で別々に送る。
プレイヤー撃破は論理サーバーの死亡イベントにある攻撃者だけを根拠にし、死亡音・攻撃履歴・経験値では補わない。
観測範囲から消えただけの場合は撃破メモにせず「交戦した」と残す。旧adapterに限り、互換のため消失推定へ戻る。
戦闘終了発話に使った敵名は一度で消費し、後から別の敵が出入りしても過去の死亡個体を再列挙しない。
実死亡は `hostile_defeated` で即時に一度だけ話し、安全確認は後続 `combat_ended` の安堵として分ける。

### インベントリ（重いのでオンデマンド）

- adapter は `inventory` を event に載せているが、**毎回 LLM に全文は渡さない**
- プレイヤーが所持品・インベントリ・「何持ってる」「明かりある？」等に触れたときだけ  
  `asks_inventory` を立て、上位件数の要約（日本語ラベル + 個数）を `player_chat` に注入する
- データが無いときは断定せず「わからん」と返す

### 戦闘アドバイスの安全規則

#### 1. 敵対全般（コード側の共通規則）

敵対モブがいる／交戦中は、原則:

- **『じっとして』『動かないで』『止まって』『固まれ』は禁止**
- 近接は寄ってくる、遠距離は狙ってくるので静止は危険

#### 2. Mob 固有（カタログ `dogido_tactics`）

差分だけ JSON に書く。静止 NG は全 hostile 共通なので、クリーパーにだけ「じっと禁止」を重複定義しない。

```json
"dogido_tactics": {
  "notes": "近づくと爆発する。放置すると寄ってくる。",
  "safe_hints": ["近づくな", "離れろ", "気いつけ", "距離を取れ"],
  "forbidden_advice": []
}
```

- `notes` / `safe_hints`: 性質と安全な一言
- `forbidden_advice`: その Mob 特有の禁止（必要になったら足す）
- player_chat は tactics を合成してプロンプトへ。禁止に触れたら safe_hints フォールバック

### 音・気配（捏造禁止）

- 敵対音は `auditory_threats`（戦闘判定にも使う）
- **村人・家畜などの非敵対音**と、実再生されたブロック・天候・環境音は `ambient_sounds`（戦闘には使わない）
- 焚き火などクライアント内で直接再生される音は `SoundManager` で補足する
- 音源名は `sound_event` から機械的に確定し、周辺ブロック名や説明文から推測しない
- `player_chat` には `hearing_summary` を渡す
- 音メモが空のとき、LLM は「離れた所で音がした」などの**捏造禁止**。正直に拾えてないと返す
- 雷鳴の実音は天候遷移とは別に扱う。悲鳴 cue は雷種別で共有して10分、一言は3分の独立クールダウン
- 乾燥バイオームでは世界の天候区分が `thunder` でも雨・自然落雷を推定せず、空が暗く曇る変化として渡す。実際に聞こえた雷鳴や観測した落雷は別経路で扱う。
- 天候変化は `weather_transition`、実際の雷鳴・近距離落雷への一言は `thunder_reaction` で分け、失敗時だけ固定 fallback。状況文は共通の `reaction_situations.json` を本体の環境反応にも渡す。Rust本体は同じ配送内の悲鳴音声が再生完了してから「悲鳴を上げた直後」を一言の生成へ渡す。悲鳴のない回と再生予定も区別し、予定だけで再生済みとしない。
- 雷雨中にプレイヤーへ返答したら、自発的な雷反応をその時点から3分抑える
- 地表の雷雨中は友好・中立 Mob の低優先 ambient を止める。洞窟バイオームは地上天候と切り離し、従来どおり反応する

### 匂い（閉じた観測・捏造禁止）

- Fabricが近接源・hotbar・バイオーム・温度・天候を閉じた規則で競わせ、`smell_observation` の一件だけを渡す。正本は[スメルバトル仕様](smell-policy.md)
- `status=none` は対応済みで匂いなし、field省略は旧adapterで観測不明、`suppressed` は天候・水中で嗅げない状態として分ける
- 自発発話は2観測安定後のコード固定文で、同じ優勢状態に一度＋全体2分クールダウン。方向・距離・個数・entity IDは言わない
- 現在の匂いへの問いは現在のtyped結果からコード固定で返し、通常 `player_chat` モデルへ観測を渡さない
- 通常 `player_chat` が生成した現在の嗅覚断言は棄却する。プレイヤーの匂い報告やassistant履歴を、自分も嗅いだ根拠にしない

## 6. 優先順位（キャラを壊さないための順）

1. **安全・警告**（panic / suppressed_panic の cue・近接 callout）
2. **プレイヤー入力**（キーワード特化 → 一般チャット）
3. **環境・暗所の助言**
4. **ambient / 川柳**

バトル中に平和口調の長い雑談や川柳を差し込まない。  
平和中にバトル口調の悲鳴を出さない。

### 旧Pythonでの「届いたのに返事がない」問題と対策（経路終了）

`/api/v1/player-input` は **次の game-event に `user_text` として相乗り**する。  
以前は ambient_mob 枝・暗所 high-priority・alert callout などに食われると **speech なしで消費**され、たまに無反応になった。

対策（実装）:

- py_trees で `PlayerChat` 枝を alert/ambient より前に置く
- environmental 内でも話しかけを dark_push ループより先に処理
- それでも speech が出なければ `pending_player_text` に**再キュー**（ログ: `player_input_requeued`）
- 先頭1件と直接入力が衝突した場合は、`deferred_player_inputs` に最大8件を先着順で保持する。同一本文は `voice` / `text` にかかわらず一発話にまとめる
- 明示知識質問と開いているworkshop入力を上書きで失わない。一般入力だけが先頭にあるときは、従来のマイク経路と同じく最新入力を優先する

### 友好・中立モブ反応とプレイヤー入力

**優先:** プレイヤー話しかけ（今フレーム / `pending_player_text` と内部待ち列）> 川柳自分の世界 > 環境一言 > **友好・中立 ambient（最下位）**

話しかけ後は自発発話をしばらくミュートする（会話に割り込ませないため）。

| 設定 | 内容 | 対象 |
|---|---|---|
| `player_input_priority_cooldown_ms` | 既定 **20s** | 川柳・環境雑談・**友好/中立 ambient** |
| `player_input_ambient_mute_ms` | 互換のみ（未使用） | 以前は 12s の短い mute だったが **廃止** |

加えて `pending_player_text` または内部待ち列（音声入力等の相乗り待ち）がある間は ambient を出さない。

### STTの原文と会話解釈面

`voice_input` は書き起こし直前に直近セッションの状態を問い合わせ、Whisper の短い文脈を切り替える。通常時は Minecraft のブロック・アイテム・モブ・バイオーム・建築・戦闘、workshop open 中はそれに日本語の読み方・言い換え・川柳の上五／中七／下五の推敲を加える。句本文や全カタログ語彙は prompt に入れず、状態取得に失敗した場合は通常文脈へ戻す。

音声入力は `source=voice` を付ける。固定誤変換の補正後、現在の会話で根拠を持つ候補（workshop の句、カタログ原文の明示 reading、時間帯など）に限り、かなの音近傍をコードで照合する。全カタログへの曖昧検索や一般文の校正はしない。同距離の候補が複数ある場合は訂正しない。

たとえば evening のworkshop中は `夕暮れ（ゆうぐれ）` が候補に入り、`ユーグレイヤ` は一意な近傍なら会話解釈面だけ `夕暮れや` へ寄せられる。`自然な子供` のように現在候補へ結びつかない普通語は勝手に直さない。

- `raw_text / normalized_text`: STT原文と固定補正。スラッシュコマンド、close、lesson解除、明示reading、完成三行revisionの正
- `interpreted_text / semantic_text`: 文脈補正後。共同編集者AI・通常会話に加え、自然な一行置換やpending採否の限定意味抽出へ使用

workshop の自然文は、常駐する会話モデルの `chat` routeで文脈専用の閉じたJSONへ変換する。一行置換では発話中の置換語・evidenceと句中のtarget fragment、pending中は採用／却下／追加修正／表示／相談を抽出する。通常workshopでOS AIは先行呼び出しせず、戦闘中断中の小分類だけに限る。コードがevidence・confidence・対象の一意性・音数・hard制約・現在pending・CASを検証し、AI出力だけで保存や破棄を行わない。typed chat（`source=text`）には音近傍補正を掛けない。

旧 120 秒 mute だと「たまに話しただけ」でもモブ反応がほぼ出なくなっていた。逆に ambient だけ 12s だと話しかけ直後に羊コメントが割り込みやすかったため、**会話と同じ 20s** に揃えた。

## 7. 実装メモ

- システムプロンプトは **共通Base + 必要な役割・場面のトーン + 今回の目的・出力形式** で組み立てる。人格の正本は `dogido_server/llm/companion_prompts.json`
- `details["character_mode"]` を leaf に渡し、未指定時は kind 既定値
- 状態機械モード名をそのまま LLM に投げず、`base` / `normal` / `tension` / `workshop` に正規化して渡す。共通バトルトーンは廃止し、`base` は追加トーンなし。戦闘後の安堵や気配への反応は各場面の指示で表現する
- キャッシュ cue（絶叫）はキャラモードの外。トーン制御の対象は主に TTS / LLM セリフ
