## P1: 静止した身体から、自分とプレイヤーの位置関係を把握する

ユーザー確認（2026-10-11）: 「プレイヤーが離れたことにドギドが気づく」「プレイヤーの位置と自分の位置の差が把握できるか」。最初はドギドの水平位置と向きを固定し、プレイヤーだけが移動する。追従・自発移動・一般の視覚／嗅覚／聴覚の全面移行は後続に分ける。

### 最初に通すデータ

1. 身体Modが同じserver tickで、自分の足元位置・目の位置・向きと、所有者であるプレイヤーの足元位置を測る。座標の単位はブロック、向きはMinecraftのyaw度数とし、次元・body ID・owner UUID・身体epoch・観測tickを添える。
2. Java APIは位置観測を加えたv3へ更新し、身体Modを0.4.0とする。一般センサーの未実装状態は維持する。今回の根拠は `server_pose` と明示し、視認できたという意味にしない。最初の実機場面は両者が見える開けた同一次元・読み込み済みの場所を使う。
3. adapterは任意のBodyBridgeからsnapshotを読み、既存のHTTPイベントの `body_observation` として送る。専用HTTP endpointや別サーバーを新設しない。Modなし・版違い・身体なし・未ロード・異次元・古いsnapshotは理由付きの未取得として扱う。
4. session登録にoptionalのplayer UUIDを追加し、Rustは身体のowner UUIDと照合する。UUID未提供の従来接続は会話を継続し、身体観測だけ利用不可とする。
5. Rustの身体専用stateが原本イベントから一度だけ現在／前回の観測を更新する。重複・逆順・別の身体epochを混ぜず、部分イベントと過去の全体観測の合成で鮮度を延長しない。
6. 現在／前回の自分と相手の位置・向きを、既存の通常会話の `world_context` に身体専用の観測項目として渡す。身体ID等の配送識別子と、会話へ渡す材料は分ける。新しいモデル用指示文・別モデル呼出し・移動命令は追加しない。

これは観測地点を移す最初の段階。周囲のモブ・ブロック・音・匂い等の既存player観測を、身体の感覚として読み替えない。身体の位置材料は自分＝ドギドと明記し、プレイヤーのHP・所持品・戦闘観測は従来の担当に保つ。

### 判定と受け入れ条件

| 試験 | 確かめること |
|---|---|
| ドギドの前から右へプレイヤーが移動 | ドギドの向きを基準とした位置関係が変わる |
| プレイヤーが遠ざかる／近づく | 自分との距離が増える／減る |
| プレイヤーがその場で振り向く | 二者の位置関係が変化しない |
| 両者が別々の座標にいるfixture | 自分とプレイヤーを取り違えない |
| snapshotの重複・逆順・古いtick | 前回／現在を壊さず、鮮度も延長しない |
| 再接続・身体epoch変更・次元変更・未取得 | 以前の位置を現在として使わず、比較対象をリセットする |
| 身体Modなし／旧版 | 通常の会話・表示・戦闘が利用できる |

相対ベクトル・距離・左右前後の正解は検査用コードで計算し、モデルの返答との比較に使う。最初のモデル入力には現在／前回の座標と向きを渡し、「右へ行った」「離れた」という正解ラベルを先に与えない。実モデルでの理解の合否は、通信や自動テストの成功から推定しない。

実装は小さい担当へ分割し、各処理ブロックを日本語コメントで説明する。契約・受信境界・履歴・モデル入力の組み立てを自動検査し、身体／adapterのビルドとRust全体検査を終えてから変更をコミットする。既存のサーバーappや常駐サービス、MinecraftのMod配置はこのコード作業で切り替えず、開発版の実機確認は具体的な起動先と試験内容を揃えて行う。
