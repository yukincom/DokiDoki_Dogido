# あなたが行う独立音声テスト

2026-09-09。**話す内容は声で入力する。文字入力の再試験ではない。**

同日10:14と10:31の実起動で判明したCore Audioの形式・I/O周期の仮定を修正し、10:59から約58分の実キャプチャが停止せず完走した。その後のフエラムネとタイマー音でも自己音の再帰や誤文字化は発生しなかった。一方、宛先のない家族会話を2件拾ったため、この時点では無活動5分後に静かな状態へ入り、明示呼びかけ（例:「ドギド、〜」「あれドギドいる？」）で対話へ戻る初期境界を置いた。単なる `handoff` は会話終了の証拠にしない。意味による判断は、下記の予測付き限定契約として後から追加した。

同日13:11の実試験では、対話本体が冒険復帰を `mode_after=normal` と判定した直後、音声ホストがすべての `handoff` を一律に `QUIET` へ落とす不整合を確認した。続く2発話はSTTで認識されたが対話へ渡らなかった。`handoff_topic=minecraft` だけを `ACTIVE` へ戻すよう分離し、一般の終了・無活動による静音は維持した。関連295件＋35 subtestsは成功し、修正後の実マイク再確認は未実施。

同日13:31の再試験では、最初の意味を持たない認識が `casual` の `handoff` になっただけで、音声ホストが開始12秒後に `QUIET` へ落ちた。その後の「今エンダーマン」と「あれドギドいる？」を含む4発話が抑止された。これにより `handoff` 自体を静音契機にする設計を撤回し、自動静音は無活動5分だけに限定した。「あれドギドいる？」は部分一致一般ではなく、観測済みの狭い呼びかけ形として復帰対象へ加えた。関連296件＋35 subtestsは成功し、再修正後の実マイク確認は未実施。

同日・次段階では、起動後または明示リセット後の最初の認識を必ず受理し、各受理ターンのあとに会話モデルが次の意味上の発話型を5件だけ予測する試験契約へ進めた。次の入力は、明示名指し・話題転換語・明確な質問・Minecraft話題ならコードで必ず通す。それ以外も、予測に一致しない大きな話題断絶をモデルが発話内根拠つき・信頼度0.85以上で `possibly_not_addressed` とした場合だけ発話を保留する。モデル失敗・不正出力・低信頼・迷いはすべて受理側へ倒す。保留原文は通常対話履歴へ入れず、上限5件の診断ログに印を付けて残す。「待たせたね」「うるさくてごめんね」は `side_conversation_resolved` と記録して「ええんやで。」と返すが、誰宛だったかを事実認定したとは扱わない。「ドギドに言った」等の訂正なら直近の保留1件だけを一度再処理する。StackChan試作の未検証scene分類器は移植せず、この限定契約を新設した。

さらに同日、独立経路に欠けていた通常会話を本体既存の `player_chat` leafへ接続した。国語・Webの解釈器は経路選択を担当し、`casual` と一般的な発話は通常会話へ渡す。参加予測は返答文を作らない。音声hostは `turn_id` と `utterance_id` を結んだ一つの短期ターン台帳を持ち、`selected → queued → started → completed / failed / cancelled` を `turn_lifecycle` に記録する。子どもの受理済み発話は残す一方、ドギドの返答は実再生プロセスが `completed` になったものだけを次の `player_chat` 履歴へ載せる。履歴は5往復・5分で、選択しただけの返答、TTS失敗、明示取消後のターンは「聞こえた返答」にしない。

会話生成、参加判定のモデル呼出し、Google処理は独立hostの有界な直列workerへ移した。マイク受信とログはその間も止めず、完了時に `turn_id + epoch` を再確認する。生成・再生中に届いた次の音声は直近1件だけを保留し、前の再生完了と参加予測確定後に処理する。現在の自動規則は再生中の声だけでTTSを止めず、確実な割込みは `/interrupt` を使う。関連380件＋87 subtestsは成功。**この通常会話・完了履歴・worker経路は自動検査のみで、実モデル・実家庭音声では未確認**。

同日16:34のユーザー実試験では、通常会話からWeb同意・15秒後の単発取得・取得内容を使う後続対話まで通った。検索完了直後の「検索ページを開いたで」という追加TTSだけが閲覧を妨げたため削除し、起動・取得結果はログだけに残すよう変更した。この無音化後の実音声再確認はまだである。

実マイク → Core Audio同期参照＋WebRTC AEC3 → 本体と同じRMS・Silero VAD・Whisper → 独立国語対話 → 設定済みTTS → 実Chrome、を使う。
Minecraft本体、workshop、保存記憶、世界操作には接続しない。

## 起動

以前の文字入力テストが動いていたら、そのTerminalで `Ctrl+C` で終了する。
VOICEVOXは普段のものを起動しておく。声・速度・モデル・VAD・音量しきい値は設定を引き継ぐ。AECだけこのランチャーで明示有効化し、`.env` や本体の既定offは変えない。

```bash
zsh scripts/start_language_voice_test.command
```

最初の案内を読んでEnter。モデルの読込後、**「マイク入力中。声で話しかけてください」**を待つ。
権限画面が出たら、テストに使うマイク・システム音声キャプチャを許可する。
声をスピーカーから出すテストなので、今回はスピーカーを使う。大音量にする必要はない。
認識文・応答・診断はローカルの `logs/language-dialogue/manual-voice-日時-PID/events.jsonl` に記録する。

起動しないときは `--check` で依存・ローカルVOICEVOXの応答だけ確認できる。この確認では録音・再生・モデルロード・Chrome起動はしない。

## 1. 自分の声・ドギドの漏れ音・雑音を分ける

ここだけTerminalに制御コマンドを入力する。会話の文章は入力しない。

1. `/listen`：聞き取り専用。マイク・AEC・STTは動かし、聞いた文への自動返答を止める。
2. 約10秒黙る。静かな部屋で `聞き取り:` が出るかを見る。
3. `/say`：ドギドが検査文を実際に読み上げる。**あなたは黙る**。ドギドの文が `聞き取り:` に現れたら自己音の誤認識として記録する。
4. 再生が終わってから、次を一つずつ声で言う。言い終わったら約1.2秒の無音とSTT処理を待つ。

   > 石炭。
   > うん。
   > きょう。
   > 金床って、なんて読むの？

5. もう一度 `/say`。今度はドギドが話している途中に **「石炭はここにあるよ」** と声を重ねる。あなたの声が落ちるか、ドギドの声が混ざるかを見る。
6. 必要なら、あなたの操作で普段のゲーム音・雨音を流す。まず黙り、次に **「きょうは雨やな」** と話す。ゲームを動かしても、この試験にゲーム状態は渡らない。

`/listen` はマイクミュートではない。認識文のTTS一致による除外もしていない。
本体と共通の無音・既知ノイズ除外やウェイクワード設定は維持しており、棄却理由もログに出る。
`diagnostic` に `speech_segment` → `stt_started` → `stt_finished` が出たかを見ると、「区切りまで届かない」「STTが空」「認識された」を分けられる。

会話が5分以上止まると静かな状態になる。その間も認識ログは残すが、通常対話履歴へは渡さない。再開するときは **「ドギド、きょうって何音？」** や **「あれドギドいる？」** のように明示的に呼ぶ。一般話題・研究終了・冒険復帰の `handoff` だけでは静音にしない。`/listen` は明示的な聞き取り専用、`/talk` は明示的な通常対話への復帰である。起動直後と `/talk` 後、および `ACTIVE` 中の `/cancel` 後の最初の音声は、5分判定や予測分類より先に受理する。

## 2. 声で対話と短い履歴を試す

`/talk` を入力し、以下を**声で一発話ずつ**話す。返事を聞いてから次へ進む。

まず、通常の相棒会話を試す。

> 今日も絶好調だよ。

> うん、今日は洞窟に行きたい。

国語の聞き返しにならず、二つ目が一つ目の続きとして短い関西弁で返るかを見る。この独立試験にはMinecraftの観測がないため、見ていない敵・場所・所持品をドギドが事実として足さないことも確認する。

ログでは、各受理ターンの `turn_lifecycle` が `accepted`、`routed`、`selected`、`queued`、`started`、`completed` の順で進む。TTSが `failed`／`cancelled` なら、そのドギド返答は次の会話履歴へ入らない。次の発話を再生中に始めた場合は、現在は自動で音声を止めず `input_deferred` として直近1件だけ待つ。

続いて国語経路を試す。

> 「きょう」って何音？

> じゃあ、「きょ」だけなら？

> 最初に聞いた言葉は何やった？

> 「三」って、何年生で習う漢字？

音数の目安は「きょう」2音、「きょ」1音。誤認識したら正誤の前に `聞き取り:` の原文を見る。
続けて **「本があついって、どういうこと？」** と話し、確認されたら **「ページがいっぱいある本のこと」** と答える。状況確認と資料不足を取り違えないかを見る。

### 会話参加の予測と脇会話候補

これは品質がまだ確定していない観察項目であり、必ず抑止されることを期待する試験ではない。

1. `/talk` の直後、声遊びとして **「プリプリプリプリチプリキプリキ」** と話す。最初の入力が落ちず、「歌かいな。ご機嫌やな〜。」と返ることを見る。
2. 関連する続きを一つ話す。ドギドの再生が正常終了した受理ターンごとに `participation_forecast` が5件記録されることを見る。
3. 明確な疑問、Minecraftの出来事、または「ところで」で始めた話題変更が、予測外でも抑止されないことを見る。
4. 宛先を示さず大きく別の家庭話題を話す。モデルが高信頼で断絶と判定した場合だけ、`dialogue_suppressed` に `marker=possibly_not_addressed` が残り、読み上げない。
5. 4で保留された場合は **「うるさくてごめんね」** と言う。`participation_resolution=side_conversation_resolved` を残して「ええんやで。」と返ることを見る。別の試行で **「ドギドに言ったんだけど」** と訂正すると、直近の保留1件だけへ謝って返答する。

モデルの生成失敗、根拠不一致、低信頼、分類不能では入力を通す。したがって、抑止されなかったことだけを失敗とはしない。`possibly_not_addressed` の原文は診断ログには残るが、会話ターン台帳や `LanguageDialogue.history` には入らない。予測は参加判定専用で、通常返答は `player_chat` が生成する。

## 3. 実Chromeとの連携

まず拒否を試す。

> 金床は、どうして「かなとこ」って読むの？ ウェブで調べて。

Webを開いてよいか聞かれたら：

> 今はやめとく。

Chromeが開かないことを確認。次に同じ質問をもう一度声で言い、確認へ：

> ええで。

**「ほな一緒にいこか！」を実際に再生し、その再生プロセスが正常終了してから、専用ChromeにGoogle検索を開く。** `/speech-completed` はこの音声試験では使えない。
初回の概要読取り要求は15秒目の1回だけ。その1回のブラウザー内処理で0.4秒のDOM安定も確認する。概要が未完成でも自動再取得せず、取得不足をログへ分ける。ロボット確認が出たら `/cancel` でそのWeb試験を終了し、再送しない。
検索ページが開いた後は、読む集中を切らないよう「検索ページを開いたで」等の追加音声を再生しない。起動・取得結果は `web` と `dialogue.status` のログには残す。

検索ページを読んだら、模擬のゲーム外移動 `/away` → 模擬復帰 `/back` を入力する。
復帰時の歓迎は行うが、実Google概要は同じタブも含めて再読しない。`--virtual-web` の保存済みfixture再生だけは別の試験経路である。これは**実OS前面検知ではない**。

ページに本当に書いてあった内容だけを使って：

> ここに「（実際に読んだ短い文）」って書いてあったで。

> それって、どういう意味？

> この説明だけじゃ、わからんところもあるんかな？

> ほな、冒険に戻ろか。

冒険への返却で `[handoff]` になっても、本体未接続なので状態機械やゲーム操作は始まらない。ただし音声受付は通常状態へ戻り、続く雑談は独立側の `player_chat` へ渡す。Minecraft観測は渡さない。マイクと検査用 `/say` も引き続き使える。

## 4. 取消・中断・終了

- `/cancel`：対話・Web同意を打ち切り、現在と待ち中の音声を取り消す。古い案内完了でChromeを開かない。
- `/interrupt` → `/release`：中断→解除の模擬制御。生成workerと再生の旧epochを無効にし、解除だけでは古い返事やWeb起動を再実行しない。現在の明示的なbarge-in手段でもある。
- 「開かないで」も声で試せるが、STTが完了して届くまで撤回処理は始まらない。確実に今止める制御は `/cancel`。
- `/quit` または `Ctrl+C`：マイク・自己所有の音声/STT子プロセス・専用Chrome接続を終了する。普段のChromeやVOICEVOXサーバーは止めない。

## まだ確認できていないこと

準備確認：既存Whisper・Silero・AEC・MLX/Chrome依存とローカルVOICEVOX（話者21）の応答を確認。2026-09-09の実行では約58分のキャプチャ、対話、TTS、Google検索1回が完走した。フエラムネとタイマー音は文字化されなかったが、予測付きの脇会話保留、通常 `player_chat`、再生完了履歴、生成workerを入れた後は、実モデル・実家庭音声でまだ再確認していない。自動テストの件数は実機品質の代わりにはしない。

自動テストは接続・取消・再生通知のコードを対象にし、実際の部屋での認識品質・漏れ音低減・重なり発話を保証しない。
AECはMacの再生音を参照する。未参照の周囲雑音を一律に消すNSはこの経路に入っていない。合成音の事前試験では重ねた人声が弱まる課題が残っているので、上の5番は特に確認する。
再生プロセス正常終了は、スピーカーの実際の出音や聞こえ方まで測定した証拠ではない。
マイク音はSTT中の一時WAV以外保存せず、参照音も保存しない。TTS用の一時音声は終了時に片付ける。異常終了時には一時ファイルが残ることがある。

問題があれば「何番／自分が話した言葉／`聞き取り:`／ドギドの声／その時の音・Chromeの状態」を教えてください。ログの保存先も起動時と終了時に表示されます。
