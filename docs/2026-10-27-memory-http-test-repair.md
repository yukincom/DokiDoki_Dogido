# 記憶・知識引継ぎ・肯定的講評のHTTP試験を修復する計画

2026-10-27作成。状態: **完了**。開始点は書類側 `main` の `69363ca`。

## 目的と対象

次の3本は現行Rust本体の統合試験であり、廃止済みの試験ではない。削除済み補助関数のimportにより開始できない状態を直し、現在の受付・相談・保存・取消の契約を実HTTPで確認する。

| 試験 | 確認する責務 |
|---|---|
| `check_memory_runtime.py` | 講評・soft lesson・明示解除・想起・revision・保存失敗・取消と保存完了 |
| `check_knowledge_handoff.py` | 詩の資料回答への寄り道で現在句・未採用案を保持し、警告待ち・順次配送・取消を扱う |
| `check_workshop_praise.py` | プレイヤーから句への肯定的講評を一度保存し、戦闘で未発話になった返答と区別する |

「肯定的講評」はプレイヤーの感想の記録であり、モデルの迎合傾向を評価する試験ではない。モデル・分類器・音声は模擬し、実モデルの品質や実Minecraftでの確認とは分ける。

## 先に確認した事実と方針

- 記憶・知識引継ぎは `check_workshop_followup.followup` をimportするが、現行ヘルパーは `meaning_ack`。肯定的講評は記憶試験の `records` をimportするため同じ不備で止まる。
- **`followup` の関数・別名・互換ラッパーを復活させない。** 現行 `meaning_ack` を直接使う。
- 既存 `check_workshop_fixture.fixture`、`submit`、`ready`、`finish`、模擬モデル・再生器を再利用する。新しい分類器や本体の代替経路を作らない。
- 終了は川柳モードのBERT分類を使う。取得していないモデルのfeedbackは作らない。AI案生成後の再応答・confidenceの足切り・撤去済み国語機能を試験のために戻さない。
- 期待値の変更は現行仕様と実装を根拠にする。失敗したassertを削るだけで合格にせず、従来の試験目的が現在のどのケースで守られるかを記録する。
- 本体の不具合が見つかった場合は試験側で隠さず、契約との差を切り分ける。本体変更が必要なら変更範囲と検証を本書へ追記する。

## 実施単位

### 1. importと記憶試験

- 現行ACKヘルパーと分類fixtureへ合わせ、終了・肯定的講評・案生成の回数と保存期待値を照合する。
- 意味説明からsoft lessonへ進む経路、ACKで記録を増やさない境界、褒めても既存lessonを消さない境界を残す。
- open中の想起抑止、採用前後のrevision、再接続後の記憶、明示解除、保存無効・I/O失敗、取消後に開始済み保存だけ完了する条件を確認する。
- 単独実行を通し、対応する変更・結果を本書へ記録してコミットする。

### 2. 知識引継ぎ試験

- `meaning_ack` と現在の身体登録・分類・観測fixtureへ合わせる。
- 句そのものの質問と詩の資料質問を分け、現在句・pending・会話段階を保持するケースを確認する。
- 警告待ちのFIFO・重複抑止・上限・音声失敗・死亡／次元移動／接続終了による取消を確認する。撤去済みの漢字学年等の専用知識を前提にする入力は、現在サポートする質問へ置き換える。
- 川柳の戦闘中に通常モードで受けた質問は、川柳再開で分類境界が変わると取消になる。ここは取消・再分類なしを確認し、正常なFIFO配送はworkshopなしの警告中ケースへ分ける。重複再送は同じ入力元を使い、分類の遅延を制御していないケースを「分類完了前」と呼ばない。
- 単独実行を通し、結果を記録してコミットする。

### 3. 肯定的講評試験

- 保存と状態変更の区別、重複受信、未採用案、戦闘割込、保存待ち、接続終了後の遅延結果を確認する。
- 再試行やconfidenceによる拒否を前提にするケースは現行処理を調べ、必要なら現在の失敗・取消境界を直接試すケースへ置き換える。生成回数の上限も確認する。
- 現行の会話出力の外形補完は最大2回の枠が残っている。撤去済みの編集案再生成と区別して確認する。不正feedbackは、モデルが実際に返す通常会話で保存されないことを試す。
- 単独実行を通し、結果を記録してコミットする。

### 4. 再発検出と最終確認

- 既存CIが収集する `dogido-rust/tests/python/test_*.py` に、3本を別Pythonプロセスでimportする軽量テストを追加する。HTTP・モデル・音声は起動せず、timeout付きで欠けたimportを検出する。
- 3本を最終状態で完走させ、各ケース数・失敗0・所有プロセスの終了を確認する。既に最終状態で単独完走している試験は、以降の変更が依存先に及ばない限り重ねて実行しない。
- `dogido-llm/bin/python -m pytest -q tests dogido-rust/tests/python/test_*.py` を実行する。既存skip・対象外の失敗があれば成功と分ける。
- 本体コードを変更しない場合は既存debug buildを確認し、試験修復のためだけのrelease更新やFabricビルドは行わない。本体変更が生じた場合は関連Rust試験と全targetを実行する。
- `dogido-rust/README.md` に3本の目的と確認入口を簡潔に反映し、前の重複整理計画に修復先を追記する。本書を完了状態へ更新してコミットする。
