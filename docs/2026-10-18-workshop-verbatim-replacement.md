# 川柳相談の指定語句を原文の範囲で保持する

状態: 明示置換と矢印指定の修正、模擬通信18件、releaseビルド・一般起動チェックが完了。稼働中の本体には未反映。

## 原因

2026-10-18の相談で、`ゆらぐひが を うつろいの に変えてください。` に対してモデルが `replacement_text=うつろい` を返した。音声認識後の `揺らぐひがをうつろいのに変えてください` では、旧語も `target_fragment=ひが` に縮めた。原文への部分一致だけでは両方を通してしまい、本人が指定していない句を音数検査へ渡していた。

`うつろいの` は5音。文字入力時の検査は4音の `うつろい`、音声入力時は `ゆらぐうつろい` を対象としていた。分類表示にも誤りがあったが、この2入力はworkshopへ到達している。

同日の追加ログでは、17:01:36の `しろいしをてらし -> しろすなてらし` に対し、モデルが直前の8音の案 `しろすなをてらし` をtool引数に再利用した。原文検証がこれを拒否した後も、モデルは古い案を読み確認して8音と説明した。今回の指定自体は7音であり、音数計算の誤りではない。17:01:10の `しろすなをてらし` を8音として拒否した結果は正しい。

追加ログの本体は15:23起動のプロセスで、先の16:51ビルドをまだ使っていなかった。ただし先の修正は `AをBに変えて` が対象であり、矢印指定には今回追加の対応が必要だった。

17:02:13に単独で入力した `しろすなてらし` は17:02:19にrevisionへ保存され、中七だけが変更されている。17:02:54の「保存させてもらう」は追加の保存ではなく、その時点ですでに保存済み。17:03の終了後は `open=false` / `close_reason=explicit_close` を確認した。

## 修正

- 既存のnative `stage_player_edit` 内で、明示形 `AをBに変えて` と `A -> B` / `A → B` の範囲を原文から取り出す。前者は `に変えて` などの操作部分を分け、B末尾の `の` を含めて保持する。矢印では左右の語句に含まれる `を` も保持する。
- 元句と原文根拠を従来どおり検査した後、明示形では原文のB全体を使う。モデルが短縮・補作した語や前の案を使わない。Aも原文の範囲で現在句へ照合し、モデルが縮めた旧語に置換しない。
- 引用符の内側の `を` は語句として保持する。複数の引用外区切り、閉じていない引用、複数変更は推測で一つへ絞らない。
- `「A」→「B」` は左右の語句の引用として扱う。操作全体の引用・伝聞にはこの扱いを適用しない。矢印付きでも引用外の否定・疑問・条件は保存へ進めず、引用したB自体に含まれる表現は語句として音数検査へ渡す。
- 引用外の先頭にある `では` / `じゃあ` は、空白・読点・引用開始で区切られるか、旧語全体の辞書読みが現在句に一致しない場合だけ導入部として分ける。実ログの `では揺らぐひがをうつろいのに変えてください` も扱う。旧語 `ではじめる` / `では始める` や引用した旧語の内部は削らない。
- `中七のくろい` 等の行呼称付き部分変更は既存の行呼称処理を使う。引用された旧語の内部や、現在句に無い旧語の接頭部分を削って一致させない。
- 表記から読みへの変換、厳密な5/7/5、対象外の行の保持、現在句・版の再照合、revision保存は既存経路を使う。新しい入力経路・モデル呼出し・プロンプトは追加しない。

この補助は明示形の範囲を扱う。その他の自由な相談は既存のモデル抽出へ渡し、原文にない置換語を拒否する。明示形でも根拠・行ID・confidence・古い元句は補完せず、否定・疑問・条件・伝聞を検査する。音数を合わせるために指定語を削ったり補作したりはしない。
