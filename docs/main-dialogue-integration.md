## ローカル処理の設計方針（2026-10-18）

コード・辞書・DB・BERT等の軽量な分類器を優先し、LLMは自然な返答・説明・新しい句案など、生成が必要な箇所に絞る。意図分類と対象行・引数・現在状態の照合は生成前に済ませ、必要な材料をまとめて渡す。生成は一つの応答につき原則1回とし、分類済みの意図の再判定や、別LLMによる意味採点・形式修復・失敗後の返答再生成を重ねない。追加呼出しが必要な場合は情報取得の依存関係と上限を明示する。

川柳の対象は手元の現在句・未採用案・原文を既存コードで照合する。感想や音数の不一致だけでは修正を開始せず、意図・対象・保存前の元句と版の確認を分ける。分類追加は担当チャットの既存作業へ合わせる。

これは今後の実装・改修に適用する方針であり、既存の多段処理を撤去済みという記録ではない。[呼出回数・分類追加の確認状況・移行先](2026-10-18-dialogue-model-call-audit.md) と [AGENTS.md](../AGENTS.md) を参照。

## 1. 会話ルートの所有者

session内に、同時に一つだけforeground routeを置く。

| route | 役割 | 非敵対ambient | 新しい自動川柳 |
|---|---|---:|---:|
| `none` | プレイヤー主導の話題なし | 可 | 通常条件で可 |
| `casual` | Minecraft観測を使う既存 `player_chat` | 最後の入力から30秒抑止 | 10分周期で可 |
| `knowledge` | 詩・Minecraftの正本DBの明示知識回答 | 抑止 | 周期ごと凍結 |
| `haiku_preparation` | 情景の先行音声と本句生成。pin・workshop期限は未開始 | 抑止 | pendingで抑止 |
| `haiku_workshop` | 既存の一句共同編集 | 抑止 | 既存workshop規則で抑止 |

- routeは長期記憶へ保存しない。
- 通常会話の本文履歴は従来の5往復を維持する。
- 雑談後の友好・中立Mobコメントは `DOGIDO_CONVERSATION_AMBIENT_MUTE_MS`（既定30秒）で再開する。会話保持の5分期限は維持し、入力待ち・危険・同種Mobのクールダウンは別に検査する。
- 詩・Minecraftの正本DB検索は既存workerで行い、通常会話は `player_chat` の一回生成へ渡す。
- 世界操作・敵方向・所持品・明示知識DB・workshop入力は、このworkerへ渡さない。
- 入力受付では未完了jobの上限を検査し、満杯なら `input_queue_full` を返す。警告で待つ通常会話・知識質問は別に最大9件（再開予約と中断に備えた進行中の一件を含む）で、満杯なら `reply_queue_full`。現行受付は [入力API](adapter-api.md#21-post-apiv1player-input) を参照。

### 撤去済みの履歴: 学習中の突然の別話題

- 直前の会話活動から2分以上空いた入力、明示名指し、または明示的な話題転換は、新しい話題として直ちに本体 `player_chat` へ渡す。
- 2分未満で、学習内容と無関係かつ宛先も不明な突然の別話題は、その場で返事を生成せず、原文と元 `turn_id` を一件だけ `awaiting_address` に保つ。
- 後から「ドギド」等で呼び直されたら、コード固定の驚き・謝罪と、保留原文から切り出した短い話題を読み上げ、「今から聞いてええ？」と確認する。この修復質問の実再生 `completed` 前の肯定では元入力を動かさない。
- 肯定後は保留した元入力を同じ `turn_id` のまま本体へ一度だけ戻す。5分で `expired_unaddressed` として終端し、呼び直しでは期限を延長しない。
- 新しい宛先不明入力で一件枠を置き換える場合、古い入力も `replaced_unaddressed` として明示終端する。待ち列が満杯なら `host_chat_queue_full` とし、通常履歴へ混ぜない。

## 2. 再生完了を会話の正本にする

入力、生成した返答、音声再生を `turn_id` と `utterance_id` で結ぶ。

```text
player accepted
  -> reply selected
  -> audio queued
  -> audio started
  -> completed | failed | cancelled
```

- プレイヤー発話は受理時に台帳へ記録し、返答の所有routeが決まった時点で短期会話に共有する。状態機械が返す正本DB回答も同じturn IDを使う。
- ドギドの発話は、音声プロセスの `completed` を本体の配送結果として回収した後だけ履歴へ入る。モデル生成か固定文かでは分けず、戦闘・危険警告、支援の返答、環境反応、川柳の前置きも対象にする（2026-10-07修正）。句本文・句の相談・想起や保存結果は既存の出来事形式で共通文脈へ渡し、通常雑談の完了対や新しい句の材料へ二重登録しない。旧Web読書用の専用履歴は撤去済み。
- `failed`、実際に `cancelled` となった音声、キュー置換、未配送の古いworker結果はassistant履歴や川柳材料へ入れない。
- workerの生成epochと、dispatcherへ渡した音声の事実を分ける。戦闘開始後でも、すでに再生開始して実際に正常終了した通常返答は `completed` のまま残す。実プロセスを止めた返答だけを `cancelled` にする。
- dispatcherが一つのbatchを取得した後に割り込まれても、現在actionと未開始の末尾actionすべてへ一度ずつterminal通知を返す。末尾を台帳上の `queued` のまま残さない。
- **2026-10-18: 音声出力が始まったら極力切らない。** 相槌・くしゃみ等の新入力は、既存の有界FIFOで現在の台詞の完了を待ち、同じ受付へ一度だけ戻す。生成中・再生前は新入力を優先する。純叫声の診断記録だけで開始済み音声を止めない。
- 通常会話・相談・環境コメント・警告・川柳の前置き／本文へ共通の実再生開始判定を使う。通常の観測変化や観測更新の途切れ、期限到達だけで話の途中を切らない。川柳は完走した行の履歴を確定し、次の生成・保存・読み上げ開始には引き続き現在性と安全の検査を行う。
- 緊急警告、明示的な停止、voice off、セッション終了・ワールド切替・サーバー終了による取消は維持する。「静かにして」等の既存停止形はBERT待ちや観測失効で保留しない。実際の再生失敗・取消を完了扱いにはしない。
- audio callbackはsession状態を直接変更せず、上限付きのイベント列へ結果を積むだけにする。
- 音声無効時は「選んだ本文」を「実際に話した本文」と見なさない。ゲーム外表示履歴とは別の境界である。

## 3. 戦闘中の会話と緊急警告後の回答

**2026-10-18実装・模擬通信で確認。** 敵の視認・聴取、直近被弾、adapterのcombat activeは戦況の根拠として保持する。交戦中であることだけを理由に、プレイヤーの質問・通常会話を拒否したり、進行中の返答を取り消したりしない。

### 会話と警告

- 敵の数を知らせる `hostile_count` は、録音断片の再生と欠損時のTTSを従来比1.15倍にする。`hostile_callout_playback_rate` の既定値は共有JSONに置き、`DOGIDO_HOSTILE_CALLOUT_PLAYBACK_RATE` で変更できる。録音再生にはafplay互換の `-r`／`-q` を使う。悲鳴cueは通常速度を保つ。

- 通常のプレイヤー会話は既存の `player_chat` と知識回答の経路で受け付ける。戦闘専用モデル・新しい会話route・旧動作へ戻す互換設定を作らない。
- 今回の入力・生成開始時の現在観測・完了済み履歴から、質問への答えと必要な注意を一つの返事にする。同じ敵への注意を毎回付けず、視認・聴取・過去観測を区別し、確認できない方向や敵の状態を補わない。
- 危険の検出、警告の優先度・間隔・現在性は引き続きコードが所有する。既存の緊急警告はLLMを待たずに配送でき、必要な場合は返答の生成・再生へ割り込む。通常の敵の存在や戦闘modeの継続だけでは割り込まない。
- 緊急でない戦況発話は進行中の返答を取り消さず、配送時にも現在性を確認する。古い警告や戦闘終了時の安堵で新しい質問を失わない。

通常会話の目的文に加える文言は、承認済みの次の内容とする。

> 敵がおるときも、プレイヤーとの会話に応じてな。注意が必要な状況なら、回答に短く注意を自然に含めてな。変化がない注意は繰り返さんでええで。

### 中断した入力の保持と復帰

- 緊急警告中に受け付けた入力と、緊急警告で返答が未完了になった入力を、既存の有界な保留処理で保持する。原文・source・元turn・分類結果を結び、警告で取り消した生成結果を回答済みと扱わない。
- 警告の配送が終わり、現在観測が有効で次の緊急警告がない時点で、保持した入力へ自動的に答える。戦闘終了や「さっきの質問」の言い直しは待たない。保留中の入力は受理順に扱い、再開では最新の観測を使う。
- 緊急警告が再び割り込んでも同じ入力を重複登録せず、完了済みの返答は再実行しない。古いepochの生成結果・取消通知で、新しい回答や完了済み履歴を上書きしない。
- 音声の実再生完了またはMinecraft文字表示ACKで配送済みとなった返答だけを完了扱いにする。途中で取り消した本文は発話済み履歴・川柳材料へ登録しない。
- 手動停止・静かにする依頼・セッション終了・接続の入れ替わり・死亡・次元変更では保留を終端する。支援命令・保存・workshop操作を通常質問として自動再実行しない。入力分類器未設定で、生成中の入力がまだ会話か呼び寄せか確定していない場合も原文を保持するが、再開時に呼び寄せ依頼と判明したら `interrupted_operation` で終端し、候補選択・実行へ進めない。発行済み命令のある入力は保持しない。
- 旧来の「戦闘中は通常会話を拒否」「戦闘中の会話試行に固定相槌」「戦ったので覚えていない旨の追記」「戦闘話題を10 player turn保持して明示再開を待つ」は撤去し、互換分岐として残さない。発句準備など別の理由による話題保持は今回の変更対象にしない。

危険開始時の通常会話5往復を一時保護し、危険終了後3通常turnまで共有する履歴保護は維持する。`player_died` では `combat_ended` を待たず戦闘状態を解放し、死亡の発話は既存の状態機械が所有する。

音声認識結果が全文で反復叫声だけの場合、通常player input・workshop・学習worker・LLM会話履歴へ入れない。原文は上限付きの非永続診断だけに残し、LLMへは、同時点のコード観測から作った「敵対モブを視認」「爆発を観測」「原因不明の驚き」等の短い状況メモだけを渡す。叫び声の字面から敵・落下・爆発を推測しない。現行event契約には生存中の落下を確定する接地・落下距離がないため、落下は未観測時に断定しない。

川柳workshopの戦闘中断は `dogido-rust/src/workshop_combat.rs` と `src/dialogue/workshop_combat_runtime.rs` が所有し、通常質問の保留・自動復帰へ置き換えない。

## 4. 雷と夕方

- 最初に実測した雷鳴／近距離落雷は現在のplayer replyより先に割り込み、同じ入力を次tickへ戻す。会話routeと履歴は消さない。
- 以後は既存のcue 10分・一言3分のcooldownを使い、再度話す場合は非割り込みの小さな懸念にする。
- 「player_chatを返したので雷を3分無視する」という旧規則は使わない。
- 地表夕方の既存警告も同じ入力を次tickへ戻す。洞窟・水中・安全な屋内の既存除外と、一晩一回の規則は維持する。
- 2026-10-18: 川柳の生成・前置き・本文読み上げと、開いているworkshopは夕方警告より優先する。既存focus判定で警告を未発話のまま保留し、終了後の現在観測でも夕方の条件を満たすときだけ一度話す。翌朝や安全な屋内へ変わっていれば、古い警告を持ち越さない。**川柳関係は再生前・生成前からコードで抑止する条件を維持する。** 通常会話も音声が始まった後は夕方警告を保留する。雷・危険な熱源はこれより先の既存判定で扱う。

## 5. 雑談中の自動川柳

雑談が続いても発句を永久に止めない。

- 通常の10分周期が来ても、現在のマイク入力やplayer replyを途中で切らない。
- player replyがある境界ではその返答の後ろ、そうでなければ次の安全なstatus／音声キュー境界へ、生成した情景（ironyのdescription）を非割り込みの先行音声として置く。雑談中も固定の前置きへ置き換えない。音声本文はRustの発句準備と `dogido-rust/src/dialogue/haiku_runtime.rs` が組み立て、workshopやHUDの状態を変更しない。
- 再生完了済みの直近3 turnだけから、目標40〜60字・最大80字の短い会話材料、最大3語のmotif、元turn IDを作る。
- 会話材料は `player_reported_context` として元turn IDへ結ぶsoft材料であり、Minecraft世界の実測事実やhard制約へ昇格しない。
- 先行音声に含めた取り合わせだけを `spoken_preface` として出典へ結ぶ。これは川柳生成側の発話選択記録であり、スピーカー実再生完了の証明ではない。従来の未発話解釈 `generated_unspoken` は読み戻し互換として区別する。
- 情景音声から本句生成までは雑談を `suspended` に置き、foregroundを `haiku_preparation` にする。句が生成検査を通った時点でpinと `haiku_workshop` を開始し、2026-10-11から全体240秒の上限は廃止し、句または相談の返答が届いた後の無発言300秒で閉じる。返答の生成・待機・読み上げ中と戦闘中断中は失効させない。移動・道具使用・snapshot受信だけでは延長しない。生成前の観測時刻や古い待機入力へ時計を戻さない。失敗・危険による取消では新しいpinを作らず準備段階を終了する。
- 考え顔は実際の生成処理中だけ表示し、先行音声／句の配送前に通常顔へ戻す。掛け軸は完成した句だけを表示する。情景音声の生成・本句生成の所要時間はworkshopの持ち時間へ含めない。
- `learning` と `web` の間は発句間隔そのものを凍結する。解除直後に抑止時間分をまとめて経過扱いにしない。
- 発句準備中に危険が来た場合は、既存規則どおり古いprompt・材料・pendingを破棄する。

## 6. 撤去済みの履歴: Web接続とMinecraftの自動ポーズ

### 本体の専用Chrome検索

本体 `MainLanguageRuntime` は、利用前提が揃うMacでだけ独立試験と同じ可視Chrome providerを受け取る。起動時の確認はファイル・設定・任意依存の読み取りだけで、ChromeやMCPプロセスは開始しない。

```text
国語・語句の問い
  -> Web検索の同意確認
  -> 「ほな一緒にいこか！」を音声キューへ
  -> 対応する発話IDの実再生 completed
  -> game-event worker外の有界workerで、専用Chromeへ検索を一度だけ開く
  -> foreground=web のまま、本人の報告・質問・明示復帰を待つ
```

- `DOGIDO_MAIN_LANGUAGE_WEB_ENABLED=true` が既定。専用MCP実行ファイル、MCP SDK、`show_browser=true` の表示用設定、Google Chromeのいずれかが欠ける場合はWebだけを無効にし、国語対話とsession作成は継続する。
- 同意前・案内音声の生成／開始だけ・`failed`・`cancelled`・古いepoch・開始前の戦闘中断・満杯で制御処理を受け付けられない場合は開かない。対応する `completed` は一度だけ消費する。既にページを開いて読書中なら、敵対警告を優先しつつ調査文脈は戦闘後まで保持する。
- 検索・15秒後の単発読み取りは既存の直列background workerで行い、ゲームイベント処理を待たせない。検索直後には説明音声を重ねず、表示されたページを読む時間を優先する。
- 調査文脈がある間は `foreground=web` が非敵対ambientを抑止し、自動川柳の時計を凍結する。通常会話の5分期限ではなく、既存のWeb読書用30分期限を使う。
- CAPTCHA、検索失敗、不正なproviderでは固定の失敗案内へ落として `learning` に戻す。通常のChromeプロフィールや既存タブは使わない。
- 「冒険に戻る」等の明示復帰で `foreground` を解除する。本体の短期文脈へ持ち帰るのは `return_context.researched_topic` の一件だけで、ページ本文・AI概要・URL・理解度は渡さない。復帰案内も他のassistant本文と同じく、実再生 `completed` 後だけ会話履歴へ入る。
- MCP接続と専用Chromeはsession runtimeが所有し、session終了時に閉じる。明示復帰時のMinecraft再フォーカス、専用タブの即時close、OS前面監視、自動再読はまだ行わない。
