# 発句の取消・不成立時に画像と内部表現を整理する修正計画

2026-11-04。書類側mainの撮影・生成・保存・本棚保全の実装を確認した。1〜6節は承認された設計を記す。実装と検証の結果は末尾に追記する。

## 1. 目的と現状

新しい発句で作られた画像・内部表現を元の発句ジョブへ帰属させ、取消・生成不成立が確定したジョブの素材を自動削除する。完成句の生成過程は、初稿・見どころ・情景・行の再生成を含めて、その句へまとめて保持する。保存待ち・保存失敗は、生成の取消や不成立と区別する。

現状の経路は次のとおり。

- [発句処理](../dogido-rust/src/dialogue/haiku_runtime.rs)は撮影を予約し、モデル要求を進め、完成した発句記録を非同期で保存する。保存開始後の音声取消でも、句の保存処理は継続する。生成不成立も通常の発話完了と同じ `Result<()>` に収まるため、戻り値の成功・失敗だけでは削除可否を判断できない。
- [撮影台帳](../dogido-rust/src/screenshot.rs)の `discard_unbound` は予約を閉じ、遅い結果を別の句へ渡さない。[Fabricの撮影](../adapter/minecraft-fabric/src/main/java/dogido/fabric/screenshot/ScreenshotRuntime.java)は先にPNGを保存し、[ACK処理](../adapter/minecraft-fabric/src/main/java/dogido/fabric/screenshot/ScreenshotProtocol.java)は結果の再送を終える。どちらも、不成立のPNGを削除する契約を持たない。Fabricは切断時に未ACK結果をメモリから外すため、再起動後の帰属回復も必要。
- [内部表現の収集](../dogido-rust/src/haiku_capture.rs)は要求直前に要求IDをメモリへ記録し、返答後に応答IDから数値を照合する。[GGUF採取器](../dev_tools/haiku_internal_probe/gguf_capture.h)は応答ID別のフォルダへ書く。応答前の取消やプロセス終了では、ドギド側が応答IDを知らないまま数値が残り得る。
- [句の保存](../dogido-rust/src/haiku_record.rs)は既存の句IDを検出すると `inserted=false` を返す。この返却だけで「今回のジョブが保存済み」か「別内容との衝突」かを確定させず、保存済みの原記録を再照合する必要がある。
- [SSD正本の入力整理](../dogido-rust/src/bookshelf/primary_storage.rs)には、完成句の素材をSSDで検証してから元ファイルを整理する処理がある。成功分にはこの経路を使う。今回の追加対象は、未成立・取消分の帰属と終了確認、その後の処分である。

## 2. 削除判断の基準

**生成の結末、句の保存状態、素材を書いている側の状態を別々に管理する。** Rustが削除の可否を決め、画像は撮影元のFabric、数値は採取先にアクセスできる処理が、所有するファイルだけを削除する。

| 状況 | 紐付けと素材の扱い | 次に確かめること |
|---|---|---|
| 撮影・モデル生成・検査・再生成の途中 | 元ジョブの素材として保持 | 書込みと生成の終了を待つ |
| 取消・期限切れ・生成不成立が確定し、完成した発句記録がない | 同じジョブの素材を削除候補にする | 書込み終了、保存処理が未開始、完成句・手動貼付等からの参照なし |
| 発句記録が完成し、非同期保存の開始前または保存中 | 保存先未確定の素材として保持 | 元の発句記録の保存結果を待つ。音声取消でもこの扱いを維持する |
| 句の保存成功、画像登録・SSD保全待ち | 保存済み句へ結合し、入力ファイルも保持 | 登録・保全の完了と内容照合 |
| 句と素材のSSD保全が完了 | SSD上の素材を保持し、検証済みの一時入力を既存の整理処理へ渡す | 保全札、要求・撮影ID、長さ、ハッシュが一致 |
| 句保存失敗・書込み結果が不明 | 元ジョブの完成した発句記録と素材を保留 | 同じ句IDで保存を照合・再試行。新しい句へ付け替えない |
| 句保存は成功したが画像登録・SSD保全に失敗 | 保存句との対応を維持して素材を保留 | 同じIDで登録・保全だけを再試行 |
| 重複保存で `inserted=false` | 保存済み原記録の句ID・ジョブ・素材要求を照合 | 同一処理の再送なら成功扱い。食い違いは保留し、自動修正・削除しない |
| 保存後の読み上げ取消、再生失敗、相談の中断 | 保存された句と素材の対応を維持 | 発句の不成立として扱わない |
| 出自不明、参照の衝突、ファイルの差替え、SSD切断 | 保留し、理由を記録 | 既知の対応を回復してから再判定 |

完成句に結び付く一部採取・失敗・取消の要求記録も残す。音数検査で使われなかった再生成案などを、完成句の生成過程から間引かない。ユーザーによる句の削除・写真の手動配置は既存の所有処理が扱い、この自動整理から句本体を削除しない。

## 3. 送信前から帰属を残す

### Rustが持つ記録

既存の発句・撮影・要求のIDを利用し、一件の発句ごとに小さな永続管理記録をSSD正本へ置く。記録先の案は `artifact-jobs/<ジョブID>.json`。保管庫ID、起動世代、接続のinstance、セッションID、ジョブID、撮影命令ID、モデル要求ID、保存先の句ID、状態・参照・照合結果を持つ。絶対パスやファイル名の日時を帰属の根拠にしない。

撮影・モデル要求を送る前に対象IDを記録する。完成した発句記録は、保存が確定するまで同じ管理記録の配下へ既存の形式で一時保持し、再起動後も同じ句IDで保存を再開できるようにする。確定後はその一時本文を整理する。対話や数値の全文を管理台帳へ重複保存しない。

SSD切断等でこの記録を書けない場合は、破壊的な自動整理を始めない。既存の発句・失敗通知を維持し、残った素材は由来が回復するまで保持する。メモリ上だけにある未保存の完成句は、再起動後に必ず復元できるとは扱わない。

### 画像

撮影命令IDをキーに、Fabricの撮影側にも帰属の記録を残す。記録先の案はゲームディレクトリ内の `dogido-vision/poem-capture-jobs/`。撮影受付、PNG保存完了、ファイル名・ハッシュ・同一ファイルの識別、処分指示の適用状態を記録する。新しい撮影先を作ることはこの計画の目的に含めず、現在の原寸PNG保存を利用する。

Rustからの「削除指示」は元の撮影命令IDと確定した処分の世代を指定し、Fabricは自分の台帳からPNGを引く。一般のスクリーンショットや、同じ分・同じ秒の別画像には適用しない。処分指示がGPU読取・PNG保存より早く届いた場合は記録して待ち、保存処理が閉じてから適用する。

現在のACKは配送確認として維持し、削除許可を表す情報と分ける。切断・再接続でも未確定の撮影記録を残し、同じ撮影元と設定済みサーバーへ照会する。古いセッションの結果は元の記録の決着だけに使い、新しい発句へ付け替えない。

この契約は新しいcapabilityで合意する。既存の `client.screenshot.body_view.v1` 対応だけでは削除を指示しない。未対応時は発句を継続し、素材の保留を記録する。

### 内部表現

ドギドが送信前に作る一意の要求識別子を、既存の採取フラグと同じHTTPの追加メタデータとして渡す。フィールド名の案は `dogido_capture_request_id`。モデル向けの本文には含めない。

採取器は、このIDと応答IDの対応を生成の受付時から記録し、待機・書込み中・終了を追跡できるようにする。これにより、応答がクライアントへ返らなくても元ジョブの採取物を探せる。呼出し元・起動世代も照合し、通常雑談、試験、他アプリの採取は対象に含めない。

各要求のwriterがファイルを開く前から最終マニフェストの確定まで、終了確認できる所有権とロックを持つ。RustがHTTPの待受けを取り消した時点や、`manifest.json` の `complete` という文字だけで削除しない。要求の終端、書込みハンドルの解放、再開されないことを確認して処分する。途中で落ちた採取器は、起動世代とロックの解放・永続記録を突き合わせて回復する。

常用GGUF採取器には、この帰属・終了確認の対応が必要。旧マニフェストを読める状態は維持し、新しい帰属情報を持たない採取物は自動削除から保留する。モデル管理側の実行ファイル更新は、実装段階で対応ソース・ビルド・起動プロファイルを照合して行う。

## 4. 紐付け・保存・削除の順序

### 完成句の保存

1. 生成成立後、同じジョブの発句記録・素材一覧を保存待ちとして確定する。発話の成否とは独立させる。
2. 既存の句IDで保存し、正本のJSONLを再照合する。返却エラーの直前に書込みが済んだ可能性も調べる。同じ句が確認できれば保存成功に進める。書込み途中・破損・別内容との衝突は保留する。
3. 撮影IDから同じジョブの句IDへ一度だけ結び、モデル要求は元の順序と応答IDを保持する。時刻、句本文の類似、ファイルの内容ハッシュだけで対応先を決めない。
4. 画像登録とSSD保全を完了させ、既存の完了札・ハッシュ照合後の一時入力整理へ接続する。登録の再送・プロセス再起動でも二重貼付や対応先変更が起きないようにする。

保存失敗後に利用するのは同じ発句記録の保存再試行であり、モデルによる再生成ではない。再試行は保存先の復旧時・再起動時等に既存の保存／同期の所有処理から行い、同じ失敗を無制限に並列実行しない。別の句へ誤適用しないよう、元句・版・削除状態も再照合する。

### 取消・不成立の素材

1. 発句の生成結果として「取消」「不成立」「生成成立」を明示する。既存の発句終了処理へ集約し、深いエラー分岐や単なるDropから直接削除しない。
2. 取消・不成立でも、既に完成した発句記録や進行中の保存jobがあれば保存結果を待つ。書込み元の終了も確認する。
3. 画像登録、句の原記録・修正履歴、SSDの保全札、写真の手動配置・ごみ箱内参照等を確認し、素材を必要とする参照がないことを確かめる。既存の保存・本棚ロックと決定の世代確認で、登録／保全と削除判断を競合させない。手動貼付で素材を読んでいる間も解放を待つ。
4. 同じ素材について処分を一度だけ確定し、処分記録を永続化する。新しい参照が先に確定していれば削除を中止する。削除予約後に同じ素材の利用が始まった場合も、コピー・登録の完了を照合するまで削除を確定させない。
5. 書込み元が閉じた素材を、同一ボリューム内の既存の固定退避名方式で移動し、同じファイルか再照合して削除する。画像はFabricの管理下のPNGだけ、内部表現は対象要求の専有フォルダ内の既知ファイルだけを扱う。片方が失敗しても他ジョブへ処分を広げない。
6. 削除済みまたは元から未作成なら処理済みにする。再送・再起動では同じ処分を続け、途中で失敗した削除も残った対象だけを再試行する。ファイル差替え、リンク、未知のファイル追加、保管庫IDの不一致では保留する。

素材I/Oは音声再生の枠や通常対話の生成待ちを占有しない既存job管理へ接続する。終了時は、開始済みの保存・整理の決着または再開用記録の永続化を待つ。素材の削除失敗で発句や会話を再生成しない。

### 再起動・遅延・旧データ

- 再起動時と既存の同期契機に、管理台帳にある未決着ジョブだけを照合する。全フォルダを「古い」「句が見つからない」だけで削除する走査は行わない。
- 切断中の撮影完了やモデル応答前の取消も、書込み元が永続記録を持つ。再接続後に元のジョブの処分を適用する。未ACK結果の上限や短い待受け期限で、帰属情報まで失わないようにする。
- 古いプロセスが生存・書込み中のもの、保存結果が未確定のものは待つ。時間が経ったことだけで終了済みとはしない。
- 既存の完成句・写真・内部表現は既存の参照で保護する。帰属を証明できない旧ファイルは要確認として残し、今回の新規ジョブ用ルールを遡って当てはめない。
- 終端の処分記録は、書込み元も処理を終え、遅延結果や再送が来ても同じ決定を確認できる状態で整理する。保留理由と対象件数は既存ログへ出し、PNG・数値の全文はログへ追加しない。

## 5. 実装する単位

| 順序 | 主な変更先 | 到達点 |
|---|---|---|
| 1 | `haiku_runtime.rs`、`haiku_capture.rs`、既存job管理 | 生成結果と保存結果を分け、発句と素材の帰属・保存待ちを永続化。削除を伴わず各分岐を確認する |
| 2 | `python_worker.rs`、`llm.rs`、GGUFの `gguf_capture.h / .patch` | 要求の送信前IDと採取器の応答IDを結び、応答前取消・writer終了を追跡。対応backendの導入を確認する |
| 3 | `screenshot.rs`、`dialogue/observe.rs`、Fabricの `ScreenshotProtocol / Runtime`、`BodyViewCapture`、`DogidoEventClient` | 撮影元に帰属と処分を残し、配送ACKと削除許可を分離。切断・再送・保存中の削除指示を確認する |
| 4 | `bookshelf/captures.rs`、`primary_storage.rs`、既存の保存・保全処理 | 参照の競合を防ぎ、取消・不成立の専有素材を削除。成功分は既存のSSD照合後の整理へ接続する |
| 5 | Rust／Python／Fabricの該当試験、仕様文書 | 一時データで以下を確認し、実採取・実Minecraftの確認結果を別に記録する |

モデル向けのプロンプト、生成回数、生成の採否基準はこの変更の実装範囲に含めない。既存の採取仕様にある「未結合の観測を残す」「自動削除しない」の記述は、実装時に新しいジョブの帰属と削除条件に合わせて更新する。

## 6. 検証する期待と合格条件

自動試験は前回追加した保存隔離を利用し、画像・数値・句・評価ログを試験ごとの一時フォルダへ置く。各ケースの直前にも期待・合格条件・確認範囲を記す。模擬の数値と実モデルから得た数値は区別する。

| ケース | 期待と観測する合格条件 | 確認範囲 |
|---|---|---|
| 撮影直後の取消、生成の不成立・上限終了 | 同じジョブの画像・数値だけが書込み完了後に消え、句の登録が増えない。2回の発句・複数要求で枚数と応答IDを数える | Rust実処理＋模擬モデル／Fabric IO |
| 応答前取消、遅いPNG保存 | HTTP本文や成功結果が未受信でも、送信前のIDで素材を特定。writer実行中は残り、終了確認後に同じ素材だけ消える | 模擬の遅延・遮断＋採取器単体 |
| 取消の直後、同じ秒に次の句が成功 | 取消側の素材は削除。成功側は別の撮影・要求IDで一つの句へ結合し、全ハッシュが一致 | Rust＋Fabric・採取器の模擬通信 |
| 生成成立後の保存待ち、音声取消・再生失敗 | 保存jobの前後で素材が残り、同じ完成句の保存・登録が一度だけ進む | 一時保存先と保存を止めるゲート |
| 保存失敗、書込み完了後のエラー返却 | 素材を保持。正本に同じ句がある場合は重複せず成功へ進む。部分書込みや別内容との衝突は保留 | 実ファイルI/Oの障害注入 |
| `inserted=false` | 同一ジョブの再送は既存の句へ一度だけ結合。別内容の同じIDは元データ不変で保留 | 正本の保存・再読 |
| 画像登録／SSD保全失敗・SSD切断 | 入力素材を保持し、復旧後は同じIDで処理。Macに別の正本を作らず、完了札とハッシュ照合後だけ入力を整理 | 一時保管庫、故障した保存先 |
| 保存・手動貼付・保全と整理が同時 | 有効な参照または読出しがある素材を失わない。対象の句・写真配置と数値が読める | 同期点を制御した競合試験 |
| 管理記録の各境界で停止・再起動 | 完成した同じ句の保存と登録を再開でき、削除途中は同じ対象だけ再開する。writer未終了・保存不明は残る | プロセスの実停止・再開 |
| 誤った応答ID、変更されたPNG、リンク、他アプリの採取、未対応版 | 自動削除も誤結合も行わず理由を記録。正常な別ジョブは処理可能 | 固定の負例、プロトコル互換性 |
| 完成句に複数回の再生成・一部採取がある | 一句の生成過程の要求一覧が元の順序で残り、取得可能な数値と画像が同じ句から読める | 既存保存形式と本棚API |
| 常用環境での最終確認 | 実Minecraftで取消／成功を各1回確認し、隔離した実採取で応答前取消と終了後整理を確認。保存句・画像・数値を本棚から読戻す | 実機・実採取。実行時に実際の確認範囲を記録 |

完了条件は、未成立・取消の新規ジョブについて、作成済みの専有素材が終了確認後に残留しないことと、完成句・保存待ち／保存失敗・処理中・参照ありの素材を保持できること。保存隔離、既存の撮影・採取・本棚の回帰確認も通したうえで、実装と実機確認を分けて報告する。


## 7. 実装・検証結果（2026-11-04）

書類側mainへ統合した。モデル向けプロンプト、生成回数、句の採否基準は変更していない。

- `artifact-jobs` に発句・撮影・送信前要求IDと保存状態を永続化し、取消・不成立だけを `discard` にする。完成原記録は保存待ち・保存失敗の間も保持し、同じ句IDで保存だけを再試行する。
- GGUFは要求IDと応答IDの対応、writer終端札とOSロックを追加した。終了確認・参照照合・退避後の内容照合が通った専有ファイルだけを削除する。旧形式・破損した台帳・参照の不明・writerの終了不明は保留する。
- 完成句への画像登録は正本内容を照合し、遅延結果も元の撮影から一度だけ結合する。Fabricは画像・受領結果・保持／削除決定・配送ACKを端末台帳に残す。同じownerの再接続後に未ACK結果を元sessionのまま再送し、ACKを永続化してから再送を終える。
- 句・修正履歴・ごみ箱・写真配置・SSD研究snapshotの参照を照合する。登録と削除のロック順を揃え、差し替えられたファイルや外部リンクを処分しない。
- 最終レビューで、撮影の終端失敗も永続ACKできるようにし、受領済みの結果・ownerと異なる再送にはACKを転用しないよう補正した。画像の登録直前には句ロック内で正本の一意性・保存時digest・jobを再照合し、差替え・重複行を保留する。無関係な破損台帳があっても、正常な台帳で帰属が確定する撮影の受領・処分・登録は継続できる。
