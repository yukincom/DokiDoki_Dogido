# 出典付き知識質問の統合

**現行の所有者: Rust本体（2026-10-03）。** 旧Pythonの知識回答・音声配送・表示の本体経路は終了。資料の根拠・明示質問・出典・保存の境界は継続します。現行の実装先は本書「実装箇所」、起動は [Rust本体](../dogido-rust/README.md) を参照してください。日付付き試験結果は当時の記録です。

**移植前の確認記録（2026-09-02まで）:** 知識検索・文字入力・音声入力・VOICEVOXの基本経路は実機確認済み。文単位の音声配送、音声本文と参考資料の分離、ゲーム外の発言履歴画面はコード・自動テスト済み。2026-09-02にMinecraft接続下で「枕詞って何？」の4文配送計画、画面表示、参考資料の分離、クリップボードへのコピーを確認済み。スピーカーの再生完了通知と通常wheelへの知識DB収録は未対応。
**対象:** 国語知識、日本と世界の詩形、Minecraft Java Edition 1.21.11公式技術資料。

## 目的

プレイヤーが「枕詞って何？」「川柳の決まりを教えて」「一二三の一は何年生で習う？」「doMobSpawningはどう変わった？」のように明示して尋ねた場合だけ、ローカルの出典付きデータベースを検索して答える。

検索結果は戦況判断、支援操作、保存判断、川柳の強制条件には使わない。データベースはLLMの道具として公開せず、事実の選択と参考資料の対応付けはコードが担う。

## 処理順

```text
player input
  └─ 明示質問の候補抽出（DBアクセスなし）
       ├─ alert / panic / combat / death / assist を従来どおり優先
       ├─ 通常雑談を返す段階でだけDB検索
       └─ workshopを処理する段階でだけDB検索
            └─ 最大3事実 → コード固定の本文 + 別表示用の参考資料
```

`src/knowledge/query.rs` の入力分類では、領域、質問種別、発話中に実在する検索語、根拠断片だけを確定する。数十MBの索引を読む実検索は行わない。そのため、戦闘フレームに知識検索の遅延を加えない。

検索語は発話中の連続部分だけを用いる。「枕詞って何？」から「枕詞」を取り出すが、発話にない同義語をLLMや辞書で補わない。手整備DBの正式名と別名は、コード内の軽量な完全一致語彙と自動テストで同期する。日本語文型バンクは正式名800件をすべて照合し、波線で始まらない51件だけを分類語彙へ明示的に写す。同じ正式名に別の意味・用法がある場合は、最初の一義だけでなく最大3件まで別レコードとして返す。部分一致は領域判定に使わないため、「せんりゅう」は扱うが、「短歌大会」「自由詩人」「AIの活用」を詩歌・国語質問として誤認しない。二つの項目に重なる「俳諧の連歌」は曖昧なまま一方へ決めず、確認不能の固定返答にする。

音声認識が一文字の漢数字を `3` のような算用数字へ転写した場合は、対応する漢字を推測して答えない。知識質問として受け止めたうえで「一二三の一」のように前後を添えて言い直すよう、コード固定文で聞き返す。

警戒・戦闘中、死亡時、戦闘終了の発話時はDBを読まず、質問を予約中の一件も含めて上限9件の待ち列へ保留する。安全化後に先着順で一度ずつ検索し、直接再送された同文を二重回答しない。暗所だけの `alert`、Wardenのソニックブーム、状態表示が `normal` でも `combat_active_hint=true` のフレームも同じ扱いである。workshop入力と戦闘開始が同じフレームでも、句編集や現在句への質問を失わない。

## 対象と対象外

代表的な対象:

- `枕詞って何？`
- `まくらことばってどんな意味？`
- `川柳の決まりを教えて`
- `川柳にはどんな規則がある？`
- `ソネットの分類を教えて`
- `「一」は何年生で習う漢字？`
- `一二三の一は何年生で習う漢字？`（音声入力向け）
- `一の読みを教えて`
- `常用漢字表って何？`
- `学年別漢字配当表って何？`
- `～間の接続は？`
- `いたしますって何？`
- `doMobSpawningは1.21.11でどう変わった？`
- `ダイヤモンドの剣のIDは？`
- `minecraft:diamond_swordの作り方を教えて`

対象外:

- 単なる言及・感想
- 川柳や文章の生成依頼
- スラッシュコマンド
- 敵数、ドラゴン方向、音、所持品など、既存の世界状況質問
- `select_sword` などの支援操作
- workshop中に現在句の語を尋ねる質問

workshop中の一般知識質問は専用枝で一度だけ答え、pin、未採用案、講評、lesson、close、drift回数を変更しない。「平べったって何だろうか」のような現在句の語は、従来どおり保存済みの行出典だけで答える。

## 返答と出典境界

- 一回の検索結果は最大3事実。
- 生のJSON、用例全文、全タグを返答へ載せない。
- 事実本文と参考資料の対応はコードで固定し、通常の雑談LLMへ書き換えさせない。
- 手で確認した `dialogue_text_ja` がある項目は、データベースの正式な `definition_ja` を変更せず、表示・音声だけをドギドの短い関西弁へ切り替える。定義を一つ伝えたあと、教科書や資料集などの実際の資料へ進むよう促し、詳しい規則を一度に読み上げない。現在この対話本文を持つのは枕詞の定義項目である。
- 任意の対話本文は未指定または空文字なら通常の本文を使う。空白だけの本文、長さ上限超過、NULを含む本文は不正として棄却し、空の知識回答を成功扱いしない。
- 任意の事実をLLMで関西弁へ自動変換しない。ほかの項目へ広げるときも、対話本文を一項目ずつ人が確認してから収録する。
- ドギドは回答本文だけを話す。機関名・資料名・URLは音声に混ぜず、ゲーム外画面の「参考資料」に一覧表示する。
- 差替えproviderを使う場合は、候補の本文・分類・レコードID・出典一式を、非公開の正本 `LocalKnowledgeProvider` が同じ質問から再構成した結果と完全一致させる。正規provider自身は二重検索しない。
- `editorial_synthesis` は「資料を基にした整理」、`editorial_guardrail` は「運用上の注意」として、資料に明記された事実と区別する。
- 常用漢字表の音訓と学年別漢字配当表を混ぜず、各出典を別に保持する。
- Minecraftの識別子、対象版、公式ウェブページ／公式配布物の別を保持する。現在の回答対象版は Java Edition 1.21.11で、回答本文にも版を明記する。明示された別のJava Edition版には推測で答えない。Data Pack 94.1、Resource Pack 75.0、管理プロトコル2.0.0は本体の版番号と混同しない。
- 公式レシピの縮約データでは、レシピの `entry_id` が質問対象と完全一致するときだけ、レシピ種別と参照素材を答える。参照IDには入力と出力の方向が保存されていないため、素材側からレシピを逆引きした回答や、未保存の配置は補作しない。
- 主索引に記録した各データセットのSHA-256を実行時にも照合し、同じ大きさ・更新日時を装った差替えもinodeと変更時刻を含む状態キーで再検査する。
- 0件、DB欠落、ハッシュ不一致、索引破損では、推測しない固定文を返す。通常雑談LLMへフォールスルーしない。

## 文単位の音声配送

知識回答は、発話本文と構造化した参考資料を別々に保持する。Rustの `src/dialogue/audio.rs` と `sentences.rs` が本文を文境界で分け、VOICEVOXへ順に送る。

- 本文をLLMで要約し直さず、分割した全文を一つの発話IDへ結ぶ。
- 再生中の一文に加え、一文だけを先読み合成する。文ごとに独立した会話turnを作らない。
- 合成待ち、次の文の待機、再生中はいずれも同じ取消通知を監視し、危険割り込み後に古い続きを再開しない。
- playerの正常終了、取消、失敗を発話IDの状態へ反映する。会話履歴は実再生処理の完了後だけ確定する。

**旧Pythonの音声配送仕様は終了（2026-10-03）。** `AudioAction`、650ミリ秒の文間待機、2ワーカー・8バッチの待ち列という旧仕様は現在のRust配送条件ではない。現行の挙動は上記の実装と [Rust本体の確認手順](../dogido-rust/README.md#検証) を参照する。

## ゲーム外の発言履歴

`http://127.0.0.1:5055/dogido` に、Minecraft画面とは別の読み取り専用画面を置く。

- 「発言」にはRust本体が確定した本文を表示し、一件ずつ、または時系列の全文をコピーできる。
- 「参考資料」には、実際に回答へ使った公式資料の機関名、資料名、該当箇所、URLを表示する。資料名は読み上げない。
- 音声が危険割り込みで途中終了しても、確定済みの本文は画面に残す。
- Rust配送では実再生処理の `completed / cancelled / failed` を発話IDへ結ぶ。表示された本文だけで再生完了とは見なさず、完了通知も実際に人が聞き取れたことまでは証明しない。
- 返答対象のプレイヤー入力は発言と組にして表示する。座標、体力、内部プロンプトは発言本文へ入れない。
- 既定200件のプロセス内履歴であり、サーバー再起動時に消去する。会話記憶・評価ログとは混ぜない。

詳細は [ゲーム外のドギド発言履歴](dogido-utterance-display.md) を参照する。

手で確認した対話文がない場合の区別表示は、資料に明記された事実との境界を保つため、次の形に固定する。

| 事実の扱い | 発話上の表示 |
|---|---|
| 資料を基にした整理 | 「資料を基に整理すると」 |
| 資料を基にした注意事項 | 「資料を基にした注意点として」 |
| 公式リリースノートの要約 | 「公式リリースノートを要約すると」 |

枕詞の定義質問では、正式な定義と五音・五七調の情報を正本に残したまま、初回発話を次の4文に固定する。

> 枕詞かいな。枕詞っちゅうのは和歌で特定の言葉につながる定型的な言葉のことやで。教科書や資料集に色々書いてあるで！気になったらみてみよか！

## 現在の配置条件

Rust本体はリポジトリまたは配布フォルダの `source_cards.json`・国語／詩形の `reference/` と、必要な場合にMinecraftの `.dogido_reference/` を読む。Python補助のwheelだけでは資料は揃わない。欠落時はfail-closedとし、資料なしをモデル知識で埋めない。Minecraftの生成済み全量DBはGit管理外のままにする。

音声配送変更後の実機確認では、サーバーを完全再起動したうえで、同じ「枕詞って何？」を使い、文ごとの配送と間を確認する。資料名が本文に入らず、`/dogido` の「参考資料」には残ることも確認する。2026-09-02には本文4分割、発言／参考資料の別表示、本文コピーまで確認した。これは当時の表示確認であり、Rustへ移植した後の危険割り込みと実スピーカーの一連の確認を証明するものではない。実再生完了通知は現在のRust配送経路で扱う。
