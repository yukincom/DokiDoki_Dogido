# ドギドの本棚 — 独立アプリと本体データの接続

更新: 2026-10-20

## 使い方と範囲

「ドギドの本棚」は、句集・あんちょこ・フォトブックをまとめた独立したMacアプリ。Minecraft、本体サーバー、LLM、マイクを起動せず閲覧・編集できる。他の本体UIへのリンクは追加しない。

- 句集: 写真と「最初の句」「編集後の句」を並べ、下に対話・発句の材料・プレイヤーメモを表示する。未修正なら「現在の句（修正なし）」。左の一覧は最新の句と従来の日付のまま。チェックした句を左メニューの一つのごみ箱から削除でき、絞込みで見えなくなった句は対象から外れる。「プレイヤーの句」専用欄と作者フィルターは置かないが、既存の句・作者記録は消さない。しおり・個人メモ・写真は「変更を保存」で確定する。星評価はUI・並べ替え・保存契約から撤去。句本文の共同編集は既存の相談機能のまま。
- あんちょこ: 本体と同じカタログを表示。手入力のことばのメモと写真を保存する。**読み訂正は左メニュー最下部**にあり、ポップアップではなく通常ページで管理する。各行は「チェック欄・読み・漢字／表記」の横並びで、読みの五十音順。チェックした複数項目を一つの削除ボタンで削除し、「変更を保存」で確定する。追加日時は表示しない。各項目の「訂正・メモ」には該当する読みと一覧への入口を表示する。
- フォトブック: 既存専用フォルダの管理名PNGと、発句時にMinecraftが自動保存した標準スクショの登録を一覧・選択し、タイトル、各ページ3枠への貼り付け、削除・復元を行う。任意画像の追加UIや既存F2画像の一括取り込みは持たない。
- Mac版フォトブックの「写真の場所をFinderで表示」はMinecraft標準の写真フォルダを開く。画像の移動・コピー・取り込み、保存先変更、未作成フォルダの作成は行わない。通常ブラウザーでは無効。独自gameDirの設定をしても、このボタンはOS標準フォルダへの固定操作のまま。
- 編集は「変更を保存」で確定。未保存の入力を閉じる前に確認し、競合する古い版の保存を拒否する。開いた本棚は3秒ごとに既存 `/api/library` のGETを読み、新しい句・写真へ追従する。未保存変更、入力欄のfocus、dialog、保存中、非表示中は更新せず、取得後にも同じ条件を再検査する。

句の上部には、元の発句記録の `materials_snapshot.preface_spoken`（句のきっかけとなった見どころの発話）を表示する。朗読の合図である `preface` の「ここで一句。」や、発話とは限らない `interpretation` で代用しない。発話記録が無い句には前口上を補わず、元の記録を書き換えない。日付はページに一つだけ表示し、修正ごとの日付欄や作者の見出しを追加しない。

コピー・貼り付けはMac標準の「編集」メニュー・⌘C／⌘V・右クリックを利用する。専用コピーボタンは置かず、句や前口上は通常のテキスト選択でコピーする。

未保存の編集がある間は削除・再読み込みを止め、HTMLの確認画面で先に保存するよう案内する。Macアプリで表示されないJavaScriptのalertには頼らない。複数句の削除は既存の一件単位のごみ箱処理を順に呼び、途中失敗時は完了分だけを一覧から除き、残りのチェックと失敗内容を保持する。

あんちょこの未追加の「ことばのメモ」も項目ごとに保持し、項目・タブ・本を移動しても入力を失わない。「追加」が成功した分だけ入力欄を空にし、未追加分は保存済みメモへ混ぜず、終了・削除時の未保存確認へ含める。ごみ箱の読込結果は、現在表示中の同じ画面だけに反映し、閉じた画面や別の確認画面への古い応答は捨てる。

本体をビルドした上で、次を実行する。

```bash
./dogido-rust/cargo.sh build --release --locked
zsh scripts/build_dogido_library_app.command
```

作成先は `/Applications/ドギドの本棚.app`。通常の「アプリケーション」フォルダから開く。アプリは書類側のプロジェクトを起動元として参照するため、プロジェクトフォルダはその場所に残す。ブラウザー確認用には `zsh scripts/start_dogido_library.command` も使える。Pythonは既存設定の読込だけを担い、保存とHTTP処理はRustの `serve-bookshelf` が所有する。アプリ終了時に止めるのは自身の本棚子プロセスだけ。

各本の表紙にも既存の左メニューを表示する。「句集を開く」等の入口ボタンは置かず、句・項目・写真を左で選ぶと内容へ進む。上部のごみ箱・再読み込みアイコンは置かない。句集は「すべての句」の一覧枠内に削除用のごみ箱アイコンと復元アイコンを並べ、復元は既存のごみ箱一覧を開く。「しおりの句」では両アイコンと削除用チェックを表示せず、選択を解除して削除処理も受け付けない。あんちょこ・フォトブックでも左から復元一覧を開ける。

左の句一覧では、バイオーム・ゲーム内の時間帯・年月日（`YYYY.MM.DD`）の順に横に並べる。この情報行だけを12pxにして、句本文や右ページのタグの大きさは変えない。
チェック欄と句本文の間には、右ページと同じメイン写真の40px正方形サムネイルを置く。一覧幅は広げず、中央トリミングは表示だけで行う。写真切替・貼り替え・取り外しに追従し、写真未登録は空枠にする。元画像や保存形式は変更しない。
「すべての句」の操作欄は、左に削除・復元アイコン、右に条件クリアと句数の上下二段を同じ枠内へ収める。右ページ最上段もバイオーム・時間帯・年月日の順にし、しおりを右詰めする。
デスクトップでは左メニューを展開後と同じ340px幅に固定し、一覧の開閉で右ページを動かさない。狭い画面では既存の縦積み表示を保つ。

左上のブランド画像は `tools/dogido-library/assets/bookshelf-open-scroll-v4.png`。横に開いた巻物を、生成り・濃緑・小さな茶色の軸先だけで簡略化した透過画像で、青い布とリボンは付けない。アプリアイコン本体は変更しない。生成方法と最終プロンプトは同名の `.prompt.txt` に記録する。

## 制作記録と月範囲JSON（2026-10-19）

- 二句の配置は日本語の読む順に合わせ、右に「最初の句」、左に「編集後の句」を置く（2026-10-20）。写真・日付・本文・記録順は変更しない。
- 元句は `haiku_entries.jsonl`、編集後は同じ保存元・同じ句IDの最新revision。元句を上書きせず、本棚用の別記録へ複製しない。
- 対話本文は `short_term/current_session.jsonl` の `dialogue_event / workshop_dialogue` だけを読む。音声再生完了または文字表示ACK後に本体が記録した本文で、音声完了だけを意味しない。`haiku_workshop_turns.jsonl` は同じ保存元・session内の `workshop_id → entry_id` の対応付けにだけ使う。対応が曖昧な記録は推測で結び付けない。同一turnは重複排除し、本文衝突・壊れたJSONL・外部リンクはエラーにする。
- 操作イベント、未発話・取消文は会話表示／出力に混ぜない。修正履歴はJSONに残すが、編集操作の一覧を画面には追加しない。対話未記録を「相談しなかった」と解釈しない。
- 材料は元句の `materials_snapshot` を読む。画面では行ごとの出典・候補材料・発句時の解釈を区別し、欠損を補作しない。JSONには保存済みの材料構造を保持する。
- 左の「JSONを書き出す」で開始月・終了月を指定。元句の `created_at` を日本時間へ変換し、開始月初日00:00以上・終了月の翌月初日00:00未満の句を選ぶ。画面の絞込みは出力条件にせず、後日の修正・対話も出力時点で読めた保存記録に含める。未保存入力があれば先に保存するよう案内する。
- JSONは `schemaVersion=1`、`exportedAt`、`period`、`historyScope`、`deletedPoemsIncluded`、`poems` を持つ。各句は出所付きID、`original / current / revisions / materials / dialogue / recordStatus / player / photos`。写真は3枠のID・ファイル名・タイトル等の参照だけで、画像本体やローカルHTTP URLは含めない。削除句は対象外。不正な発句日時を現在月で補わない。
- `POST /api/poems/export` は同一originと画面トークンを必須にし、保存・削除・期限整理を行わない。Mac版は本棚自身の主フレームからのJSONだけを受け取り（上限32MB）、標準の保存パネルで選んだ場所に書く。Web側から保存先パスを受け取らない。通常ブラウザーはJSONダウンロードを使う。
- 個人メモの新契約は `favorite / note` のみ。旧 `rating` 入力を受け付けず、旧stateを黙って読み替える恒久互換処理も置かない。既存データの評価欄だけを固定ロック内で一度限り除去し、metadata revisionを進める。写真revision、しおり、メモ、削除中のメモ、写真参照は保持する。

モデルの隠れ状態・活性の数値は、上記の材料・解釈とは別の記録である。既存の [MLX採取実験](../dev_tools/haiku_internal_probe/README.md) は合成fixtureの独立再実行で、本体の実プレイ発句には未接続。本体のHTTPクライアントにも数値採取経路は無い。本棚の制作記録追加だけでは数値を採取せず、過去の句へ実験値を流用したり、文章・JSONで数値活性を代用したりしない。

次工程は既存の [GGUF移行方針](https://github.com/yukincom/AI-Curious-Community/blob/main/j-lens-study/docs/2026-10-17-qat-jacobian-optimization.md#gguf系へ移る場合) に沿ったbackend側hookと、発句ID・要求段階・生成token位置・重み／実行実装の識別情報を結ぶ設計。既存NPZ形式と対応検査を再利用候補とし、分離環境で出力一致、MTPの位置対応、速度・メモリ・保存量を検証してから本体へ組み込む。今回、数値採取、新規推論、常駐LLMの変更・再起動は行っていない。

## 正本と保存先

| 内容 | 正本・保存先 |
|---|---|
| カタログ | 本体と共通の既存ローダー。原文JSONは書き換えない |
| 句と直し | 設定の `memory_dir` とその `sessions` 配下の `long_term/haiku_entries.jsonl`、`haiku_revisions.jsonl` |
| 材料 | 元句の `materials_snapshot`（行出典・観測・解釈等） |
| 句の対話 | 同じ保存元の `short_term/current_session.jsonl`。`long_term/haiku_workshop_turns.jsonl` のID対応を利用 |
| 読み訂正 | 設定の `memory_dir/long_term/catalog_corrections.jsonl`。本体の既存カタログ編集と同じ検証・追記・CAS |
| 個人メモ・しおり・写真タイトル・貼り付け | `memory_dir/bookshelf/state.json` |
| 句のごみ箱 | 各正本の `long_term/poem_trash.json` |
| 写真 | ユーザーのPictures配下の「ドギド」。`YYYYMMDD_連番.png` の管理名だけを扱う |
| Minecraft標準スクショ（発句時の自動登録） | MacはユーザーのLibrary配下の `Application Support/minecraft/screenshots`。WindowsはAppData配下の `.minecraft/screenshots`、Linuxはホーム配下の `.minecraft/screenshots` |

Finderボタンは現在の標準構成用。Mac側で保存先を組み立て、本棚自身の主フレーム・起動ポートからの固定操作だけを受け付ける。Web側から任意のパス・URLは受け取らない。フォルダが無ければ案内するだけで、他の保管先へ黙って切り替えない。

### 発句時の自動撮影と参照登録（2026-10-20）

**2026-10-21の身体視点への更新:** 材料を固定して新しい自動川柳を開始した時点で、既存command/result配送へ `capture_screenshot` を追加する。モデル生成・前置き・句の完成・保存を待たず、命令を受けた次の描画frameを共通の `BodyViewCapture` で撮影する。開始から10秒を過ぎた場合は別の景色を撮り直さない。保存無効、revision、preview、テキスト相談室、身体を取得できない場合、非対応adapterでは撮影しない。

`client.screenshot.body_view.v1` の接続だけを対象とし、ドギドの眼の位置・向きから、枠も文字もない原寸PNGを保存する。保存先はゲームディレクトリ配下の標準 `screenshots`、名前は `dogido_YYYY-MM-DD_HH.mm.ss.png`。同名なら `_2` 以降を付けて既存画像を保つ。会話用192px画像とは保存目的を分け、24時間の一時画像整理には含めない。

命令の `poem_id` は元sessionと生成IDから作る予約キー `session:<session_id>:capture:<haiku_job_id>`。adapterはそれを変更せず結果へ返す。Rustは同じ生成処理の正本保存成功後に限り、一度だけ実際の `session:<session_id>:<entry_id>` へ対応付ける。生成中の画像結果は未ACKで待ち、本棚にはまだ登録しない。生成の既存timeoutに加えて120秒まで待て、保存成功後の登録再試行は最大120秒。PNG自体の取得開始は最初の10秒、保存完了は最初の120秒の内側であることを照合する。取消・失敗・保存失敗・重複保存では予約を終了し、次の句や現在表示中の句へ流用しない。既に保存された句は読み上げが取り消されても対応を維持する。先に撮影した後で生成を中止した場合も、Minecraftの原画像は削除しない。

撮影時にはworld、dimension、接続、身体UUID・世代・所有者、期限を再検査し、メニューやチャット画面が開いていれば拒否する。身体・プレイヤーを撮影のために移動せず、描画後は元のcameraへ復帰する。材料観測と撮影は通信を挟むため同一フレームではない。結果の `captured_at` と `capture_view` に撮影時刻・身体・復帰結果を残し、Rustは要求時の身体へ照合する。撮影後のportal移動でも同じsessionの予約にだけ返す。

Rustは固定ルート、`dogido_`付きファイル名、通常ファイル、PNGヘッダー・寸法、最大64MiB、内容hash、対象句の在存と未削除を照合する。画像を移動・複製せず `minecraft-shot_<UUID>` の参照を登録し、対象句の3枠のうち最初の本当の空枠に貼る。満杯なら写真一覧への登録のみ。削除中の参照も空枠とは扱わない。状態→句ロック順で競合を防ぎ、写真revisionだけを進める。永続登録後にACKし、同じ結果の再送で手動剥離・削除を取り消さない。配信時にも同じファイルhandleでhashを再検査する。

標準原本の所有者はMinecraft。本棚での削除・30日後の整理は参照・タイトルだけを消し、原画像は削除しない。既存の本棚管理フォルダの期限整理とは区別する。独自gameDirでは `DOGIDO_MINECRAFT_SCREENSHOTS_DIR` にその `screenshots` を指定すると、本体・本棚が同じ明示ルートを使う。未設定ではOS標準ルートだけを照合し、保存先を推測・自動探索・変更しない。

過去のF2写真は旧日時名のまま閲覧・参照できる。新規の自動撮影を旧capabilityやプレイヤーカメラへ戻す互換処理は設けない。

旧F2経路の調査資料: [Minecraft公式F2案内](https://www.minecraft.net/en-us/article/screenshotting-guide)、[Fabric Yarn 1.21.11 API](https://maven.fabricmc.net/docs/yarn-1.21.11+build.4/net/minecraft/client/util/ScreenshotRecorder.html)。現行adapterと同版のMinecraft JARの呼出し先も読取確認。実Minecraftの自動撮影と開いた実アプリへの連続反映は、実機確認と区別して記録する。

句IDにはroot／sessionの出所を付け、別保管場所で同じIDでも混同しない。句を本棚用の別DBに複製しない。個人メモは会話学習やlessonにしない。旧試作のSQLiteが存在する環境では、空の新保管庫に見せかけず移行が必要な旨で起動を止める。

## 読み訂正と実音声

保存された明示訂正を、通常会話・環境反応・想起とワークショップの音声用本文へ、UniDicより先に反映する。表示文、保存された句本文、確定済み音数は変えない。漢字・英単語・カタカナの長い複合語の一部を短い登録語で置換せず、長い登録語を優先する。

訂正は各発話で読み直すので、保存ごとの本体再起動は不要。ただし本機能を含まない旧バイナリーで既に起動している本体には、一度だけ更新後の再起動が必要。既に合成・取得された音声を遡って変更しない。固定音声素材は対象外。

## 句と写真の30日ごみ箱

- 削除した瞬間から一覧で非表示。句は本体の想起・保存句一覧と直し保存からも除外する。
- 削除日時から **30×24時間未満** は復元できる。重ねて削除しても期限を延長しない。
- 句の復元では直し履歴・しおり・個人メモ・写真参照も戻る。句だけを削除しても写真の元画像は削除しない。
- 写真の削除では各ページでも非表示にする。元画像とタイトルを保持し、復元時に未変更の貼り付け枠へ戻す。別の写真で置き換えた枠は上書きしない。
- 期限以降は復元不可。本棚の起動時と起動中の1時間ごとの整理で、該当句・直し履歴、個人メモ・参照、本棚管理フォルダの写真原本を削除する。Minecraft標準フォルダの原本は削除しない。本棚が閉じている間は物理削除を行わない。
- 期限後も削除IDは保持し、遅れて届いた正本保存の再送で復活させない。他の評価ログやバックアップまで消去する機能ではない。

正本の追記と期限整理は同じ固定ファイルロックで排他し、置換後の古いファイルへの追記を防ぐ。壊れたJSONLを読み飛ばして再保存しない。外部へのsessionリンクと写真リンクを採用しない。写真の元画像が削除時から変わった場合は、誤削除・誤復元を避けて操作を止める。

HTTPはloopbackの専用ポートだけを使い、Host・Origin・画面固有トークンを検証する。静的公開はUI資産の許可リストに限定し、設定・記憶ファイルを直接公開しない。

Fetch Metadataはヘッダー無し・同一origin・直接アクセスだけを許可し、同じlocalhostでも別ポートからのスクリプト読込を拒否する。応答のCross-Origin-Resource-Policyもsame-originとし、句・メモ・読み訂正を別ページへ渡さない。
