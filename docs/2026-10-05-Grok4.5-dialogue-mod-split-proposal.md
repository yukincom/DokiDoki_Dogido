## いまの形（要約）

すでに `*_runtime` 群は分かれている。`mod.rs` に残っている太い塊は **配線の幹**:

| 区間 | おおよそ | 中身 |
|---|---:|---|
| Config / Session / Data / Dialogue | ~65–251 | 所有とロック境界 |
| 観測ヘルパ | ~252–293 | `complete_observation` / `fresh` 等 |
| `observe` / `observe_inner` | ~442–799 | 観測入口（~310 行） |
| `submit*` | ~800–1305 | 入力受理・振り分け（`submit_impl` ~386 行） |
| `update` | ~1335–1683 | 再生／表示結果の反映（~349 行） |
| `run_turn*` | ~1684–1996 | 通常 turn 実行（`run_turn_body` ~280 行） |
| lifecycle | `new`/`register`/`close`/`snapshot`/`shutdown` | 薄い入口 |
| tests | ~2069– | 入口結合テスト |

ドメイン本体は runtime 側。`mod.rs` の問題は **4 本の幹が長い**こと。

---

## 切り分けの型（推奨）

**Session / Data / Dialogue / mutex 順序（jobs → data）は `mod.rs` に残す。**  
ドメイン判断は runtime のまま。移すのは「幹の長い手順」だけ。

```text
mod.rs          … 所有・公開 API・薄い委譲
session.rs      … Session / Data / 観測鮮度ヘルパ（任意・Phase A）
observe.rs      … observe / observe_inner
submit.rs       … submit / submit_inner / submit_recorded / submit_impl
update.rs       … update（再生完了・履歴確定・workshop 行反映）
turn.rs         … run_turn / run_turn_body
```

`impl Dialogue` は親子で共有してよい（同じ `Dialogue` に対する `impl` ブロックを複数ファイルに分ける）。新しい facade 型や `DialogueFacade` は作らない。

## Phase（小さく）

### Phase 0 — やらないこと

- Session フィールドの再設計
- runtime 同士の統合／改名祭り
- 「全部をイベントバス化」
- 判断ロジックの変更

### Phase A — 型とヘルパだけ（任意・低リスク）

`session.rs`（または `state.rs`）へ:

- `Session` / `Data`
- `complete_observation` / `recent_observation` / `observation_fresh` / `fresh` / `empty_event` / `id`

`mod.rs` は `Dialogue` + 公開メソッドの入口だけに近づく。

### Phase B — 幹を4ファイルへ（本命）

優先順（依存が少ない／境界がはっきりしている順）:

1. **`update.rs`** … 入力は turn 結果と playback。出口は履歴・HUD・epoch 照合。独立しやすい  
2. **`observe.rs`** … ゲームイベント → Session 更新。combat/environment/warnings への委譲の列  
3. **`submit.rs`** … 叫声／知識待ち／workshop focus／combat classifier への振り分けの列  
4. **`turn.rs`** … serial 待ち → snapshot → routing → render → `update` へ戻す  

各 Phase は **1 PR = 1 ファイル移動**。挙動・試験変更なし。

### Phase C — テストの同居

`mod.rs` 末尾の結合テストは:

- 入口結合のまま `mod.rs` に残す、または  
- `dialogue/tests_lifecycle.rs` へ移す（`#[cfg(test)]`）

ドメイン別の詳細は既存 runtime 側テストへ寄せる。

## 残すもの / 移すもの

| 残す（`mod.rs`） | 移す |
|---|---|
| `DialogueConfig` / `Dialogue` | `observe_inner` 本体 |
| `pub` API: `new` `register` `close` `observe` `submit` `interrupt` `snapshot` `cancel_all` `shutdown` | `submit_impl` 本体 |
| mutex 順序・serial・jobs・clock の説明 | `update` 本体 |
| runtime への一行委譲 | `run_turn_body` 本体 |
| | （任意）Session / 鮮度ヘルパ |

公開シグネチャは変えない。`server` から見える `Dialogue` の面を壊さない。

## 完了の目安（切り出し後）

- `mod.rs` がおおよそ **入口 + 委譲**（目安 400–700 行台）  
- 幹4本がそれぞれ独立ファイル  
- `cargo test` / 既存模擬 HTTP が緑  
- 新規の `*bridge*` / `*facade*` / 互換ラッパなし

## Codex に渡すなら（最小）

```text
dialogue/mod.rs の切り出し。挙動変更禁止。facade/wrapper 新設禁止。
今回は update 本体だけを dialogue/update.rs の impl Dialogue へ移動せよ。
公開APIと Session/Data の定義場所は維持（または事前合意した session.rs のみ）。
完了条件: コンパイルと既存 dialogue 関連試験が通る。無関係なリネーム禁止。
```

次の PR で `observe` → `submit` → `turn` と同じ型を繰り返す。

## 一言

もう runtime 分割は終わっている。次は **所有（mod）と手順（observe/submit/update/turn）の分離**。  
Session を壊す大きな再設計より、幹4本の機械的移動の方が安全で、AGENTS の意図にも合う。
