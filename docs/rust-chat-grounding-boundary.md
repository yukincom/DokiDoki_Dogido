# Rust 通常会話の対象照合

通常会話の planner が採用した一手を Rust が保持し、同じ turn の現在観測とカタログ候補だけで対象を照合する。`chat_materials::before_plan / after_plan` と `planner::ground`、`fixed_reply` をRust本体の通常会話へ接続する。

Sessionが判断時点の型付き `GameEvent` と会話snapshotを固定し、Rustが現在観測・カタログ候補・planner入力を組み立てる。採用plan、照合結果、本文へ渡す材料の一致と一回のturn内の順序を検査する。カタログを読まないplanには候補を渡せない。プレイヤー報告やassistant履歴は現在観測へ合流しない。

在否確認と過去の誤断言訂正では質問に最も強く一致する候補だけを照合し、関連 Mob の視認で構造物の存在を証明しない。対象不明、未観測、観測済みでもプレイヤーから見えない指摘への返答は既存の固定文を使う。固定文が確定した場合は本文生成を省き、そのまま返す。通常本文へ進む場合も grounding の status・query・候補名・観測名を検査済みの値へ結ぶ。追加のモデル呼び出しはない。

観測の投影、カタログ検索、topic filter、stance、名前の利用範囲、観測の要約、planner入力とfallbackはRustが組み立てる。判断時点のsnapshotがなければ処理を止め、別の観測から作り直さない。通常会話の本人訂正で対象を聞き返す経路は対象照合より先に戻る。

照合状態は一回のRust対話turnに所属し、取消・期限切れ後や別turnへ持ち越さない。実音声完了、履歴確定、session/epochはRust runtimeが所有する。通常会話の対象照合にPython helperは使わない。

**旧Pythonとの実行時比較は終了（2026-10-03）。** 保存済みfixture、Rustのドメインテスト、採用順序・取消の模擬通信試験へ移行した。現行の起動・確認手順は [Rust本体](../dogido-rust/README.md) を参照する。Minecraft、実モデル、実音声による確認は別途必要。

会話workerが待機後に観測を更新するときも、今回入力の直前に確定した会話と戦闘前の退避分を保持する。戦闘後の3回目の応答まで退避分を使い、4回目には期限を延長しない。待機中に完了した発話と沈黙記録は取り込み、今回のplayer入力は履歴欄へ重複させない。通常会話と限定国語対話へ同じ更新済み履歴を渡す。

## 話題の扱い

Rustがraw catalog候補から弱い候補を除外してから現在観測へ照合する。候補表のindexを保持し、出典や名前を失わない。reply stance・方針文・同定候補・固定骨子もRustで選ぶ。モデル呼出は増やさない。

元Pythonとの36,000組のpolicy比較は移植時の記録であり、比較器の運用は終了した。現行は保存済みfixtureを保ち、ネイティブ照合へ渡す前の弱い候補除去と、候補のindex保持をRustで試験する。会話に渡す現在フレーム、カタログ検索、名前の利用範囲や時間付き観測もRust側で作る。
