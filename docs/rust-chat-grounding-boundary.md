# Rust 通常会話の一回生成

更新: 2026-10-07

通常 `player_chat` は、Sessionが固定した現在観測・短期履歴・今回入力を `chat_materials::prepare` でまとめ、話題選択と本文を同じ一回のモデル呼出しで行う。前段の `player_chat_plan`、生成後の内容照合、一度の言い直し、定型の代替発話は本体経路から撤去した。独立CLI用の `planner/` は残るが、通常対話から呼ばない。

共有プロンプトの `dialogue` は目的別に `reply / ambient` を持つ。通常会話は `reply` で今回入力と直前の会話への返事を優先し、環境対話と自発的な反応leafは `ambient` で観測の変化から話しかける。既存の呼出し口が目的を指定し、分類用モデルは追加しない。Base、場面、grounding、出力契約は共通のまま、沈黙も選べる。

観測・一般知識・player報告・過去の発話は別の材料として渡す。対象の名前や辞書描写、現在の音・視線先・所持品、共通環境観測と既存の会話保持期限を維持する。名前・嗅覚・危険助言・方言・日本語かどうか・移動方針との整合を、返答の採否条件にはしない。世界操作・保存・戦況の判断は既存コードが所有する。

編集用の `chat_prompt/data.json` では、今回の優先情報を `priority.return_home / seek_safe_place` に分けて定義する。帰宅予定・発話根拠・移動状況・安全方針は一度だけ持ち、コードが該当する文を順に組み立てる。条件の組み合わせごとの完成文は列挙しない。

`chat_validation::finish` はJSON末尾の閉じ記号、欠けた本文の空文字化、数値本文の文字列化だけをコードで補完する。打切りでも受信済みの本文を使い、続きを生成しない。語句は補作せず、空・文字化け・明らかな反復、補完不能な外形だけを発話なしにする。

不成立の出力・生成通信失敗では読み補正・TTSを起動せず、短期履歴には `role=event, reaction=story` で「難しい話だったので、ドギドは沈黙を選んだ」と残す。壊れた本文や定型の代替発話をassistant履歴へ入れない。モデルが明示的に選んだ `silent` は既存の「黙って受け止めた（発話なし）」を使う。どちらも実再生済みの一往復や川柳材料には数えない。取消・再生失敗・古いepochでは生成失敗の沈黙記録を作らない。

正本知識、現在の匂いへの明示照会などの既存固定経路はモデル呼出し0回。国語対話・川柳workshopから通常雑談へ戻る場合は、その前段処理とは別に通常雑談の一回がある。川柳の生成・検査回数はこの変更の対象外。

通常会話の模擬HTTP試験は `dogido-rust/scripts/check_chat_native.py`。関連Rustテストと模擬LLM/TTS試験で呼出し回数、形式補完、履歴、取消を検証する。実Gemma・Minecraft・マイク・スピーカーでの自然さは別途確認する。
