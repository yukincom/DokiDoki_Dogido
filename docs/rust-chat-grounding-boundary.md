# Rust 通常会話の対象照合

通常会話の planner が採用した一手を Rust が保持し、同じ turn の現在観測とカタログ候補だけで対象を照合する。既存 `planner::ground` と `fixed_reply` を通常会話の bridge へ接続した。

Python の narration は現在観測と候補を閉じた `chat_ground` フレームへ投影する。Rust は plan の完全一致、観測表の型、planner が読んだ先頭 16 行の正規化結果との一致、候補最大 8 件、各 turn 一回の順序を確認する。カタログを読まない plan には候補を渡せない。プレイヤー報告や assistant 履歴は現在観測へ合流しない。

在否確認と過去の誤断言訂正では質問に最も強く一致する候補だけを照合し、関連 Mob の視認で構造物の存在を証明しない。対象不明、未観測、観測済みでもプレイヤーから見えない指摘への返答は既存の固定文を使う。固定文が確定した場合は本文生成を許さず、helper の最終本文も一致を検査する。通常本文へ進む場合も grounding の status・query・候補名・観測名を検査済みの値へ結ぶ。追加のモデル呼び出しはない。

観測表は Python のコードが作る信頼境界であり、Rust がゲームイベント全体から再構築する段階ではない。先頭 16 行以降も従来どおり現在観測として照合に参加するが、モデル prompt には追加しない。カタログ検索、topic filter、stance、名前の白リスト、観測の要約、planner 入力と fallback の構築は Python に残る。Python の planner consumer 検査も互換の確認として残し、採用済み native plan と食い違えば処理を止める。通常会話の本人訂正で対象を聞き返す経路は従来どおり対象照合より先に戻る。

状態は一回の helper 実行に所属する。取消・通信終了・期限切れは既存 turn の取消と helper の回収を使い、別 turn へ照合結果を持ち越さない。実音声完了、履歴確定、session/epoch の所有権は既存 Rust runtime が維持する。

合成入力の Python 比較、採用順序・取消・helper 回収の mock 試験を実施済み。Minecraft、実モデル、実音声による確認は別途必要。

## 話題の扱い

raw catalog候補も同じ一往復で渡し、Rustが弱い候補を除外してから現在観測へ照合する。候補表のindexを返すため、既存の出典や名前を失わない。reply stance・方針文・同定候補・固定骨子もRustで選ぶ。Pythonの通常経路は既存動作を保ち、移行bridgeだけこの取得口を使う。モデル呼出は増やさない。

元Pythonとの36,000組のpolicy比較に加え、ネイティブ照合へ渡す前の弱い候補除去と、候補のindex保持を試験する。会話に渡す現在フレーム、カタログ検索、名前の利用範囲や時間付き観測の作成は残る。
