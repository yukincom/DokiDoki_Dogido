## 現在の動作

| 場面 | 動作 |
|---|---|
| 安全なFOLLOW待機 | 前回の選択開始から30秒以上空け、現在見えている対象から会話モデルがinspect／stayを選ぶ。既見の種類だけでも再選択できる |
| 接近先に実到着 | 身体の到着tickから8〜12秒、その場と向きを保つ。浮遊の上下動は継続 |
| 通常待機・到着後の間の終了 | 5〜9秒の間を挟み、45〜100度先へゆっくり見回す。最大1.25度/tick（通常20tick/秒） |
| 見回しで新しいものが見えた | 実際の身体yawと既存の視野・遮蔽判定で候補を更新し、向きを止めた時に次を選ぶ |
| 同じ対象への再訪 | 確認済みの到着通知を受理してから120秒間、その対象だけを候補から外す。同種の別個体・別ブロックは残す |
| 距離追従・呼び寄せ・危険回避・停止 | 到着後の間と見回しを中断して既存の優先動作へ進む |

到着後の8〜12秒が終わったら最初の見回しを開始する。通常待機へ入った時と、各見回しを終えた後の間は5〜9秒。見回しは位置を変更せず、プレイヤーのカメラ旋回にも連動しない。

## 既存の接続を使う

- `body_interest`のモデル・プロンプト・inspect／stay出力は維持。種類の既見は`newly_seen_type`の参考情報として残し、打ち切り条件から外す。
- 対象の短いモデルIDは、再訪待ち対象を除いた候補表から採番する。元の対象IDとの対応を同じ不変候補表で検証する。
- 到着は既存`inspect_body_target`の命令ID・身体世代・期限と一致した`succeeded / arrived`通知だけ。受付・生成・移動開始・失敗を訪問済みにしない。
- 同じイベントの身体更新・休止・入力による取消を先に反映し、その後に到着通知を照合する。重複イベントで届いた正常な結果は一度だけ受理し、重複通知で120秒を延長しない。
- 到着後の間は身体のサーバーtickで管理する。Rustは`holding / inspection_dwell`を見て新しい選択を保留し、遅れて届いた通知から待機時間を重ねない。
- 見回し中は`holding / follow_lookaround`。到着後の間・見回し中には新規選択を開始せず、遅れて返った選択も実行しない。身体側でも観察MOVE_TOの受付時に再確認する。
- 訪問記録は接続内の最大64件。取消・一時的な観測不能では保持し、身体世代の変更で消す。長期記憶へ保存しない。
- Body APIはv6、`body_observation`はv3、`body_autonomy`はv1のまま。0.7.0と0.7.1のAPIクラス36個はバイト単位で一致。HTTP窓口や操作の種類を増やしていない。

## 実機確認

身体Modは`cube-dogido-lab-0.7.2.jar`へ差し替え済み。Minecraftを起動して確認する。旧版は復元用に退避済みで、mods内に新版だけがある。adapterは配置済みの同一API v6対応版を使う。0.7.2の自然消滅対策ではRust本体とadapterのコード変更・再ビルドは不要で、配置済み0.7.1とのAPIクラス36個もバイト単位で一致している。

1. 持ち主登録済みの身体に対してMinecraftのチャット欄から`/dogidobody follow`を実行し、「身体操作: follow」の表示を確認する。複数の対象がある場所でプレイヤーを静止させる。再読み込み後は身体操作が未指示状態に戻るため、同コマンドで開始する。
2. 接近先への到着後に間が入り、その後ゆっくり向きを変えることを確認する。
3. 見回して得た現在候補から次の対象が選ばれることを確認する。モデルのstayは許可されているため、毎回の移動を必須にはしない。
4. 同じ対象への即時再接近が続かず、同種の別対象は選べることを確認する。
5. 待機中にプレイヤーが追従範囲を離れた時の距離追従、危険回避、`/dogidobody direct`による停止を確認する。

自動検査は移動の見た目・実ゲームの通信・実モデルの選び方を保証しない。実機では特に見回しの速さ、間の長さ、対象の選択頻度を評価する。

### 実機で見つかった自然消滅設定の修正（0.7.2）

- 0.7.1の再起動後、`follow`が通常会話へ送られ、身体操作は実行されていなかった。その後、身体が消えたとの報告と`NOT_BOUND / bind_existing_body`を確認。保存済み所有台帳も空だった。単なる未ロードなら`UNLOADED`になるため、未ロードだけでは説明できない。ただし除去理由そのもののログはなく、今回の個体が自然消滅したという直接記録はない。
- 原因候補として、コンストラクターの`setPersistent()`がMinecraftの`MobEntity.readCustomData()`に上書きされる不具合を確認した。通常の召喚データには`PersistenceRequired`がなく、親の読み込みではfalseになる。0.7.2は親の読み込み後に永続化設定を確定し、旧データでfalseだった身体にも適用する。
- 実際のMinecraftのNBT読み込みを使う3件の回帰テストを追加。修正前はタグ欠落・falseの2件が失敗し、修正後は欠落・false・trueの3件すべて成功。worldのtick、距離による実消滅、ワープの実行試験とは区別する。
- 再召喚後、12:10:03に持ち主登録、12:10:19に`身体操作: follow`、12:10:55にポピーを対象とした`inspect_body_target`の`succeeded / arrived`を確認した。続く馬への接近選択は`inspection_target_unsafe`で拒否されており、到着済みとはしない。
- ユーザーの「声で呼んでも隣まで来ない」という報告は別項目の呼び寄せ問題。12:10:57の発話は動物呼び戻しへ流れ、馬が呼ばれた。12:12:44の「もっと近くにおいで」も通常会話の返事だけだった。通常FOLLOWの16/14ブロックという距離設定を、この声の呼び寄せ問題への対処として変更していない。
