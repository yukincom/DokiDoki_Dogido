# Rust移行後レビューの照合と修正

2026-10-03付のClaude Sonnet 5.5レビューを、書類側のRust本体と照合した記録。レビュー原文は当時の観測として保持し、以下を現行の対応状況とする。

## 対応

| 指摘 | 対応 |
|---|---|
| H1 未コミット | 本体・Fabric、ラボ、家庭用配布、文書を `4acc04d` / `47e1c64` / `7431961` / `0452fdd` に保存済み |
| H2 設定が届かない | HTTPのbatch・body・heartbeat・schema設定をRustへ接続。消費先のない旧設定17個を撤去し、残っている環境設定は名前だけを通知する |
| M1 古い表示 | 本体の接続済み機能を表示。画面をRustへ移し、旧HTMLへの6か所の無言の置換を廃止。状態表示は専用挿入位置を検査する。API phaseも `dialogue` へ揃えた |
| M2 Clippy | 条件式・ループ・不要な更新記法を修正。モブ観測の引数を名前付きの一組へ整理 |

## レビューと実装の食い違い

`voice_vad_cli` は `dogido_server/voice_settings.py` に直接参照がある。`resolve_vad_paths()` → 音声起動JSONの `vad.cli` → Rust `voice/stt.rs` の実行指定という経路で使う。動的参照で検索しにくい項目ではない。レビューは `--voice` の確認未実施を明記しているが、「どこからも参照されない」とする判断は参照コードと矛盾する。検索操作・結果集約の記録がないため、具体的な見落とし原因は確定できない。明示した `.env` のVAD実行ファイルがRustへ届く境界テストを追加した。

レビューの「三重管理」の三番目だった `combat/model.rs` はJSONを読む処理であり、独立した値の定義ではなかった。ただしPythonとJSONの二重定義、およびJSON内の重複は実在した。さらに別の `threats.rs` にも一部の値の再定義があったため、数え方の訂正だけにとどめず、定義と読込口を統合した。型の宣言・環境変数の解釈・上書き値の検証は各言語の境界に残す。

`allow_non_local_bind=true` 単独で起動が失敗するわけではなく、非loopback待受の指定をRustが拒否していた。現在はPython起動側でも同じ境界を明示する。`/dogido` の「Python環境」はレビュー時点でも置換済みだったが、置換前HTMLだけを読むと古く見える構造だったため、画面資産自体を現行表示へ揃えた。

旧Python構成を含むGrokのレビューは当時の記録であり、削除済みの本体や比較器を復元する指示として使わない。現在の消費先と、終了・履歴の文書を分けて照合する。

## 検証範囲

- Rust: `cargo test --offline --locked --all-targets` は576件成功（unit 455件・integration 121件）。`cargo clippy --offline --locked --all-targets -- -D warnings` も成功。
- Python: 現行補助・起動・家庭用配布・ラボの試験は224件成功、6件skip、24 subtests成功。実SSHを使う `tests/test_family_link_integration.py` は今回の対象外。
- ビルド: debug / releaseの本体・examplesをビルド済み。
- 模擬HTTP: 設定伝達・batch/body制限・LLM/音声無効時・川柳音声設定の4ケースが成功。環境・戦闘・会話再開等の28ケースも成功し、起動した試験用プロセスはすべて停止済み。
- 起動の事前確認: 通常本体と `--voice --check` が成功。音声入力・実モデル・常駐サービスは起動していない。
- 配布資産: Python wheelを作成し、共有JSONの同梱と廃止ファイルの非同梱を確認。RustソースのないPythonパッケージ構成でも設定を読み込める。

環境の模擬試験には、雷の実再生完了によるassistant履歴を認めない古い期待値が残っていた。現行の共有履歴仕様に合わせ、取消済み会話が残らないこと、再開会話が一度だけ入ること、追加の雷履歴が実再生完了IDと一致することを検査する形へ修正した。本体の履歴仕様は変更していない。

実Minecraft・実マイク・実LLM/TTS・家庭用Macでの動作は今回未確認。既存 `.env` の廃止設定は通知にとどめ、書き換えていない。
