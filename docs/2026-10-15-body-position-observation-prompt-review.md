# 2026-10-15 位置関係を現在観測と変化リストへ渡す案

状態: **ユーザー承認済み。この文面を本体へ反映済み。検証結果は[実装記録](2026-10-15-body-position-observation.md)を参照。**

## 確認したコードと変更範囲

SugarScapeの `observations.py` の `_spatial_fields` / `identified_observation` は、コードで方向・距離を算出し、観測者と対象を明記する。`main.py` の `build_prompt` は判断ごとに現在観測を入力へ入れる。差分だけを渡す方式ではない。SSは世界の8方位、ドギドは各本人の向きに対する前後左右なので、ドギド既存の `body::position::calculate` を使う。

ドギドの既存 `conversation_observation::State` は、使ったrevisionまでの変化を考慮済みにして次の入力から外す。初回や静止したままの再質問にも答えられるよう、最新の一組を現在観測へ置く。

- 受理済みの同じsampleからコードで計算し、`body_observation.current.position_relation` へ最新の両視点・上下・距離を渡す。
- 計算結果が変わったら、既存 `changes` に `body_position_relation` を一件載せる。種類ごとの最新一件・判断したrevisionだけ消費する仕組みを再利用する。
- 初回は現在値だけ。失効・一時停止・次元／身体世代の変更では過去値を現在値へ流用しない。
- 生座標やyawはモデルへ渡さない。視認と位置の区別は維持する。
- 通常の位置回答は一回の会話生成で返す。位置toolによる照会と結果専用の追加生成を外し、既存の馬呼び寄せは維持する。
- 生成開始時点の新鮮な観測を固定する。返答中の移動まで同じ位置であるとは保証しない。位置tool専用だった配送検査を通常の雑談すべてへ広げて、歩行中の返事を止める実装にはしない。

変更する指示文は `body_observation` と、共通tool出力指示から位置照会の段落を除いた `chat_tools`。結果専用の `body_position_reply` は使わなくなる。以下は通常モード・匂いの観測ありのsystem全文。匂いの観測がないときは匂いの一段落を省く。プレイヤーの呼び名は既存の置換を維持する。
