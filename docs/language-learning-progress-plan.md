# 国語学習の説明保留・学習記録計画

**状態:** 設計案。未実装・既定無効。  
**対象:** 子どもを含む学習者へ、国語知識を短く区切って説明する場合。  
**前提:** 人物別の体験プロファイルと削除・閲覧境界を統合するまで、長期記録は有効化しない。

## 目的

長い説明を一度に読み上げず、短い意味単位ごとに止まり、学習者の反応に応じて続行・再説明・終了を選べるようにする。

また、「何を話したか」と「本人がどう受け止めたか」を混同せず、学習指導要領との対応を確認できるチェックリストを作る。

## 二種類の状態を分ける

| 状態 | 保存場所 | 役割 | 再起動後 |
|---|---|---|---|
| 説明保留状態 | 現在のセッション | 次に話す説明部分、脱線、危険中断、再開確認 | 破棄する |
| 学習記録 | 人物別の追記型JSONL | 説明済み範囲、本人の自己申告、閉じた確認、人による訂正 | 明示設定時だけ保持 |

未処理のプレイヤー入力を入れる `pending_player_text` へ、説明の続きは混ぜない。前者は「まだ処理していない発話」、後者は「処理済み回答の残り」であり、意味が異なる。

## 説明保留状態

初版では、一つのセッションにつき一件だけ保持する。説明を入れ子にしない。

```json
{
  "schema_version": "knowledge_continuation.v1",
  "continuation_id": "continuation_...",
  "domain": "japanese_language",
  "subject": "枕詞",
  "intent": "definition",
  "plan_version": "makurakotoba.v1",
  "segments": [
    {
      "segment_id": "makurakotoba.v1.definition",
      "ordinal": 1,
      "text_ja": "人が確認した短い説明文",
      "record_ids": ["knowledge.rhetoric.makurakotoba"],
      "source_ids": ["src.mext...."],
      "objective_ids": ["objective.makurakotoba.definition"]
    }
  ],
  "next_segment_index": 1,
  "status": "awaiting_response",
  "pause_reason": null,
  "off_topic_turns": 0,
  "created_at": "...",
  "last_relevant_at": "...",
  "hard_expires_at": "..."
}
```

`segment_id` は説明上の意味単位であり、TTSの都合による文分割とは別にする。同じ意味単位を二つの音声へ分けても、学習記録では同じ `segment_id` を使う。

### 状態名

| コード上の値 | 表示する日本語 |
|---|---|
| `active` | 説明中 |
| `awaiting_response` | 返答待ち |
| `paused_off_topic` | 脱線により保留 |
| `paused_danger` | 危険により保留 |
| `awaiting_resume` | 再開確認待ち |
| `completed` | 説明終了 |
| `abandoned` | 説明打切り |
| `expired` | 保留期限切れ |

### 初期の期限と脱線規則

- 関連する返答がない状態で120秒経過したら、短期保留を期限切れにする。
- 一回の説明は、実際に進めていた時間を合計240秒までとする。
- 危険中断を含む絶対上限は15分とする。
- 無関係な入力が一回あれば「脱線により保留」とする。
- 無関係な入力が続けて二回あれば、短期保留を打ち切る。
- 安全に戻っても、残りを自動再生しない。「さっきの枕詞の続き、戻る？」と一度だけ尋ね、明示的な肯定後に再開する。
- 別の知識質問へ長い説明を始める場合は、以前の説明を置き換える前に固定文で確認する。

数値は実機観察前の初期値であり、設定として調整できるようにする。

## 学習指導要領対応チェックリスト

学習指導要領の全項目を、そのまま自動的にチェック項目へ変換しない。広い目標や見出しも含まれるため、知識項目との対応は人が確認した小さな対応表にする。

| 対応区分 | 意味 |
|---|---|
| 直接対応 | 出典資料上、対象項目との対応を直接確認できる |
| 編集上の対応付け | ドギド側で学習上の関連を整理した。文部科学省による教材認定を意味しない |

チェックリストで使う表示は、次に限定する。

- 未記録
- 説明途中
- 説明済み
- 本人が「わかった」と回答
- もう一度確認したい
- 閉じた確認で一度一致
- 人が確認

「習得済み」「学年相当」「能力点」は初版では使わない。説明を読み上げるアクションを選んだだけでは、「説明済み」にもしない。実際の再生完了通知が導入されるまでは、配送決定と実再生を別に記録する。

## 学習記録の正本

現在値を上書きする一枚の人物表ではなく、訂正可能な追記ログを正本とする。

```text
.dogido_memory/
  players/{opaque_profile_id}/
    learning/
      evidence.jsonl
      progress.json
```

`progress.json` は `evidence.jsonl` から再生成できる表示用キャッシュとする。

```json
{
  "schema_version": "learning_evidence.v1",
  "evidence_id": "evidence_...",
  "profile_id": "local-profile-id",
  "objective_id": "objective.makurakotoba.definition",
  "plan_version": "makurakotoba.v1",
  "segment_ids": ["makurakotoba.v1.definition"],
  "record_ids": ["knowledge.rhetoric.makurakotoba"],
  "source_ids": ["src.mext...."],
  "dataset_hashes": ["sha256:..."],
  "evidence_kind": "self_report",
  "outcome": "understood",
  "observed_at": "...",
  "rule_version": "learning-progress.v1",
  "supersedes_evidence_id": null
}
```

### 根拠の扱い

| 反応 | 記録 |
|---|---|
| 「続けて」 | 続行希望。理解の根拠にはしない |
| 「わかった」 | 本人の自己申告として記録する |
| 「分からない」「簡単に」 | 再確認希望として記録する |
| 固定選択肢への一致 | 閉じた確認で一度一致した事実として記録する |
| 自由回答 | 初版では自動採点しない |
| 人による訂正 | 元の行を消さず、`supersedes_evidence_id` で訂正する |

## 個人情報と誤判定を避ける境界

- 長期学習記録は既定無効とする。
- 体験プロファイルはプロセス設定だけで選び、発話やモデル出力から切り替えない。
- 名前、年齢、学年、学校名、生音声、書き起こし全文、自由回答全文を学習記録へ保存しない。
- 声色、返答速度、感情、知能、能力を推定しない。
- Minecraftの座標、体力、戦闘履歴を学習記録へ混ぜない。
- 学習記録をLLMの常時few-shot、訓練、支援操作、危険判定へ使わない。
- 人物ごとの閲覧、訂正、JSON出力、完全削除を、永続化の有効化より先に実装する。
- 音声認識の確信度が低い場合は記録せず、聞き返す。

## 実装順

1. 人物別の体験プロファイル、閲覧、削除、既定無効の境界を統合する。
2. 長期保存を行わず、セッション内の説明保留状態だけを実装する。
3. 人が確認した二、三項目だけに、短い説明計画と再開確認を付けて実聴する。
4. 学習指導要領との対応表を人が確認し、直接対応と編集上の対応付けを分ける。
5. 人物別の追記型学習記録と、決定的に再生成できるチェックリストを実装する。
6. 本人の自己申告と閉じた確認を追加する。自由回答の自動採点は行わない。

## 最低限の試験

- 危険中は説明位置、確認結果、学習記録を動かさない。
- 安全化後に自動再生せず、再開確認を一度だけ行う。
- 脱線一回、脱線二回、明示終了、期限切れ、別質問への置換を区別する。
- 出典データのハッシュが変わった古い説明は再開しない。
- 「続けて」を理解扱いせず、「わかった」は自己申告以上に扱わない。
- 配送決定だけで「説明済み」を記録しない。
- 重複イベントで学習記録を二重追記しない。
- 人物間で記録が混ざらず、名前や発話全文がJSONLへ入らない。
- 人による訂正後も元の根拠を追跡できる。
