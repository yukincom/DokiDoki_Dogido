## Codex への一言

三機から連続で殴られるのはきつい。それでも今回の差分は、**抽象リファクタではなく指摘への応答**になっている。

特に効いていたのは次の型の直し方だった。

- 名前が嘘だったものを、責務どおりの名前へ移した（`haiku_bridge` → `python_worker`）
- 散らばっていた Python 形フォーマットを、互換ラッパ増産ではなく `text_format` に集約した
- 試験を「期待値を緩めて通す」ではなく、模擬・待ち・辞書条件を現行方針に揃えた
- 空パッケージ／化石コメント／称賛即終了の文書まで同時に触った

まだ残る指摘はある。ただ「逃げのラッパで誤魔化した」印象は薄い。この調子なら、次は範囲を切った具体指示に一本ずつ答えればよい。

## まだ残る指摘

### 1. high — `speech_choice::parse` に fence strip が無い

**証拠:** `dogido-rust/src/speech_choice.rs` は `serde_json::from_str(raw.trim())` のみ。  
`strip_code_fence` は `haiku_response.rs` 内に閉じたまま。  
呼出: `reaction_leaf` / `environment/reaction` / `chat_validation`。

プロンプト側で禁止しても、モデルが囲むと反応・雑談がまとめて `invalid_contract` → fallback になる。初回から一貫して残っている実行時リスク。

**修正方針:**

1. `strip_code_fence` を `text_format`（または小さな共有モジュール）へ移す  
2. `speech_choice::parse` の先頭で適用  
3. \`\`\`json 付き／閉じ無しの回帰を `speech_choice` に追加  
4. 呼出側で二重 strip しない  

### 2. med — `workshop_helper.py` がまだ相談エンジンに見える

**証拠:** 中身は `tts_tokens` → `tts_shared_tokens.handle` のみ。コメントも「相談の判断はしない」。  
それでもファイル名が `workshop_helper`。家庭用キットや試験がこの名前に依存している。

**修正方針:**

- `tts_tokens_worker.py` 等へ改名  
- 起動・family 配布・README・試験の必須一覧を同じ変更で更新  
- 相談ロジックを Python に戻さない  

### 3. med — `is_python_whitespace` / `py_regex` が現行仕様なのに Python 名

**証拠:** `compat.rs` は「現在の仕様」と書きつつ関数名は Python。多数が `as space` で import。  
エージェントが「互換レイヤだから残す／増やす」と判断しやすい。

**修正方針:**

- `dogido_whitespace` / `guard_regex` 等へ改名（挙動不変）  
- モジュール名 `compat` も将来 `text_rules` 等へ。今回は関数名だけでも可  
- コメントの「Python」は歴史一行に限定  

### 4. med — 戦闘5分類の action 集合が二言語で二重定義

**証拠:** `dogido_server/combat_input_contract.py` の `ACTIONS` と Rust `workshop_combat_input::Action`。  
外形 vs 語義の分担コメントは良い。列挙追加時の取り違え余地は残る。

**修正方針:**

- 正本を Rust enum（または共有 JSON 契約）に一本化  
- Python は生成物／固定リスト参照に落とす  
- 契約変更は helper 試験と `Analysis::parse` を同じ PR で  

### 5. med — workshop 周辺の名前が四系統

**証拠:** `workshop_edit`（CAS）/ `workshop_editing`（エンジン）/ `dialogue/workshop_edits`（保存接続）/ `check_workshop_edits.py`。  
コメントで分担は説明済み。初見コストは高い。

**修正方針:**

- いま大規模移動は不要  
- `AGENTS.md` か workshop 文書に一行対応表を固定し、新規別名を増やさない  
- 改名するなら `workshop_cas` / `workshop_engine` / `workshop_apply` へ一括  

### 6. med — `dialogue/mod.rs` の肥大

**証拠:** 依然として巨大な配線ファイル。`AGENTS.md` も集積禁止を書いている。

**修正方針:**

- 新規ドメインを `mod.rs` に足さない  
- 既存 `*_runtime` への切り出しを続ける  
- 入口一覧だけ残す  

### 7. low — 回帰試験名の `*_match_python*`

fixture 出典名としては分かるが、関数名だけ見ると旧本体再起動に読める。

**修正方針:** 触るファイルから `matches_fixture` / `matches_canonical_contract` へ順次リネーム。挙動不変。

### 8. low — alignment メモが「未着手」のまま読める

`docs/2026-10-04-Grok4.5-workshop-test-alignment.md` は方針メモ時点の文面のまま。スクリプトは既に追従済み。

**修正方針:** 冒頭に「スクリプト側は対応済み。本ファイルは難点分析の履歴」と、本 third-pass へのリンクを足す。

### 9. low — listen 既定 5055 vs 起動スクリプト 5056

意図的並走ならよい。文書で「CLI 既定」と「推奨入口」を一文で固定しないと、また取り違えが起きる。

**修正方針:** README / `start_dialogue.command` コメント / `main.rs` 既定の主従を一文で揃える。自動でポートを黙って変えない方針は維持してよい。
