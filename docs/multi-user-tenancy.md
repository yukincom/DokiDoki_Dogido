## 0. スコープの外（明示）

**同時に複数人がドギドと会話する**ことは想定しない。

- 利用イメージはマイクラ **一人用**（または交代で一人が遊ぶ）
- 1 サーバーに複数プレイヤーが同時接続して並列に相棒会話、は **やらない**
- この文書の「複数ユーザー」は **時間をずらした世帯利用**（親のあと子、など）と **プロファイル切替**

---

## 1. いまの前提（事実）

現行はおおむね **単一プレイヤー・単一メモリ空間**。

| 領域 | 現状のイメージ |
|---|---|
| 記憶ディレクトリ | `.dogido_memory/` が **1 本** |
| 川柳 entries / revisions / lessons | グローバル JSONL に追記 |
| player_profile | **1 ファイル**（`player_profile.json`） |
| 呼び名 | `meta.call_name` → なければ `DOGIDO_DEFAULT_CALL_NAME` |
| セッション | アダプタ session はあるが、記憶の **論理ユーザー境界は弱い** |
| 名前音声（検討中） | call_name ごとのキャッシュが自然（複数キー） |

家庭で **交代プレイ**（親→子）や、呼び名・好みの違う人を切り替えると、  
**「誰の句か・誰への lesson か・誰を呼ぶか」** が分離していないと混線する。

---

## 2. 困る例（交代利用）

- 兄の日の workshop lesson が、翌日の弟の句に効く  
- 川柳一覧が世帯全員で混ざる  
- うしろコールで **別の人の名前** が鳴る  
- profile の進捗・好みが上書きされる  

---

## 3. 方針の方向性（未確定・議論用）

効くのは **論理ユーザー（player identity）境界**（同時接続の多重化ではない）。

### 3.1 境界の切り方（候補）

| 案 | 概要 | 向く | 注意 |
|---|---|---|---|
| **A. ワールドで分ける** | ワールド（またはセーブ）ごとに記憶ディレクトリ／namespace | ワールド＝旅の記録を分けたい | 同じ人が別ワールドでも履歴が切れる。ワールド名の安定キーが要る |
| **B. アカウント ID** | マイクロソフト／Minecraft のプレイヤー UUID 等をアダプタから受け identity にする | ログインが一意で自動化しやすい | 家族共用 PC で同じ MS アカウントのことも。オフライン／LAN 名だけだと弱い |
| **C. 明示プロファイル + 切替発話** | Config UI で「人物」を新規登録（呼び名・好み）。音声／テキストで「いまは XX がプレイしています」で **active profile を切替** | 世帯交代・子ども用の呼び名・lesson 分離に素直 | 切替忘れで混線。登録 UI と認識フレーズが要る |
| **D. 組み合わせ** | 例: プロファイルが本、UUID はヒント、ワールドは句のタグ | 実運用に近い | 設計が厚くなる。段階導入が必要 |

**いまの感触（案）:** 同時マルチは不要なので、

1. **人物プロファイル（C）を本**にする（誰の相棒か）  
2. アダプタから取れる **UUID／プレイヤー名（B）は自動推定・紐づけ**に使う  
3. **ワールド（A）は identity ではなく、句・記憶の「旅のタグ／フィルタ」**に寄せる  

ワールド＝人物、にすると「同じ子が別ワールド」で句が分断されやすい。  
人物＝プロファイル、ワールド＝その人の中の章、の方が川柳・lesson に合うことが多い。

### 3.2 切替 UX（C を本にする場合）

```text
Config UI
  - プロファイル一覧（表示名 / 呼び名 call_name）
  - 新規登録・編集・削除
  - 既定プロファイル

プレイ中
  - 音声 or player-input:
      「いまはメルがプレイしています」
      「プレイヤー切替: たろう」
  - 成功したら active profile を変更し、
    以降の haiku / lesson / 呼び名 / 名前音声キーがそこに載る
  - 切替確認の一言（任意）: 「おけ、今日はメルやな」
```

登録と切替を分ける: **新規は UI**、**日常の交代は短い発話**。

### 3.3 記憶レイアウト（イメージ）

```text
.dogido_memory/
  players/
    {profile_id}/
      long_term/   # haiku, lessons, profile
      short_term/
  active_profile.json   # いま誰か（切替で更新）
```

音声名前キャッシュも `{profile_id}` または `call_name` キーで揃える（[voice-delivery-plan.md](voice-delivery-plan.md)）。

---

## 4. 段階（案）

| Phase | 内容 |
|---|---|
| **0 現状** | 単一空間を明示（このメモ） |
| **1 境界の定義** | プロファイル本 + UUID ヒント + ワールドはタグ、を決める |
| **2 記憶の分割** | haiku / lesson / profile を profile_id 単位に |
| **3 切替 UX** | Config UI 登録 + 「いまは XX」発話ルーティング |
| **4 呼び名・音声** | 名前断片キャッシュを profile / call_name 単位に |

完成度の本丸（観測 materials）より **後でよい**が、  
世帯で交代利用が現実になったら **Phase 1–3 を前倒し**。

---

## 5. やらないこと（当面）

- **同時マルチ会話・同時マルチセッション相棒**  
- クラウドアカウント必須の多人数 SaaS 化  
- 記憶を全部 LLM コンテキストに載せて「賢く分離」  
- 無関係リファクタとの混ぜ込み
