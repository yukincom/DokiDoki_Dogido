# 要求時の位置確認

2026-10-14。状態: **旧方式。実Minecraft・実モデル試験では位置質問5回中4回で照会を省き、不合格。** [試験記録](2026-10-14-body-position-live-test.md)。2026-10-15に[現在観測と変化リストへ渡す方式](2026-10-15-body-position-observation.md)へ置換。以下は旧方式の実装記録。

通常会話から要求されたときだけ、コードで両者の位置関係を計算する。指示文は[全文確認用](2026-10-14-body-position-prompt-review.md)をユーザー確認済み。

## 会話の流れ

1. 通常会話の生成に読取り用の `get_body_position` を公開する。プレイヤーに位置関係を聞かれた場合、またはモデルが返答のために必要と判断した場合だけ呼ぶ。語句による位置分類器は置かない。
2. 呼出しを受理した瞬間に、現在のSessionから `body_observation.accepted(now)` を読み直す。生成開始時に固定した観測は使わない。
3. 同じsampleのドギド・プレイヤーの足元座標と各yawから、双方から見た8方向・上下・直線距離を計算する。
4. もう一度だけ返答を生成する。入力は今回の問いと計算結果だけ。生座標、角度、計算式、途中の値、以前の位置回答を含む履歴は渡さない。
5. 表示待ち列へ積む直前と各文の音声再生直前に、現在の受理済み観測で身体世代と結果の一致を確かめる。表示前の失効は位置を述べない案内に変更。音声合成中の失効は古い音声の起動を拒否し、追加生成はしない。

位置照会なしの通常会話は生成一回。位置照会ありは最大二回。連続tool呼出し・自動再試行・世界操作はない。新しいHTTP/API経路やMinecraftの座標フィールドも増やさない。

## 鮮度と取得範囲

ここでの「最新」は**要求時にRustが最後に受理している、3秒未満の観測**。Minecraftへ要求後の再採取を命じる方式ではない。既存の身体側取得・adapter送信を使い、owner・dimension・身体世代・server tick・revision・eventの通信経過時間の検証も維持する。同じ観測の再配送で寿命を延長しない。

同じサーバー観測の `self_pose` と `player_pose` を使う。別時点のtop-level player座標は混ぜない。視認や感覚が未取得でも、有効な姿勢があれば照会可能。位置取得は視認の証拠ではなく、視認範囲16ブロックを位置計算の制限として使わない。身体未取得・失効・一時停止では `unavailable` を返し、ゼロ座標や過去値で穴埋めしない。

返答中も観測の更新が続き、計算結果が同じなら、照会から3秒以上経っただけでは破棄しない。配送時点の新鮮な観測で照合する。再生後の移動まで将来の位置を保証するものではない。

## 計算結果

```json
{
  "position_status": "available",
  "relative_positions": [
    {"observer":"dogido","target":"player","horizontal":"front","vertical":"same"},
    {"observer":"player","target":"dogido","horizontal":"right","vertical":"same"}
  ],
  "distance_blocks": 4.0
}
```

- 方向は各本人のyawを基準に45度ずつの8区分。境界は正面から右回りに22.5度を加えて切り捨てる。同じ水平位置には前後左右を割り当てない。
- 上下は足元Yの大小。距離は足元間の3次元直線距離を小数第一位へ丸める。
- ドギドの視線yaw/pitch、プレイヤーpitchを地面基準の前後左右へ混ぜない。
- 未取得は `position_status: unavailable`, `relative_positions: []`, `distance_blocks: null`。

座標変換は既存の評価用 `body::evaluation::relation` から共有の `body::geometry` へ移した。評価側はその再公開を使い、同じ変換を二重実装しない。結果の8方向化は `body::position` が行う。

## 通常観測と既存機能

内部の生姿勢、前回値、差分台帳は維持する。モデルへ渡すContextのコピーだけを `for_model` で投影し、身体欄には視認・感覚の状態を残す。位置・向きの4種類のchangesは数値を除いて「変化あり」にする。視認のstatus/reasonは残す。通常返答・環境反応・周期通知・興味対象の選択で共通に使う。

今回のtool入口は通常会話。川柳相談・知識回答・環境の自発発話・興味選択には位置確認の追加生成を設けていない。これらにも生姿勢は渡さない。

乗れる動物の呼び戻しは通常会話の最初のtool選択を共有し、その後は既存の本人依頼検証・候補選択・現在状態照合・実行queueを使う。戦闘支援の馬専用入口は維持する。位置確認は実行capabilityを必要としない。

診断行に `body_position_requested / body_position_status / body_position_input` を記録する。計算結果を通常world_contextへ保存せず、次の位置確認では再取得する。本文JSONからtoolを推測実行せず、完全なnative呼出し一件・空引数だけを受け付ける。

位置の幾何検査は、前回の比較に使った取得可能な17ケースを3種類の平行移動で照合。8方向の境界付近・同じ水平位置・上下・視線yawとの分離も確認した。mockでは、最初の生成中に新しい位置が届いた場合の読み直し、結果のみの二回目、通常会話一回、不正tool引数・取消時の追加生成なし、世代変更・失効・一時停止、音声player起動前の拒否を確認した。

検査用コピーの国語資料不足で失敗した回は資料を補い、全targetを再実行して成功。全targetの静的検査で指摘されたテスト内のロック範囲も明示した。馬のログ中のConnectionErrorは、選択時の通信失敗を意図的に起こす検査ケース。

今回のコード経路に対する模擬通信・自動検査と、以前の3条件実モデル比較は別の証拠として扱う。Minecraft・常駐モデル・常駐ドギドの停止や再起動、MOD交換は行っていない。
