# 共有Mac・ユノからドギドへの伝言

2026-11-05の家庭内運用の仕様。以下は実装した動作。確認範囲は末尾に記す。

## 誰が何をするか

- **お母さんの用件を、息子さんの遊びより優先する。** ユノは家庭のスケジュール管理者、ドギドはMinecraftの相棒。ユノから届いた伝言はゲーム内の判断より優先する。お父さんからユノへ届いたLINEも、その送り主の伝言として届ける。
- **入口は二つ。** 共有Macの管理者は「ドギド共有」に直接入力できる。声を使うときはMacの音声入力で文字にし、内容を確認して送る。LINEでは、ユノが受信したすべてのテキストが転送対象。「ドギドへ」などの前置きは不要。
- **ユノのLINE設定は二つ。** 「ユノでLINEを読み上げる」は受信した本文の読み上げ、「ドギドへLINEを転送する」は息子さんへの転送を制御する。両方オンなら両方が話す。ユノはドギドの配送を待たずに自分の受信処理を続ける。
- **ドギドは登録PC全員に伝える。** 各PCに接続したドギドへ、送り主の呼称とそのPCの環境設定のプレイヤー名を使い、用件の意味を保って約40字を目安に言い換える。時刻・数字・否定を保つ。生成できないときは送り主を添えて原文を届ける。

## 共有画面と管理者名

共有画面の「メッセージ」はEnterまたは送信ボタンで送る。日本語の変換確定は送信と分け、空欄・未確定文字・500文字超過では送らない。workerへ書き込めた場合だけ入力を消し、停止中・書込み失敗時は残す。

歯車から設定画面を開き、管理者名の保存、端末追加、登録削除を行う。管理者名は1〜80文字の一行。初期値は「管理者」で、家庭内の役割を固定しない。この名前を送信時の`sender`として既存の表示・生成・原文代替へ渡す。変更前に受付済みのメッセージは元の送り主を保持する。LINEは従来どおりユノに登録された実際の送り主を使う。

登録PCはコンピュータ名で一覧表示し、内部の登録IDやIPアドレスを表示しない。「登録追加」で従来のペアリング受付を開く。その左に「削除」を置き、各PCの先頭にチェックがあるときだけ有効にする。チェックは削除対象だけで、送信対象は常に登録PC全員。宛先の選択欄は置かない。設定画面は右上の茶色い×ボタンで閉じる。

PC名は遊ぶMacが既存のHTTPS認証確認時に通知し、認証済みの登録にだけ保存する。`devices.json`の名前のない旧形式を読み、名前の追加時に同じtoken hashを保持したレコードへ移す。名前未受信の旧クライアントは「登録PC 1」等で表示する。名前とIPは認証の識別には使わず、IP変更後も同じ端末ID・鍵で再接続する。

管理者名の正本はmacOSのApplication Support内の`com.dokidoki-dogido.lan.host/ui-settings.plist`。アプリの更新や停止とは独立して保存し、ファイルの原子的な置換成功後だけ送信者へ反映する。読めない既存設定を別の送り主へ置き換えて送信せず、設定し直すまで入力を保持する。端末登録は既存の保存先と操作を使う。

外観は白い本文、茶色の文字、淡い緑、角のある枠とボタンを使う。配色・配置は共有アプリに限定する。

## 場面ごとの動作

ドギドは伝言をゲームに表示し、音声がオンなら読み上げる。戦闘の警告中も、川柳の生成・読み上げ・相談中も、伝言を優先する。音声がオフなら文字で届ける。ユノは表示確認後も同じ成功文を使い、音声設定には触れない。

LINEから届いた場合、ユノは**自分のLINE受信通知を先に読み、そのあとでドギドへの配送結果を話す**。結果が先に分かっても読み上げ順は同じ。成功時は、まず届けたことを伝え、続けて戦闘や川柳の状態を添える。

| ドギドへの配送結果 | 共有Macに直接入力したときのユノの声 | LINE受信通知に続けるユノの声 |
| --- | --- | --- |
| 通常プレイ中に届いた | 追加報告は省く | 「ドギドにも、ラインメッセージを伝えたよ！」 |
| 戦闘中に届いた | 「伝言を届けたよ！今は戦闘中みたい！」 | 「ドギドにも、ラインメッセージを伝えたよ！今は戦闘中みたい！」 |
| 川柳中に届いた | 「伝言を届けたよ！今は川柳中みたい！」 | 「ドギドにも、ラインメッセージを伝えたよ！今は川柳中みたい！」 |
| Minecraftのワールドが開いていない | 「マインクラフトが止まっているみたい！ドギドに伝言できなかったよ！」 | 直接入力と同じ |
| 一部のPCへ到着し、ほかには届かなかった／未確認 | 「一部のPCには届いたけど、全部のPCへの到着は確認できなかったよ！」 | 直接入力と同じ |
| 途中で通信が切れ、届いたか不明 | 「途中で通信が切れたよ！届いたかどうかはわからないや！」 | 直接入力と同じ |

送信受付時の全登録PCを対象として固定し、一台の未接続や失敗でほかのPCへの配送を止めない。各PCは同じ送信期限内に処理する。共有画面には複数PCの結果をPC名付きで表示し、ユノやLINEへは送信単位で結果を一回だけ返す。全PCの表示または再生が確認できた場合だけ全体成功とし、一部成功は「一部のPCには届きましたが、全PCへの到着は確認できませんでした」と区別する。登録PCがゼロなら登録を案内する。

既存の`messages`に配送群IDを追加し、LINEの通知IDは群の先頭だけで保持する。同じLINEの再送で配送群を増やさず、受付後に追加・再接続したPCへ古い通知を追加配送しない。旧単一宛先の完了記録は一件の群として引き継ぎ、旧宛先設定は撤去する。移行は一つのトランザクションで行い、途中の失敗では元のDBへ戻る。

ドギドが「届けた」と返すのは、Minecraftが表示を確認したとき、または音声の再生が完了したとき。息子さんが実際に読んだ・聞いたことまでは判定しない。再接続や同じ伝言の再照会で二重に読まない。ゲーム内での「はーい」はドギドとの会話として扱う。

LINE経由の配送失敗では、ユノの音声報告に加え、元のLINE送信者に理由を返す。直接入力の場合は共有画面に結果を出す。ドギドの失敗がユノのLINE通知を止めることはない。

## 実装と確認範囲

- 全登録PCへの配送と設定UIは、関連Python/AppKit試験57件で確認。二台への個別文面、全員完了後の結果一回、一部未接続、期限切れ・削除・再起動、LINE再送、旧DB移行と移行途中の失敗を隔離環境で検査した。ユノの固定文面・結果schema・模擬LINE返信は別の関連試験38件で確認。実画面では宛先欄の撤去、ボタン配置、チェックと削除の連動、右上の×で閉じる操作を確認した。共有アプリとユノへ反映し、登録・管理者名の保持、旧配送DBの移行、両受付の復帰を確認した。実PCを複数台使った伝言送信は未実施。
- 共有UI・管理者名の変更は、関連Python/AppKit試験43件で確認した。AppKitは一時設定と模擬worker書込みで、未確定文字・送信失敗・名前保存失敗・再読込を確認。送り主のモデル入力と出力は模擬応答で確認し、モデル向けの指示文は変更していない。
- 隔離した確認用アプリの実画面でEnter送信、設定画面、管理者名の保存と送信者への反映を確認。共有アプリを更新・再起動し、既存の登録設定を保持したまま受付が復帰した。管理者名は実環境で「おかあさん」を保存した。新UIから実ゲームへの試験伝言は送信していない。
- 両Macへのアプリ更新、共有画面からの入力、LINE転送、ユノの独立した二つのスイッチは導入済み。導入時に両方オンを確認した。[導入・操作手順](../scripts/lan/遊ぶMacの導入.md)
- 模擬ゲームと音声プレイヤーで、戦闘・川柳中の表示、表示確認または再生完了後の成功、警告への割り込みを確認。ユノは、元のLINE通知を端末が受け付けてから配送結果を再生し、端末が再生中なら待つ。実LINE・Minecraft・実スピーカーを同時に使った確認は未実施。
- 元のLINE送信者へのエラー返信は実装済み。ユノ側の同じLINEチャネルのアクセストークン設定が残る。
- 停止中の伝言を次回起動まで保管する機能はない。LINE本文の読み上げをオフにした場合、LINE経由の結果も声では報告しない。転送と失敗時のLINE返信は独立して動く。
