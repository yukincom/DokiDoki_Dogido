# 乗れる動物の呼び戻し（2026-10-11、10-12対象拡張）

状態: 通常の馬は2026-10-12にユーザーが実機で成功を報告。14種への拡張と自動・実モデル検証、通常のMODフォルダへの配備が完了。拡張後の実機確認は未実施。

## 会話からの流れ

1. 通常会話モデルが、今回の本人による「今ここへ乗れる動物を呼び寄せる依頼」を判断する。この段階へ候補一覧は渡さない。名前の完全一致や肯定操作語の列挙で入口を絞らない。
2. 依頼の原文全文とconfidenceをRustが検査した場合だけ、Minecraftが送った現在の候補一覧をモデルへ渡す。
3. モデルが名前の表記ゆれ・種類・会話・最後の騎乗から一頭の短いcandidate IDを選ぶ。候補が曖昧なら質問する。登録名の辞書は持たない。呼べる候補が0頭なら選択toolを公開せず、同じ二回目の会話呼出しに一覧と理由を渡す。
4. Rustが元の候補表のUUIDを取り出し、現在のsession・turn・処理世代・個体状態と照合して、既存assist配送へ5秒の命令を積む。
5. Fabricの統合サーバーが実状態と着地点を再検査し、同じUUIDの個体を移動する。移動結果が届くまでは成功として扱わない。

平常時の通常会話は一回、呼び寄せ依頼は最大二回のLLM呼出し。戦闘中は既存の戦況・知識受付の後、同じ二段契約を操作支援の一件枠で実行する。呼び戻し依頼以外と判断した入力は生成本文を発話せず、再判定しない印を付けて既存の戦闘中入力処理へ戻す。各段階の再生成・別方式へのfallbackは行わない。根拠の省略や過去発言の混入、confidence 0.9未満、不完全な操作出力は実行しない。名前・語句の肯定リストを実行条件にはしない。否定・引用・伝聞・予約・単なる名前の呼びかけ・場所や能力の質問は会話で扱う。通常受付へ戻した後の会話可否は従来の `chat_allowed` 等の判定に従い、敵が残るAlertでも条件を満たせば会話できる。呼び戻し支援の追加で会話許可を広げたり、Alertの会話を禁止したりしない。

## 対象と実行条件

シングルプレイの統合サーバーで、同じ次元にロード済みの生存・成体の14種を対象にする。未ロード個体を探すチャンク読込は行わない。

| 対象 | 候補資格 |
|---|---|
| 馬・ロバ・ラバ・ゾンビホース・オウムガイ・ゾンビオウムガイ・ラマ・行商人のラマ | 本人が飼い慣らし、Owner UUIDが本人と一致する個体。既存の馬と同じく、所有個体は名札・鞍を必須にしない |
| スケルトンホース・ラクダ・ラクダハスク | Ownerがあれば本人と一致・飼い慣らしを必須にする。Ownerなしは飼い慣らし状態＋名札＋鞍を必須にする |
| ブタ・ストライダー・ハッピーガスト | バニラにはOwnerがない。名札＋鞍（ハッピーガストはハーネス）を必須にする |

所有者なしの名札＋乗用装備条件は2026-10-12にユーザー承認。名札を所有の証拠とは扱わず、この種類に限る呼び戻し資格として使う。通常のハスク・敵ガスト・子どもは対象外。ラマ2種は座れるが通常は騎乗操縦できない。乗員あり・ほかの乗り物に乗っている個体・リード付き・他個体を牽引中のハッピーガストは呼べない。

観測の候補一覧は最大32頭。上限を超えると部分一覧を使わず全体を利用不可にする。表示名は現在の名札、個体の正はUUID。改名・種類変更・所有者変更・装備解除・乗車・死亡・ワールド変更が生成待ちに起きた場合、古い選択を実行しない。snapshotは過去3秒、時計差による未来1秒までを許容する。

逃走のため、敵・警告・被弾・panic中も本人の明示依頼を受け付ける。戦闘中の判定と命令発行は警告音声の直列枠を待たず、通常会話の取消世代とも分離し、既存assistの入力世代・取消・session instanceで照合する。ゲーム一時停止中・観測が古い場合は実行しない。通常雑談・workshop・川柳の戦闘抑制は維持する。生成中に新しい入力が入った場合は古い結果を破棄する。すでに発行した命令は後の発言だけでは取り消さず、同じIDの再配送・5秒の期限・Fabricの再検査で管理する。

着地点はプレイヤー付近2〜5ブロック、足元高さの上下1ブロックで探す。準備10 tickの間と移動直前にも候補資格・拘束・プレイヤー位置・着地点を検査し、成立しなければ移動しない。

- 陸上種：最低2×2の乾いた平らな支持面と高さ3ブロック。実際の立ち姿の身体が大きければその寸法へ拡大する。ストライダーもこの乾いた床を使い、溶岩着地は追加しない。
- ハッピーガスト：通常4×4×4の身体全体が入る空間。実寸を使い、空中では床を必須にしない。
- オウムガイ2種：**横3×3＝9マス以上**の水域。一直線の9マスや横9×9という意味ではない。身体の高さ分（通常1ブロック高）の各マスが水かつ衝突物なしであることを検査する。水中からの依頼も受け付け、陸上には呼び戻さない。

どの種類も、危険ブロック・他のentityとの衝突・ワールド境界・高さ・全域の読込済みチャンクを検査する。水生・飛行へ陸上の接地状態を強制しない。

## 呼べなかった理由の受け渡し

候補の公開範囲（同じ次元・ロード済みのみ）と、乗員・拘束・名札／装備などの不成立理由をモデルへ渡す。「その個体に乗員がいる」と「その個体が別の乗り物に乗っている」を分け、鞍とハーネスの不足も区別する。一覧にないだけでは、遠距離・別次元・消失・資格不足を区別できない。プレイヤーへの案内はユーザー指定の意図に合わせ「声が届かへんかったみたいや」とし、読み込み範囲やチャンクを会話へ露出しない。

Minecraft実行時に対象を確認できなくなった場合も同じ案内にする。水域の条件不足、安全な場所なし、乗員、拘束、状態変化などは既存の`detail_code`で返す。Rustは既存の結果ACKに結び、確認できた理由を一度だけ短期の出来事として残す。次の会話モデルが理由を参照できるが、長期記憶や川柳材料には入れない。期限超過や通信・実行失敗では「動かなかった」と断定せず、成功未確認として扱う。追加の原因推定用LLMや別endpointは設けない。

## 出現演出

準備光の後に同じ個体を移動する。馬・ロバ・ラバ・スケルトンホース・ゾンビホースだけは前脚を上げ、クライアントでその姿勢を確認する。他の種類は到着位置を確認する。確認した同じtickに、その種類の鳴き声と中心が白・周囲が黄色の粒子を出す。粒子範囲は体格に合わせて広げ、周囲へ散って明滅しながら消える。外部素材の追加はなく、vanillaのglitter spriteを使う。

移動ACKは移動成功の証拠であり、音や描画の観測証拠ではない。演出待ちがタイムアウトしても二度移動しない。実機での色・タイミング・馬体との重なりは別途確認が必要。

## 通信契約

専用endpointは設けず、既存の登録・game-events・commands・command_results・ACKを使う。`horse_recall`、`owned_horses`、`recall_horse`、native toolの`list_horses / select_horse`は既存の経路名を維持する。契約をv2へ更新し、v1互換の別経路は設けない。両側の更新が必要。

- 登録の実行権限: `execution_capabilities: ["integrated_server.horse.recall.v2"]`
- 観測: `owned_horses` は任意。`status_snapshot` で省略された場合は一覧を撤去する。馬一覧を持たない戦況・聴覚等のイベントでは直前の一覧を元の観測時刻のまま保持し、鮮度を延長しない。次元変更でも破棄する。
- 一覧: `schema_version:2, status:available|unavailable, world_id, revision, observed_at, player_uuid, dimension, recent_mount_id, candidates`
- 各候補: `entity_id, entity_type, custom_name, tamed, owner_uuid, adult, equipped, alive, dimension, has_passengers, has_vehicle, leashed`
- 命令: `type:recall_horse, command_id, issued_at, expires_at, world_id, player_uuid, dimension, entity_id`
- 結果: `command_type:recall_horse, command_id, status, executed_at, detail_code, entity_id, world_id`。識別子はトップレベルに置く。

`entity_type` は`horse / donkey / mule / skeleton_horse / zombie_horse / camel / camel_husk / pig / strider / happy_ghast / nautilus / zombie_nautilus / llama / trader_llama`の閉じた値。`owner_uuid`はOwnerなしならnull、`tamed`は実際の飼い慣らし状態で、所有者のない動物へtrueを捏造しない。`equipped`は鞍、ハッピーガストではハーネスの有無。LLMへはUUIDを渡さず、名前・種類・呼び戻し可否・不成立理由・直近騎乗だけを公開する。

`world_id` は接続・ClientWorldが変わると新しくする。同じ次元名の別世界へ命令を持ち込まない。revisionが増えても対象情報が一致すればよい。未知IDの結果はACKするが成功の証拠にせず、正しい命令・種類・個体・世界・期限が一致した成功だけを一度記録する。

実行と再配送の期限は発行から5秒。結果の受信にはさらに5秒の猶予を設け、期限内に動いた馬の結果が次の観測で届いても成功を確認できるようにする。猶予中の新しい呼び戻しは受け付けず、実行時刻が5秒の期限外なら成功扱いにしない。受信猶予を過ぎた結果は復活させず、「確認できなかった」と記録・案内する。
