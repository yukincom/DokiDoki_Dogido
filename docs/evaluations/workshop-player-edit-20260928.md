# 一案の対象保持と部分置換

対象はプレイヤーが出す一つの差し替え案。開発側の改善手法比較と、実際のプレイヤー操作を分ける。
複数案の管理・候補ID返却・順位による選択は実装しない。

## 上流コードから取り入れた範囲

上流の固定revisionとファイルは[OSS比較計画](../haiku-workshop-oss-trial-plan.md#参照したossと範囲)に記載。
TypeAgent、Framesの評価コード、Trustcall、OpenDFの対象ソースおよびMITライセンスを確認した。
上流コード・モデル・データのコピーや新規依存追加はなく、次の考え方を既存のドギドの型と処理へ適用した。

| 読んだ部分 | ドギドでの扱い |
|---|---|
| TypeAgent `clarifyActionSchema.ts` のパラメータ省略と参照不能の区別 | 対象の省略を「対象が存在しない」と混同せず、現在の相談の対象箇所を使う。原文の新しい対象指定を優先し、解決できない対象を適当に別の行へ写さない |
| Frames `key_value_pairs` のframeとslotの分離 | 複数frameは使わず、現在の一案の対象箇所・差し替え表現・検査結果を分離。公開repoはデータ評価用で、追跡器の完成実装ではない |
| Trustcall `_ExtractUpdates` の識別済みデータへの差分更新 | 「やっぱりXXにして」では差し替え表現だけ更新し、既に確定した対象を維持。全三行の生成、任意JSONパス、追加LLM修復loopは使わない |
| OpenDF `side_task` の未完了の本題の保持 | 今回は一般的な本題復帰の実行器を追加せず、相談中の一案が短い履歴や音声中断と一緒に消える問題に限定して既存状態を修正 |

## 実装

- `workshop_candidate.rs`: 検証済みの完成三行だけを持つ形から、対象箇所・差し替え表現・原文根拠・検査結果を持つ一案へ変更。現在句の内容と版を結び付ける。
- `dialogue/mod.rs`: プレイヤー自身の案は返答音声の開始前に保持。ドギドの会話履歴は従来どおり実再生完了後だけ確定。
- `workshop_helper.py`: 明確な引用付き相談は原文から一案を取り出し、そのターンを相談に限定。表現だけの訂正では、今回の原文に対象の新指定がない場合だけ保持中の対象を使う。
- `workshop_runtime.rs`: 保持中の一案も適用時に既存の部分置換・読み・音数・hard制約を再実行し、RustのCASを通す。未採用案の明示採用・保存は既存経路。

## 検証

実モデルの全入出力: [workshop-player-edit-20260928.jsonl](workshop-player-edit-20260928.jsonl)。
会話はRustのHTTP経路を使い、発句・Minecraft観測・TTS・再生は模擬。
指定モデルと全4生成の応答modelは `mlx-community/Qwen3.6-35B-A3B-4bit-DWQ`、全て `finish_reason=stop`。
実サービスの起動・停止は行わず、試験用プロセスのみ起動・回収した。

| 入力の流れ | 結果 |
|---|---|
| `くろいをしろいに変えて` | `くろいおのへと` → `しろいおのへと`。直接編集は既存コード経路でモデル0回 |
| `『くろい』を『しろい』にするのはどう？` → 一往復相談 → `それにして` | 相談中は変更せず、指示後に同じ部分だけ未採用案へ反映。選択時モデル0回 |
| `『くろい』を『あお』にするのはどう？` → `それにして` → `やっぱり『あおい』にして` | 音数不足の`あお`は不適用。対象を再指定せず`あおいおのへと`へ訂正できた |

3系列・7発話が完走。各系列で対象外の文字・他の二行・元の保存済み句を維持した。
モデル生成4回は2,928〜5,232ms。高速化の一般的な効果を示す比較ではない。
直接編集の成功を実モデルの意味理解の成功には数えない。

自動検査はRust全207件、Python関連193件＋87 subtests（helper98件を含む）。
模擬HTTPで、一案の保持、4往復を越える相談、音数不合格からの表現訂正、返答音声の中断を確認。
既存の編集HTTP試験16項目も通過。戦闘HTTP試験は`さっきの句についてまた話そうよ`が既存の記憶検索へ入る箇所で失敗し、今回の変更範囲では修正していない。戦闘pauseで一案を保持し、closeでは破棄する境界はRust検査で確認した。

Minecraft・実マイク・スピーカーは未確認。引用符なしの自由な相談や複雑な訂正は、既存モデル抽出の精度に依存する。実モデルの発話の口調・説明品質を全般的に改善したという結果ではない。
