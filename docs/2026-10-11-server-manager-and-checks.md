# 2026-10-11 Mac管理アプリと既存検査の修復

## 管理アプリ

`apps/ドギド サーバー.app` に、本体・マイクの個別起動と停止、ターミナル出力の閲覧、発言だけの履歴へのリンクを用意した。実装・再ビルドは [アプリのREADME](../apps/dogido-server-manager/README.md) を参照。

- 本体の既存設定読込と `start_dialogue.command` / `start_voice.command` を使う。モデル・VOICEVOXを別途起動する経路は追加しない。
- 誰が起動したかによらず、実行ファイル、作業フォルダ、サブコマンド、接続先を照合する。本体は待受と `/healthz` のRust会話準備完了も確認する。別プロセスのポート占有や複数候補では起動・停止を無効にする。
- 停止ボタンの操作時にPID・開始時刻・実行ファイル・引数・作業フォルダを再確認し、そのプロセスへSIGTERMを送る。アプリを閉じてもサービスは停止しない。アプリを開くだけではサービスを起動しない。
- ログは照合済みプロセスの実際の標準出力・標準エラーのファイルを読み、末尾を自動更新する。アプリ起動分は `.dogido_tools/server-manager/logs/` に追記する。外部TTYへ直接出力するプロセスの過去出力は取得できないため、起動元での確認を案内する。
- 発言履歴は既存 `/dogido` の `view=utterances` 表示を使う。診断・参考情報を隠し、保存・配送・履歴の内容は変えない。管理アプリにも同じ表示スクリプトを同梱するため、今回の変更前から稼働している本体でも履歴画面を表示できる。

## 署名とアイコンの更新

毎回のビルドで変わるad hoc署名を、このMac専用の `Dogido Local Code Signing` 証明書による署名へ切り替えた。macOSのアクセス許可の同一性照合に使われるdesignated requirementは、実行ファイルのhashではなく固定のbundle IDと証明書に結び付く。証明書と秘密鍵はログインキーチェーンに作成し、ビルドは証明書名またはSHA-1で一意に選択する。見つからない場合や同名が複数ある場合は中止し、ad hocへ自動で戻さない。`--ad-hoc` は試用時の明示指定に限る。根拠はAppleの[TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)。

- 証明書の照合・重複・不在・明示ad hocの自動検査4件が成功。
- 本物の証明書でアプリをビルドし、厳密な署名検証に成功。
- 版番号とリソースを変えた別ビルドも同じ証明書で署名し、両方向で同じdesignated requirementを満たすことを確認。同じbundle IDのad hoc署名はこの照合を通らない。
- おっとりした表情を保ち、外周の透明余白をなくして背景を四辺・四隅まで拡張。設置済みICNSから1024px画像を抽出して全1,048,576画素のalpha=255を確認。版番号は0.1.1、アイコンのリソース名はv2。
- Finderのアイコン表示と管理画面の本体PID 64602・実ログを確認。管理アプリを開き直してもアクセス確認の再表示はなく、本体は同じPID・開始時刻で稼働を継続。

初回の固定署名への切替時は、macOSの書類フォルダ等への許可を再度求められる場合がある。以後も同じ証明書を使用する。実際のmacOS権限ダイアログの更新前後での継承は別途実画面での確認が必要であり、上記の署名同一性試験とは区別する。
