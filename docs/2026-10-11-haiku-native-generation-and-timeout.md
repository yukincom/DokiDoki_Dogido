# 2026-10-11 川柳候補提出APIと相談の待ち時間

> 同日後続の比較と採用判断により、自動生成のnative候補提出はJSON方式へ戻した。この記事はAPI版の実装・検証時点の履歴。返答後5分の無操作期限と全体4分制限の撤廃は継続する。[採用と確認記録](2026-10-11-qat-json-adoption.md)。

自動発句の初稿・再生成を `submit_haiku_candidate` のnative function callingへ移した。既存のChat Completions通信を使い、新しいHTTPサーバーやagent基盤は追加していない。

## 候補提出と案内

- 初稿は `lines: [{line_index, text}]` の0・1・2、再生成はコードが指定した行だけを提出する。本文JSONからの代用、未知の関数、複数呼出し、重複・範囲外の行、固定行の変更は受け付けない。
- 初稿・再生成の「本文にJSONを返す」指示と旧構造再試行の案内を削除した。systemは候補生成担当の役割、共有のドギド人物像は句の視点の参考として渡す。人物像の文言は共通ソースを使う。
- 再生成では前候補の関数呼出し、同じIDの実検査結果、今回の修正依頼の順に渡す。前候補に付随した会話文は戻さない。結果には確定読み、実測音数、目標・許容範囲、不合格理由、固定行、次の対象行を含める。未解決の読み・音数を確定値にしない。
- APIの `tool_choice` は提出関数を明示指定する。現在のMLXサーバーはこの指定を強制しないため、受信側でもnative呼出しを必須とする。
- 音数・読み・出典・材料重複・道具制約・候補重複と最大6回の再生成は既存検査を維持する。自動発句の音数許容は従来の5/7/5各±1音。workshopの厳密な5/7/5とは別。見どころ・出典評価・workshop修正案のJSON契約は対象外。

## 相談の待ち時間

発句から4分で閉じる全体上限を廃止し、句または相談返答が届いてから5分、句の相談への発言がない場合に閉じる。生成・配送待ち・読み上げ・戦闘中断中は失効しない。文字表示ACKが先でも、音声終了から待ち時間を数え直す。移動、道具使用、観測snapshotの受信だけでは延長しない。

## 確認結果

- 関連Rustユニット: `haiku` 72件、`python_worker` 9件が成功。
- 模擬HTTP: 候補提出3件、発句14件、待ち時間1件、workshop18件、読み音数出典の照会1件、編集8件、計45件が成功。本文JSONの不受理、最大再生成回数、失敗時の保存なし、生成・音声中の保留、移動・道具使用で延長しないことを含む。
- 常駐 `google/gemma-4-E4B-it` と保存済みの実景材料で独立実行した。最終構成は初稿1回＋再生成6回の計7回すべてがnative候補提出、検査結果6往復を確認。説明文・本文JSONへの逸脱はなかった。句は音数超過・候補重複が残り、上限到達で不採用。ゲーム・記憶・音声へは送っていない。これはAPI往復の確認であり、発句成立率の改善を示す結果ではない。
- 修正途中には説明文のみを返す失敗を実測した。元の会話役割のまま指示を追加するだけでは解消せず、候補生成の役割と要求順序を変更した。途中の結果も証跡に保持する。
- 全ターゲット試験は途中版でlib 517件が成功した後、既存 `chat_topics` の文言fixture不一致2件で停止した。対象の関西弁文言は作業開始前から変更済みで今回触っていない。全体成功とはしない。
