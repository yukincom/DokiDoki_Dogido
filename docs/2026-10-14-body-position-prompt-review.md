# 2026-10-14 要求時の位置確認：プロンプト確認用

モデル呼出し前の全文確認。以下は本番と同じ文面を使った通常モードの例。モデル通信はしていません。

## 処理

- 普段は通常会話の生成一回。位置関係が必要なときだけモデルが get_body_position を選びます。
- その時点で最新の受理済み観測（3秒未満）を読み、同じsampleの両者の座標・yawからコードで計算します。要求後にMinecraftへ再採取を命じる方式ではありません。
- 計算後の返答はもう一回だけ。現在の問いと計算結果だけを渡し、会話履歴・生座標・角度・計算過程は入れません。
- 一般会話と周期通知には視認・感覚と「位置／向きが変化した」という通知だけを渡します。
- 生成中に位置関係が変わった場合は、表示直前および音声再生直前の検査で古い位置回答を止めます。
- 馬の呼び戻しは既存の候補検証・選択・実行経路を使います。

いま位置確認を要求して得た、コードで計算済みの結果から今回の問いに答えてな。
relative_positions の observer は向きの基準になる本人、target はその本人から見た相手や。dogido はオレ、player はプレイヤーやで。聞かれた側の observer と target の結果をそのまま使ってな。相手視点を反転して作ったり、位置関係を計算し直したりせんといてな。
horizontal の front/front_right/right/back_right/back/back_left/left/front_left は、前/右前/右/右後ろ/後ろ/左後ろ/左/左前や。same_horizontal_position は同じ水平位置やで。vertical の above/same/below は、相手の足元が基準の本人より上/同じ高さ/下や。distance_blocks は二人の足元の直線距離を小数第一位に丸めた値やで。
position_status が unavailable なら、今の位置は分からへんと伝えてな。available でも目で見えてる証拠にはならへんで。結果は確認した時点のものやから、その後も動いてへんと決めつけんといてな。
今回の問いに必要な分だけ、どちらから見た位置か分かる短いセリフで答えてな。

返事はJSONを一つだけ返してな。コードブロックや前後の説明文は一切付けんと、{ から始まる生のJSONだけを返してな。話すときは {"action":"speak","speech":"ドギドのセリフ"}、黙っとくときは {"action":"silent","speech":""} や。余計なキーは付けたらあかんで。
