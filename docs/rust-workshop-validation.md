# Rustの川柳相談処理

## コードはLLMの出力を受け取り、補完し、実行する

**川柳は、人間とAIの認知のぶれデータを収集するための窓口。あとで句集の方でも編集できる。** その場の句をコードの品質判定で完成形へ絞ることを目的にしない。

**2026-10-21の方針。コードはLLMの邪魔をしない。** コードの役割は、LLMが出してきたものを受け取り、不足を補完して、実行すること。会話の意味・意図・句の良し悪しを、固定語句や正規表現でもう一度審査しない。

- LLMが選んだ会話・編集・採否・終了を受け取る。「もし」「かな」、疑問符、引用・伝聞・否定などの語形だけで操作を拒否したり、利用できる操作を減らしたりしない。語句ごとの例外追加で対処しない。
- 補完には、既知の現在句・対象行・版、保存済みの候補、原文中の置換語、機械的に確定する形式を使う。補完のために意味を作り直したり、本人の語句を別の語へ変えたりしない。
- 川柳WSでは音数の計測・目標比較・固定案内を行わない。読みは参照情報として扱う。読み未確定、字余り・字足らず、hard禁止語、同じ表現を含むことを編集の拒否理由にしない。読みが不明なら不明のまま扱い、確定したと偽らない。
- コードは指定された対象へ適用し、現在句・版・取消状態・保存結果を管理する。原文にない置換語、存在しない対象、古い句への適用、二重保存など、実行データの不整合を扱う。これを口実に意味・意図の再判定を追加しない。
- 受け取った操作の実行結果を表示・音声・記録へ反映する。未実行を成功と報告せず、保存成功後の本人編集は「変更したで。」と通知する。

この方針は川柳WSに対する旧来の語句判定・音数・hard禁止語・表現重複による拒否の記述に優先する。自動発句、戦闘の物理状態、他の世界操作を変更したという意味ではない。ModernBERTへの分類移行は別作業として維持する。

## 既存処理との接続

`workshop_projection` が渡した現在句と文脈を使い、`workshop_validation` がモデル出力の形式と具体的な入力元を整える。`workshop_editing` が対象行の差分を作り、`workshop_edit::Pending` と `dialogue/workshop_edits` が現在句・版を照合して保存する。読みの取得には既存UniDic helperを使い、本人から読み方・保存材料を尋ねられ、手元の情報で答えられないときだけ既存toolで参照する。編集の前提確認にはしない。

取消・期限・実行回数・通信量の上限と、対象外の行を変更しない契約は既存の所有者で扱う。新しい意味検査器、並列の編集経路、拒否後に意味を再審査するモデル呼出しは追加しない。
