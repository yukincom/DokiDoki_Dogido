# Rustの川柳相談：モデル出力の受信と適用

## コードはLLMの出力を受け取り、補完し、実行する

**川柳は、人間とAIの認知のぶれデータを収集するための窓口。あとで句集の方でも編集できる。** その場の句をコードの品質判定で完成形へ絞ることを目的にしない。

**2026-10-21の方針。コードはLLMの邪魔をしない。** コードの役割は、LLMが出してきたものを受け取り、不足を補完して、実行すること。会話の意味・意図・句の良し悪しを、固定語句や正規表現でもう一度審査しない。

- 行指定・具体変更・終了はBERT、語句・採否・称賛・lesson解除はLLMの解釈を受け取る。「もし」「かな」、疑問符、引用・伝聞・否定などの語形だけで操作を拒否したり、利用できる操作を減らしたりしない。語句ごとの例外追加で対処しない。
- 補完には、既知の現在句・対象行・版、保存済みの候補、解釈済みの旧語・置換語、機械的に確定する形式を使う。LLMから受け取った語句を認識原文から再抽出して上書きしない。
- 川柳WSでは音数の計測・目標比較・固定案内を行わない。読みは参照情報として扱う。読み未確定、字余り・字足らず、hard禁止語、同じ表現を含むことを編集の拒否理由にしない。読みが不明なら不明のまま扱い、確定したと偽らない。
- コードは指定された対象へ適用し、現在句・版・取消状態・保存結果を管理する。存在しない対象、古い句への適用、二重保存など、実行データの不整合を扱う。これを口実に意味・意図の再判定を追加しない。
- 受け取った操作の実行結果を表示・音声・記録へ反映する。未実行を成功と報告せず、保存成功後の本人編集は「変更したで。」と通知する。

この方針は川柳WSに対する旧来の語句判定・音数・hard禁止語・表現重複による拒否の記述に優先する。自動発句、戦闘の物理状態、他の世界操作を変更したという意味ではない。BERTの[川柳8分類・通常16分類の分離](2026-10-24-bert-mode-routing.md)と、WS外の既存shortcutも維持する。

## 現行の受信・適用（2026-10-28）

`workshop_validation` を `workshop_response` へ置き換え、出力のdecodeとactionに必要な項目の補完へ役割を絞る。原文の語形を検査する `workshop_input_guard` は撤去する。`evidence`・`confidence` は任意の記録で、欠落・値・認識原文との一致によって操作や称賛を足切りしない。

BERTが具体変更に分類した入力は、原文の正規表現から直接編集せず、既存native `stage_player_edit` による一回のLLM解釈へ渡す。2026-10-30から、コードが対象行と元句を補い、LLMは認識原文・補正された言葉・会話から変更後の一行全体を返す。部分変更でも残す言葉を含める。コードが元の行との同値・差分を確認し、他の二行を保持して既存の版照合・保存へ渡す。旧語の部分一致による置換はこの入口では行わない。保持する相談案と対象も原文一致を要求しない。[変更記録](2026-10-30-workshop-complete-line.md)。

採用・破棄、BERT終了に付随する採否、任意の称賛feedbackから原文evidenceの検査と専用再試行を撤去する。WS内のlesson解除は会話LLMの `clear_lessons` actionを既存memory runtimeへ渡す。終了分類、採否の解釈、実行完了の記録は区別する。BERTが終了に分類し、未採用案がなければ直接閉じる。未採用案がある場合はLLMが採用・破棄・会話を選ぶ。採否が未確定なら尋ね、askや会話の応答ではopenとpendingを保持する。LLMが採用または破棄を選んだときだけ、その操作の成功後に閉じる。

新案生成は一案だけを受け取り、漢字や記号を含む表記を保持する。材料は参照情報であり、空・未使用・重複で案を拒否しない。返却された材料IDのうち実在するものだけを任意の注記にする。材料IDの一致は、意味や実際の使用出典を検証した証拠ではない。

未採用AI案への本人編集は元句と対象外行の材料・来歴を保持し、pendingだけを更新する。編集だけでは採用・保存せず、採用後に保存する。編集結果が元の句へ戻った場合は、既存の案破棄処理で未採用案を解消し、保存や相談終了は行わない。今回の修正で、AI生成案であることだけを理由に本人編集を止める経路を解消する。

対象・現在句・版・入力世代・取消・対象外の行の不変・保存整合性は既存処理で確認する。利用できないaction、実行に必要な対象や本文の欠落、適用先の不一致は実行データの問題として扱い、意味の再審査へ広げない。

**検証状況:** Rust全対象978件、関連の模擬HTTP試験13本、releaseビルド、起動前チェックが成功。Clippyは既存箇所の警告27件で未通過。実BERT・実モデル・Minecraft・実音声の再確認と常駐本体の再起動は未実施。以下の成功件数は各日付時点の結果。[変更記録](2026-10-28-workshop-interpreted-edits.md)。

## 生成・発話中の戦闘保留（2026-10-28）

受付済みの川柳返答は、敵の戦闘で生成・発話が中断しても同じworkerを保持する。生成済み結果、保存結果、再生済み文数を持ち、安全確認と既存の復帰案内が終わった後に続行する。再中断でも同じ扱いとし、生成・操作・保存を繰り返さない。音声は途中の文だけ文頭から再開し、文字は新しい表示IDで確認する。明示停止・死亡・次元変更・voice off・切断・終了は保留を終端する。

[変更と検証記録](2026-10-28-workshop-reply-resume.md)。

## 既存処理との接続

`workshop_projection` が渡した現在句と文脈を使い、`workshop_response` がモデル出力をdecodeし、actionに必要な項目だけを実行用に整える。`workshop_editing` が対象行の差分を作り、`workshop_edit::Pending` と `dialogue/workshop_edits` が現在句・版を照合して保存する。読みの取得には既存UniDic helperを使い、本人から読み方・保存材料を尋ねられ、手元の情報で答えられないときだけ既存toolで参照する。編集の前提確認にはしない。

取消・期限・実行回数・通信量の上限と、対象外の行を変更しない契約は既存の所有者で扱う。新しい意味検査器、並列の編集経路、拒否後に意味を再審査するモデル呼出しは追加しない。
