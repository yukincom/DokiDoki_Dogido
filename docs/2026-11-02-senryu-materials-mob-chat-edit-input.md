## A. 発句の前置きから、その場の景色や生き物を選ぶ

**担当Aの状況（専用作業ツリー）** ホットバー限定・現在と過去の観測・配送済み会話の材料を既存の前置き選択へ接続した。関連自動確認とreleaseビルドを実施し、本人による実機確認を待つ。元材料の記録と生成結果の評価は区別し、実機合格後に試した差分をmainへ反映する。

発句開始時、既存の材料一覧に、観測できたバイオーム・天候・周辺のブロック・モブやその他のエンティティ、直近の視認、配送済みの直近の会話で話題にしたモブを載せる。「今見える」「さっき見た」「プレイヤーが話した」は、出典と時点を保ち、話題に上っただけのモブを現在の視認にはしない。身体観測の鮮度、空・地下の投影条件、会話材料の既存範囲は維持する。

持ち物候補は発句時の `player.hotbar` の空でない枠に限る。手持ちの道具に代わる一品も同じ範囲で選ぶ。空枠・空の手（`air`）は題材にせず、欠測・全枠空でも全インベントリで補わない。落下物は持ち物とは別の周辺観測である。景色・天候・生き物からの着想を優先し、持ち物はその場との取り合わせに使う。毎句モブを必須にはせず、語句一致による再生成も増やさない。

`haiku_irony` は上の候補から前置きを考え、`haiku_scene` は**同じ候補**から前置きで選んだ元材料を返す。三行生成・再生成へはその選択結果と前置きの調理方針を引き継ぐ。記録にだけ残す、後段で全材料を再投入する、といった別経路は設けない。[前置きと句用材料の契約](2026-10-29-haiku-preface-materials.md)（1〜3件なら全件、それ以上なら選んだ部分集合）と行別出典の意味は維持する。

**実機確認:** 竹林でパンダを視認し、話題にしてから視野を外して発句する。骨・腐った肉をホットバーの外に置き、発句時の枠、前置き・材料選択の実入力、そこから三行に渡った材料、保存句を同じ発句で照合する。竹林とパンダが出典を保って選べ、枠外の持ち物が混じらないこと。景色やモブを実際に詠んだかは、同じ場面の数句で別に記録し、候補への配送だけを改善の証拠にしない。

## B. モブの有無・数・方向は通常会話で答える

通常BERTが既存のモブ情報分類（Rustの `EnemyInformation`）を返しても、戦闘の定型文へ振り分けず、通常の `player_chat` で一回だけ生成する。受付側と通常会話の拒否条件を一緒に変え、同じ質問を再分類しない。学習済み16分類とIDは当面維持し、ラベルの整理は次の通常BERT教材・再学習時に扱う。危険警告・静粛・世界操作・戦闘中断の判断は従来どおりコードが持つ。

現在視認の種類・個体数・方向は観測できた範囲で渡す。直近の視認と経過時間、音、確定した対話履歴も別々の材料として使う。設定が有効で今回の画像を取得できたときは、その画像に見えるモブを「おるで」と言える。一度一覧から消えただけで不在にせず、直前の視認なら「さっきそこにおったな」、音だけなら聞こえたことを伝えられる。画像なしでも得られた観測と履歴で答える。辞書の一般知識やプレイヤーの報告をドギド自身の目撃に変えない。

将来のMinecraft専用画像分析器の検出は、対応する画像の撮影時刻に結び付け、その一枚で見えたものとして既存の会話材料へ渡す。今回は接続せず、全フレームを解析する処理や追加のモデル呼出しも設けない。

**実機確認:** 「パンダさんもいるかな？」「あれ、さっきいたよね」を続けて試す。画像に写る／視野を外れた直後／音だけ／画像なしを区別し、「いるか」をイルカと取り違えず、過去を現在と断定しないこと。数・方向は既知の観測と照合する。入力から発話開始までの時間と、通常会話の生成一回・定型文の二重配送なしを記録する。

## C. 分類済みの一行編集だけ入力を短くする

対象はBERTが上五・中七・下五の**具体変更**と分類した入力だけ。通常の川柳相談、行指定だけの感想、終了の扱いは変えない。既存の一回の呼出しで `stage_player_edit`（変更後の一行全体）または `ask` を選ぶ。現在の三行・分類済みの対象行・今回の依頼・直前の通常会話とこの句の相談履歴を残し、未採用案や同じ行の相談案があれば渡す。保持していた履歴を削ったり要約したりして入力を短くしない。

この呼出しには、使わない操作の説明や例文、重複した編集指示、元材料と三行分の出典を載せない。記録自体は保存し、読みや出典を尋ねる通常の相談で引き続き参照できる。対象・元句・版・対象外の二行・取消・保存回数は既存の実行処理が管理する。変更後の行が同じなら保存しない。先行再生中の未完成なtool引数を実行しない。

**比較の基準:** 11月2日の上五編集は実測入力6,727トークン、入力処理5.03秒（47トークン生成に0.34秒）。同じ語彙での再構成は6,728、出典だけを除くと5,831、会話履歴を全文残した短縮案は2,541。これは入力長の試算であり、速度の実測値や一律の上限ではない。

**実機確認:** 同じモデル・設定・履歴で「暗闇の絵を暗闇のに」、直前の単一案を受ける「それにして」、複数案から特定できず聞き返す場合を比較する。各回の実入力トークン数・入力処理時間・生成時間・発話開始を記録する。対象行だけが一度保存され、聞き返しでは句も版も変わらないことを、掛け軸・実際の返答・revisionで確かめる。

3. 担当ごとの自動確認の後、上の実機手順をMinecraft・実モデル・必要な実音声で一件ずつ実施する。日時・試した版・実入力・実際の応答と観測・保存結果を残す。実機が使えない、または結果が合わない担当は保留し、模擬試験を実機の代わりに数えない。
4. 実機で確認した差分を親担当が照合し、その担当だけを書類側の main にコミットする。3件をまとめて先に入れない。
