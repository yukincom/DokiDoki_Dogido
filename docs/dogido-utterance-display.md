# ゲーム外のドギド発言履歴・診断ログ

**旧Python版の運用仕様は終了（2026-10-03）。** 発言と参考資料の読み取り表示はRust本体へ移行した。`/dogido` と表示snapshotは引き続き利用できる。発話本文の表示と実再生処理の `completed / cancelled / failed` は区別する。

現行のAPIは [adapter API](adapter-api.md)、所有範囲と起動は [Rust本体](../dogido-rust/README.md)、実機確認は [Rustの実機チェック](../dogido-rust/manual-dialogue-check.md) を参照する。

## 移行前の画面・運用仕様（終了）

以下は移行前の記録。Python版の可変件数設定、診断の名称、待ち列・停止処理を現在のRust仕様として使わない。現行と共通する画面の目的・出典境界は継続するが、下記の「実装済み」は当時の状態を示す。

**状態:** 実装済み  
**入口:** `http://127.0.0.1:5055/dogido`

## 目的

音声は流れて消えるため、ドギドが発言として確定した本文と、その返答対象になったプレイヤー入力をMinecraftとは別の画面に残す。聞き逃した会話を読み返し、引用形式でコピーできるようにする。

同じ画面に、ドギドの判断、LLM、川柳、STT、TTSの診断ログも表示する。固定川柳が選ばれたときに、LLMを利用できなかったのか、生成候補が品質検査を通らなかったのかを切り分けるための画面である。

知識回答で使った機関名・資料名・URLは読み上げず、同じ画面の「参考資料」に分けて表示する。「参考資料」は出典名を示すだけでなく、教科書や公的教材などの実際の文章へ進むための入口として扱う。

## 画面

| 欄 | 内容 |
|---|---|
| 発言 | 新しい順の本文、返答対象のプレイヤー入力、時刻、分類、個別コピー |
| すべてコピー | 保持中の入力と返答を時系列順に空行で区切ってコピー |
| 参考資料 | 機関名、資料名、該当箇所、公式URL、個別コピー |
| 診断ログ | 古い順の運用ログ、時刻、重大度、発生元。末尾追従と全ログコピー |

診断ログは読みやすさを優先して `1.25rem` を既定とし、画面上の「文字を小さく」
「文字を大きく」で、その起動中だけ5段階に調整できる。

コピー結果は各行を `> ` で始める。一件コピーでは、入力がある場合に
`私:` と `ドギド:` を一組にする。全文コピー、参考資料、診断ログも同じ引用形式にする。
音声入力の `私:` には、既知語補正後ではなくSTTが返した原文を残す。

画面は外部CDN、解析サービス、外部フォントを使わない。動的な本文と資料名はHTMLとして解釈せず、文字列として表示する。

## 記録の意味

履歴は、状態機械とserviceが最終的に選んだ発言本文のミラーである。音声が最後までスピーカーから再生されたことを示す記録ではない。

この区別により、危険割り込みで説明が途中終了した場合にも、全文を画面で読める。一方、画面だけを見て「音声再生完了」と判定しない。

## 保存境界

- 発言履歴の既定上限は200件。`DOGIDO_DISPLAY_HISTORY_MAX_ENTRIES` で20〜2000件の範囲に設定できる。
- 診断ログの既定上限は1000件。`DOGIDO_DIAGNOSTIC_HISTORY_MAX_ENTRIES` で100〜10000件の範囲に設定できる。
- プロセス内だけに保持し、サーバー再起動時に消去する。
- 会話記憶、川柳記憶、エピソード評価ログへ読み戻さない。
- 発言履歴には返答対象になったプレイヤー入力だけを含める。Minecraftの観測値と内部プロンプトは含めない。
- 参考資料にはプレイヤー入力を含めない。
- 診断ログには、音声認識結果、入力の正規化結果、処理段階、棄却理由を含める。音声波形、認証情報、内部プロンプトは含めない。
- 一つの文単位音声回答は、分割数にかかわらず一件の発言として表示する。

成功した定常通信のアクセスログは端末と診断画面の両方で省略する。対象は `voice-input/context`、`player-input`、`game-events`、表示snapshot、heartbeatなどの高頻度APIである。同じAPIでも400以上の応答は省略しない。それ以外のドギド判断、LLM、川柳、STT、TTSのログは診断画面へ写す。

音声入力は次の段階を区別して表示する。

- 音声区間の検出
- Whisperへ渡した文脈の種別
- 認識された原文
- Whisperへ渡した区間の無音判定、既知の雑音語、認識失敗などの棄却理由
- サーバーへの配送成功または拒否

2026-09-17: Whisper／Sileroの診断ログにUTF-8として読めないバイトが含まれていても、正常な認識本文・発話判定は受け取る。認識本文自体が文字化けしている場合は `stt_rejected reason=whisper_invalid_utf8` としてその発話を配送せず、次の音声入力へ進む。空結果の再試行とは区別する。不正バイトを出す子プロセスで自動テスト済み。実マイクでの再確認は未実施。

診断HTTPは上限付きの別待ち列へ送り、サーバー応答の遅延を音声認識の
待ち時間へ加えない。満杯なら診断だけを破棄し、音声入力は止めない。

## API

- `GET /dogido`: 読み取り専用HTML
- `GET /api/v1/display/snapshot`: 全セッションの上限付きsnapshot
- `GET /api/v1/display/snapshot?session_id=ses_...`: 指定セッションだけのsnapshot
- `POST /api/v1/voice-input/diagnostics`: 別プロセスの音声入力から認識結果と失敗理由を通知

snapshot取得は短い専用lockだけを使い、LLM処理を直列化するservice workerへ積まない。ブラウザは前の取得が終わってから次を行い、非表示タブでは取得間隔を延ばす。

既存のBearer認証が有効ならsnapshot APIにも同じ認証を適用する。画面のトークン入力はメモリ内だけで使い、URLやlocalStorageへ保存しない。

## 夜の実機確認（10〜15分）

Minecraft画面・マイク・スピーカーを使えるときだけ、次の順で確認する。昼間のコード検査では代替できない、聞こえ方と実際の割り込みを中心に見る。

macOSではTerminal本来の2タブを使う。一方で
`scripts/start_dogido.command server`、もう一方で
`scripts/start_dogido.command voice` を実行する。tmuxや独自のマウス処理は
使わず、Terminal標準のホイール、ドラッグ選択、選択色、`Command+C`を保つ。
停止は `Ctrl+C` とし、停止後は同じタブ・同じシェルで同じコマンドを再実行する。
実行元・Python・プロファイルは `scripts/start_dogido.command --dry-run` で確認できる。
通常起動ではこれらの案内を表示しない。診断画面には絶対パスを出さず、
「通常チェックアウト」または「Codex作業ツリー」、Python環境名、PID、
起動識別子を表示する。

診断画面の「サーバー: 接続中」はブラウザからサーバーへ到達できること、
「Minecraft: 接続中」はFabric adapterの登録後にheartbeatまたはイベントが
直近15秒以内に届いていることを別々に表す。

1. **起動と画面**
   - Terminalの2タブで `scripts/start_dogido.command server` と `scripts/start_dogido.command voice` をそれぞれ実行し、両方のログを確認する。
   - `http://127.0.0.1:5055/dogido` が「接続中」になることを確認する。
   - 診断欄が成功した `game-events`、`player-input`、`voice-input/context` のアクセスログで埋まらないことを確認する。
2. **音声認識の成功**
   - はっきりした短文を一度話す。
   - 診断欄に `capture`、`context`、`stt_result text=...`、`delivery reason=accepted` が順に出ることを確認する。
   - 認識文字列が実際の発話と違う場合は、その行を修正せずそのままコピーして残す。
3. **音声認識の棄却**
   - ごく短い声を一度だけ入れる。
   - 最低発話時間に届かない断片は、雨音などの定常環境音と同様に診断へ表示されず、プレイヤー入力としても配送されないことを確認する。
4. **知識回答の文分割**
   - 「枕詞って何？」のような短い知識質問をする。
   - ドギドが関西弁で短く答え、複数文なら文ごとに間を置いて順番に聞こえることを確認する。
   - 発言欄には分割片ではなく全文が一件だけ表示され、参考資料は本文と別欄に出ることを確認する。
5. **割り込みと古い続きの失効**
   - 複数文の回答をもう一度出し、一文目の途中または文間で危険な状況を発生させる。
   - 警告が先に出て、古い説明の残りが危険解除後に遅れて再生されないことを確認する。
6. **川柳生成と再試行**
   - 通常の発句条件を待ち、診断欄の `haiku_grounding result=round` を確認する。
   - 行が不合格なら、理由つきの次roundと `haiku_line_regeneration` が続くことを確認する。
   - 固定川柳や「まとまらんかった」が続く場合は、直前からの全ログをコピーする。`schema_contract_error`、`generation_error`、内容不合格を同じ原因として扱わない。
7. **終了**
   - 問題があれば「全ログコピー」で保存してから、音声入力、サーバーの順に停止する。

待ち列が満杯になった場合は、`audio_queue_replaced`、`audio_queue_evicted`、`audio_queue_dropped` のいずれかが診断欄に残る。通常の確認で、待ち列を故意に満杯にする必要はない。

## Minecraft内HUDとの関係

[ドギド表示オーバーレイ（Minecraft内UI）計画](dogido-display-overlay-plan.md)とは別機能である。

- 本機能: ゲーム外で読み返す、コピーする、参考資料を確認する。
- Minecraft内HUD: プレイ中に短い字幕をMinecraft画面へ残す将来計画。

サーバーの発話判断はどちらの画面にも移さない。表示は出力の読み取り専用ミラーに限る。
