## 1. いまどこにいるか

軽い気持ちで始めた相棒でも、層としてはすでに **ゲーム内エージェント** に近い。

| 層 | 内容 | おおよそ |
|---|---|---|
| 知覚・文脈 | biome / 持ちもの / 視認 / 音 / 取り合わせ | ある |
| 判断 | 状態機械・いつ詠む・黙る・バトル口調 | ある |
| 生成 | 川柳・雑談・各種 leaf → LLM | ある |
| 対話 | 短履歴 + 句の pin（workshop） | ある |
| 薄い学習 | soft lesson / 明示緩め / TTL（praise は critique 保存のみ） | ある |
| 記憶 | entries / critiques / revisions / 読み訂正 | ある |

**AI を一から訓練しているわけではない。**  
世界を見て → 決め → 喋り → 反応を薄く残す、まで組んである、という意味での「AI を作っている」。

```text
[強い] 状況に反応する・喋る・詠む・戦う口調
[できた] 句を一緒に直す・soft に覚える・雑談の過適合を抑える
[弱い] 世界の取りこぼし / 句の当たり外れ / 「一緒に冒険してる感」の連続
[まだ先] 建造物・景色をちゃんと見る / 深い長期人格
[別軸] 複数ユーザー（世帯）での記憶・呼び名の分離 — [multi-user-tenancy.md](multi-user-tenancy.md)
```

骨格はある。完成度の残りはだいたい:

1. **よく見てる感**（観測の解像度）  
2. **外したあとの立ち直り**（関係を壊さない）  
3. **続きもの感**（薄い連続）

## 2. 「完成」の段階（定義）

機能数ではなく、プレイヤー体感で 3 段階。

| 段階 | 体感 | いま |
|---|---|---|
| **A 相棒β** | 危ないとき・面白いとき・句のときに反応。大外しが減る | 後半〜達成寄り |
| **B 一緒に遊んでる** | 同じ景色を共有。句を一緒に直せる。覚えすぎない | **入口**（ここを固める） |
| **C そのワールドの相棒** | 思い出・建造物・長い旅の話ができる | 先 |

次の完成度の主戦場は **B を固める**。  
手段の優先は **観測 → ログ改善 → 雑談の空気**。機能の山積みではない。

## 3. 完成度が上がる順（おすすめ）

### 3.1 観測の穴を埋める（いちばん効く）

プレイヤーが「見てるだろ」と思うものを materials に載せないと、LLM を賢くしても空振りする。

例:

- 近くの **水・湖・川**（「うみ」問題の本体になりやすい）  
- 旗・地下・LOS・音の正体（既存計画どおり）  
- structure / biome の `note` を haiku・chat に薄く載せる  

**完成度の定義:** 「いまここ」をプレイヤーと同じ解像度で共有している。

「うみ」を固定禁止する、は **やらない**（湖の圧縮・隣バイオームなど、プレイヤー視点では自然なことがある）。  
場の違和感は **プレイヤーが言ったとき** workshop で扱う。固定 drift リスト（旧 H6）は撤回済み。

### 3.2 実プレイ・ログ駆動の改善ループ

機能追加より、外した発話を集めて分類する方が完成に近い。

| 分類 | 打ち手 |
|---|---|
| カタログ・実測には無いが、発話済みの見どころにある | 一次atom・分類・主張範囲を別評価で通した `preface_clause` と、句全体で共有できる `poetic_interpretation` として許可。事実とは別 provenance |
| カタログ・実測にも発話済み見どころにも無い | 候補・scene の取りこぼし |
| 材料はあるのに句が壊れた | 出典・重複・音数のコード検証、低温化、行別失敗理由つき再生成、既出候補の即時棄却（正本は [川柳アーキテクチャ](haiku-architecture.md)） |
| 寒冷地名・気候係数から雨雪を捏造した | 現在Y・気温・降雪高度をコード比較し、数値を伏せた降水・雷・降雪環境だけを共有。積雪は adapter の雪ブロック実測 |
| 地下なのに地表の空・天候・バイオームを詠んだ | 空が見えなければ時刻・天候を句から外し、洞窟固有でないバイオームも外す。周辺ブロック・手持ち・全インベントリから選んだ物を背景情報より先にする |
| 言いすぎ / 被る | クールダウン・モード |
| 無反応 | 観測 or policy |

workshop の critique JSONL は、そのまま改善キューになる（プレイヤーが教師）。

通常の反応は、受理した非重複イベント1件につき `trigger → observation → state_before → decision → action → result` を `.dogido_memory/eval/episodes.jsonl` へ記録する。発話なしも含むため、誤反応だけでなく無反応も同じ集計面で比較できる。支援commandは発行時の `action` と、後続イベントで観測したadapter実結果をcommand IDで相関する。これは会話・川柳の記憶ではなく、runtimeへ読み戻さない評価ログ。詳細は [支援アクションの操縦席 §A](assist-action-architecture.md#a-エピソード-jsonl実装済み)。

### 3.3 川柳は「当たる率」より「外したあとの関係」

H1〜H5.2 で **関係性の側はかなりできた**（pin / 講評 / soft lesson / 緩め / TTL）。

出典不明・材料重複・形式不合格の句は発話前に閉じる。workshop は検証を通った句の好み・表現・場面違和感を扱い、生成品質ゲートの代わりにはしない。

足すなら（任意）:

- AI修正案と、プレイヤー語による連続局所編集、句評価の極性／範囲／根拠抽出、行の曖昧な呼び方を `line_1/2/3` へ対応する常駐会話モデル抽出、pending採否、自然な終了意図のscope／根拠抽出は実装済み。通常workshopでOS AIは先行呼び出しせず、戦闘時の句保持pause中の小分類だけOS AI優先＋chat fallbackとする。次は実ログで評価・行呼称・対象行・読み・自然さ・終了誤判定を見る
- 「前よりマシ？」の短い自己参照（lessons が効いた感）  

**やらない方がいい:**

- 固定禁止語で締め直す  
- revision の few-shot 山盛り  
- strength の複雑な段階（TTL + 明示緩めで足りる）

### 3.4 雑談の「空気」

P1〜P5 で過適合と none 時の相槌は改善済み。現在発話の明示帰宅予定と、地表夕方／雷雨から毎フレーム導出する安全方針も、短期目標メモリを増やさず雑談へ渡す。残り（任意）:

- 同じ話題の連打を避ける  
- 冒険の小さな連続を **1 文だけ**（さっきの洞窟、さっきの句）

### 3.5 人格の連続（薄い長期記憶で十分）

フル人格モデルは不要。効くのは:

- 呼び方・嗜好  
- 「このワールドで一緒に見たこと」をたまに思い出す（haiku recall の一般化）  
- battle / peace のトーン切り替えのキレ  

### 3.6 大きな飛び道具は後回し

| 後でいい | 理由 |
|---|---|
| VLM 常時 | コスト大。イベント駆動の「あれ見て」だけで十分 |
| Vector RAG | 直引きと被りやすい。材料が薄い問題を先に |
| workshop 全域の LLM 制御 | 文脈別の限定 intent / findings / 句評価 / 一行置換 / pending採否 / 終了意図抽出で十分。状態・保存判断まで渡すとノイズ |
| 巨大パッケージ整理（Phase E） | 完成度というより開発者快適さ |

## 4. 本丸（一文）

完成度を上げる本丸は **もっと賢いモデル** ではなく:

> **プレイヤーが見てる世界を、ちゃんと materials に載せ続けること**  
> **外したときは、一緒に直せる関係を壊さないこと**

soft workshop 方針は後半をすでに押さえている。  
前半（観測の解像度）をゆっくり上げるのが、「完成した相棒」にいちばん近い。

---

## 5. 気楽な進め方

締切なし前提。

1. **気が向いたセッションで実プレイ** → 気になった発話を数個メモ  
2. 「観測 / 生成 / ポリシー / 無反応」に分ける  
3. 観測ギャップなら候補を足す。生成ならプロンプト 1 行。関係なら workshop のまま  
4. 機能 PR は気が向いたら 1 本（P5・水辺候補など）

**やらないこと（このガイドの精神）:**

- 機能チェックリスト消化競争  
- プレイヤーなしの完全自動名句を目標にする  
- VLM / RAG を「完成の必須条件」にしない  
- soft lesson を hard 禁止に戻す
