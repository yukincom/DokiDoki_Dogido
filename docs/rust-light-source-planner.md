# 照明コメントの一回生成とRustの判定境界

2026-10-18: `light_source_comment_plan` は、反応の選択とドギドの本文を一回で生成する。別の発話leafとモデル再試行は使わない。

- 入力はコードが許可したaction、段階化した所持量・暗所回復の事実、現在の場所・直近対話。共有人格を使い、`action` と `speech` を返す。正確な所持本数は渡さない。
- モデルは既存会話設定、温度0.48、上限160 tokens、thinking無効。`stay_silent` の本文は空、発話actionの本文は非空とする。confidence・basis_idsの返却は求めない。
- JSON不正・外形不正・生成失敗・出力打切りでは無言にし、同じ入力で生成し直さない。意味や言い回しをコードの語句リストで採点しない。
- 半スタック、現在の暗さ、5分の重複抑止、会話優先、敵の有無、所持数・身体の観測世代は既存Rust処理で確認する。暗所警告の状態変更は現在観測から確定し、所持増加をクラフト・設置と断定しない。
- 返答が戻った時と配送時に現在性を再照合する。生成中に新しい入力・敵・危険な暗さ・所持数変更・身体の観測世代変更があれば、古いコメントを配送しない。通常の移動、明るさ・近くの光源・バイオーム・時間帯の変化だけでは取り消さない。
- 再生開始後は相槌・くしゃみ等の新入力で切らず、返答を現在の台詞の後へ回す。生成中・配送待ちの入力優先、緊急警告・明示停止による取消は維持する。
- 全体上限95秒、取消時のfuture破棄、実配送完了後の履歴確定を維持する。一回分のモデル結果を発話行の `llm_reports` に残す。

単体検証は `light_plan` の一回制約・外形・取消・期限、`environment::ambient::tests` の観測条件を扱う。模擬HTTP検証は `check_environment_runtime.py` で本文の直接配送・呼出回数・生成中の暗所再発を確認する。旧Python比較用の巨大goldenは、新しい契約の動作検証に置き換えた。

検証状況は [モデル呼び出し監査](2026-10-18-dialogue-model-call-audit.md) を参照。実モデル・実Minecraftへの反映とは区別する。
