# 起動管理ツールの分類表示更新（2026-10-25）

川柳8分類と通常対話16分類に合わせ、管理アプリの「対話・分類」を更新した。

## 表示と対応表

- 既存の表示APIから `request_classification.mode` を読み、分類中は行の `classifier_mode` を使う。「分類［川柳］」「分類［通常対話］」を明示する。
- 日本語名と元のラベル名を併記する。色は領域ごとのラベル順に割り当て、川柳内の8色・通常対話内の16色はそれぞれ重複させない。領域をまたぐ色は再利用する。
- 予測確率は各モデルのラベル順で参照する。旧5分類の添字を現在のモデルへ流用しない。ラベル・領域・確率配列の長さが対応しない場合は、確率を推測して表示しない。
- 領域がなかった旧5分類snapshotの既存表示は保持する。本文から領域やラベルを推測せず、本体の分類・操作・保存処理は変更しない。

### 川柳

| ラベル | 日本語表示 |
|---|---|
| `not_target` | 対象外・その他 |
| `senryu_line_upper` | 上五の行指定 |
| `senryu_line_middle` | 中七の行指定 |
| `senryu_line_lower` | 下五の行指定 |
| `senryu_change_upper` | 上五の具体変更 |
| `senryu_change_middle` | 中七の具体変更 |
| `senryu_change_lower` | 下五の具体変更 |

行指定と具体変更は区別する。「上五・中七・下五」は対象行の名前で、音数検査の結果ではない。

## 反映・確認範囲

管理アプリを0.1.3（build 4）へ更新した。ラベル順は本体の `Mode::labels` と採用済み2モデルの `id2label` を参照した。

- ビルドと厳密な署名検証が成功。旧版と同じ署名条件を確認し、書類側の `apps/ドギド サーバー.app` を更新して開き直した。
- 本体が保持している履歴で、通常対話の方向指定と、川柳の行指定・具体変更・終了・対象外が、日本語名・元ラベル・確率付きで表示されることを確認した。
- 管理アプリ更新前後で、本体とマイクのPID・開始時刻は同じ。管理アプリだけを開き直し、既存の対話履歴を読み直した。
- 旧アプリは `.dogido_tools/server-manager/backups/2026-10-25-before-new-labels.app` へ保存した。
- テストの追加・実行や、新たな会話を送る実機試験は行っていない。全24分類を実発話で発生させた確認ではない。

## 分類の二重表示を修正（同日）

受付行と返答行に同じ分類結果が保存されるため、分類バッジが二重に表示されていた。0.1.4（build 5）では、**入力側に分類を残し**、表示中の受付行が `forwarded_input.turn_id` で指す返答行に、同一の分類結果がある場合だけ再表示を省く。返答本文・配送状態・エラーは表示する。

別の入力が同じラベルに分類されても、それぞれ表示する。受付行が表示上限200行の外へ出た場合や、分類結果が異なる場合は、返答行の分類を残す。

更新版を同じ証明書でビルド・署名し、書類側の管理アプリへ反映。本体・マイクのPID、開始時刻、起動コマンドを保持した。旧版は `.dogido_tools/server-manager/backups/2026-10-25-before-single-classification.app` に保存した。自動テストは実行していない。

更新後の既存履歴で、各入力の分類が1回だけ表示され、返答側は本文と配送状態が残ることを管理アプリの画面で確認した。
