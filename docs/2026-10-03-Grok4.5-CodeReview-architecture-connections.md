## A. つながっていない / つながりそう

### A1. Python `state_machine` と Rust `combat` / `environment` — **disconnected**（移行中の **should-connect**）

- Python: `dogido_server/state_machine/`（`DogidoStateMachine` + 巨大 mixin）
- Rust: `dogido-rust/src/combat/`・`environment/`（`docs/rust-migration-plan.md` では戦闘・環境・会話判断は Rust 接続済み）
- 比較用: `scripts/compare_*.py`、`dogido-rust/scripts/compare_*.py`

同じドメイン名で実装が二つある。実行時の正本は **どのサーバーに adapter を向けるか** で分岐する。つながりそうに見えるのは正しいが、現状は意図的な並走。

### A2. 国語対話の「独立試験」と「本体配線」 — **disconnected**

- 独立 CLI / voice_test: docs・`AGENTS.md` に「本体・workshop・音声には未接続」の記述が残る系統
- 本体側: Python `service.py` の `MainLanguageRuntime`、Rust `dialogue/language_runtime.rs`

「国語対話」という同じ名前で、**試験ハーネス**と**本体の限定学習**が別ライフサイクル。触る前にどちらなのかを確認しないと前提がずれる。

### A3. `player_chat_policy`（docs）と `dialogue/chat_policy`（実装） — **disconnected** / docs 化石

- `dogido_server/player_chat_policy.py` は **存在しない**
- 実装は `dogido_server/dialogue/chat_policy.py`
- 一方 `AGENTS.md` は「`player_chat_policy.py` は re-export」と記載したまま

コードの死リンクではなく、**エージェント誘導用 docs の死リンク**。パッケージ移動の中間状態が文書に残っている。

### A4. 反応プロンプト契約の分岐 — **disconnected** / **clash**

同じ `dogido_server/llm/reaction_situations.json` を読むが:

| | Python 反応 leaf | Rust 反応 |
|---|---|---|
| 既定 | `choose_silence=False` → `speech_contract` | 常に `choice_contract` |
| 期待する返し | 素のセリフ | JSON speak/silent |

詳細は follow-up レビュー。ここは「つながりそうなのに契約だけ切れている」代表例。

### A5. 複合構造物認識（橋・飛び石等） — **dead** / **should-connect**（将来）

- `experiments/composite_structure_recognition/`

### D2. `haiku_context` / `dialogue_context` の置き場 — **misplaced**

- `state_machine/haiku_context.py` … 川柳文脈が状態機械パッケージに居座る
- `dogido_server/dialogue_context.py` … ルート直下（`dialogue/` 配下への移動は reorg 文書で任意・未了）

### D3. `hostile_callout` だけ旧 `leaf_dialog` + `/no_think` 形 — **misplaced**（様式の取り残し）

多くの反応は `build_reaction_messages`（共通人格 + 状況 JSON）へ寄っているが、

### D4. 運用ドキュメントの「本体」表記 — **misplaced**

### D5. フェンス除去が haiku にだけある — **misplaced**

`strip_code_fence` は `dogido-rust/src/haiku_response.rs` のみ。  
反応・環境反応・choice 有効チャットが使う `speech_choice::parse` には無い。

「JSON 契約の掃除」は haiku 専用レイヤではなく、**共有 wire 契約側**にあるべき処理に見える。

## E. 処理がぶつかっているところ

### E1. デュアルサーバ 5055 vs 5056 — **clash**

意図的な移行ポート分離。同時起動や adapter 向き先ミスで「動かない／古い挙動」になりやすい。

### E2. `choose_silence` True/False — **clash**

同じ観測でも、素のセリフ経路と JSON speak/silent 経路でパース失敗・fallback 条件が違う。  
出力 follow-up レビューの中核。

### E3. フェンス例示（本番）× フェンス非対応パーサ — **clash**

- 本番 `companion_prompts.json` が \`\`\`json を例示
- prompt_lab 候補は除去済み
- Rust `speech_choice` はフェンス非対応
- Python `clean_output` はフェンス JSON を \`\`\` に潰し得る

誘発と耐性の不一致。

### E4. Python 経路の py_trees + mixin 判断 — **clash**（軽め）

- `py_tree_policy.PyTreeActionPolicy` を `machine.py` が保持
- docs 上は「状態遷移の置き換えではなく出力優先」
- Rust 側は独自優先規則へ移植済みで、**Python 互換経路だけ** tree が残る

二重ゲート。意図的な段階移行だが、Python 経路の読みにくさの一因。

## F. 「こことここはつながりそう」マップ

読みやすさ用の早見。矢印は「データ／契約を共有している／すべき」方向。

```text
companion_prompts.json ──► Python character_mode
                       └──► Rust companion_prompt
                              │
reaction_situations.json ──► Python reaction_prompts ──► speech_contract（既定）
                         └──► Rust reaction_leaf/prompts ──► choice_contract
                                                              │
                                              speech_choice::parse ◄── フェンス耐性なし
                                              haiku_response::strip_code_fence（haikuのみ）

data/fallbacks/* ──► Python fallback/response_catalog
                 └──► Rust combat/environment words

player_chat_planner.py ≈ Rust planner/     （二重・比較で同期）
precipitation.py       ≈ environment/precipitation.rs
sanitize.py            ≈ reaction_leaf/sanitize.rs

Fabric adapter ──► :5055 Python service / state_machine
               └──► :5056 Rust serve-dialogue   ← 同時は衝突しやすい

composite_structure_recognition (experiments/dev_tools) ──✗── 本体未接続
language_dialogue 独立CLI ──一部──► service MainLanguageRuntime / Rust language_runtime
```

## G. 触るときの実務メモ

1. **今動かしているのは 5055 か 5056 か**を先に固定する。  
2. 反応・雑談の不具合は、状況 JSON より **契約（speech vs choice）と fence 耐性**を疑う。  
3. docs の `player_chat_policy` 表記は信用せず `dialogue/chat_policy` を見る。  
4. `experiments/` / 旧 prompt_lab 候補 / 旧教材経路は本番挙動の根拠にしない。  
5. mixin をさらに太らせる変更は、reorg 方針と衝突する（`AGENTS.md`）。
