# Rustの川柳相談prompt

川柳相談の `prepare_details` は、既存の `details_for` が作る材料と、認識原文に基づく `fixed_payload` だけを返す。Rustの `workshop_prompt` が相談のsystem/userメッセージと、契約違反時の再試行文を組み立てる。旧 `prepare` と `consultation_messages` は比較用の互換経路として残す。

現在句・未採用案・相談中の案、認識原文と会話用解釈の差、会話段階、実検査結果、検査後の返答制限を含む11条件は従来と同じ。JSONは既存のPython互換serializerを使い、許可リストの順序と重複も維持する。固定編集がある場合は、従来どおり契約再試行の追加文を付けない。

材料の投影、意味・evidence検証、読み・音数の実検査、編集のCASは既存の担当に残る。この変更でモデル呼出・辞書初期化・helper数は増えない。会話モデル、420 token、温度0.25、契約再試行の最大2回、初手・実検査・修正検証の段階上限は変更しない。既存helperの15秒交換上限とturn全体95秒の取消・回収も維持する。Rustで作るpromptにも従来の応答サイズ上限を適用する。不正な投影や旧messages応答を成功fallbackへ変換しない。

検証は、Python正本由来の580投影例と90純粋例の全文比較、投影専用経路でのPython prompt再呼出禁止、原文に基づく固定編集・終了検証、サイズ上限、mock helperでの再利用・互換性エラー・取消・期限・実子回収を含む。長文のgoldenは共通文字列を参照して保存し、比較時に全文へ復元する。実モデル・実音声・Minecraftでの確認は別途必要。
