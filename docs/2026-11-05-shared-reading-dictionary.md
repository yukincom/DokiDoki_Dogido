# 家庭内LANでの読み辞書共有

Mac Studioを読み辞書の正本にし、遊ぶMacは取得した辞書を閲覧・利用する。既存の本体の辞書画面と、本棚の「あんちょこ」を編集入口として使う。

## 保存と権限

- 親は通常の設定から解決した `memory_dir/long_term/catalog_corrections.jsonl` を使う。既存の追加・変更・削除と版照合を維持する。
- 子は同じ `memory_dir` 内の `long_term/shared_readings.json` に、登録済みの親の鍵印と現在有効な読みを保存する。このファイルがある保存先は読み辞書だけを閲覧専用にし、本体・本棚・共通保存処理で編集を拒否する。句・写真などの編集権限は変えない。
- 同期ファイルは全体を検証して原子的に置換する。追加・変更に加え、空の辞書を含む削除も反映する。既存の子の個人辞書JSONLは移動・削除・親へ統合しない。
- 共有する項目は `id / surface / reading / wrong_reading / forbidden_readings / source`。会話記憶・句・セッション情報は送らない。

## 接続と反映

既存のBonjour発見・双方承認済みHTTPS接続で `GET /dogido/readings` を取得する。編集用のLAN APIは設けない。親の共有アプリは通常の設定とRustの正本readerを使うため、Minecraftや本体サーバーが停止中でも本棚で保存した変更を共有できる。

子の一括起動が本体と同じ保存先を接続係へ渡す。接続係は本体の開始前に閲覧専用の複製を準備し、約10秒ごとに全体を取得する。次の読み込みから既存の読み上げ・生成の補正処理へ渡す。表示中の辞書一覧は再読み込みで更新する。

切断・親SSD不在・不正な応答・保存失敗では最後の有効な複製を保つ。親の保存先不在を空の辞書に読み替えない。別の親へ登録し直したときは古い親の辞書を使わず、新しい親から取得する。壊れた同期ファイルを個人辞書への編集許可には読み替えない。

## 確認状況

2026-11-05に実装し、Mac Studioの共有アプリ・書類側本体、遊ぶMacの既存アプリ・kitへ反映した。アプリは両方とも署名と配置内容を照合した。起動中のアプリは停止・再起動していないため、共有側と遊ぶ側を開き直してから新しい同期を使う。

- Rustの読み関連試験44件成功。共通保存入口の編集禁止、両HTTP APIの403、既存の読み補正を確認。実VOICEVOX・スピーカーを使う1件は明示skip。
- Python64件成功。隔離したTLS接続、追加・変更・空辞書による削除、失敗後の保持、別の親、壊れた複製、アプリの同梱と起動配線を確認。
- JavaScript16件成功。実JSと模擬DOMで、親の編集・保存と子の閲覧専用表示、句の選択が継続することを確認。
- releaseビルド成功。親の実際の辞書18件を読み取り専用で書き出せることを確認し、元の辞書は変更していない。
- 実ブラウザーの表示確認は、本棚のアクセス制御から403が返り未完了。制限を緩めず、一時サーバーは終了した。更新後の2台間同期・実Minecraft・実スピーカーの確認は再起動後に残る。
