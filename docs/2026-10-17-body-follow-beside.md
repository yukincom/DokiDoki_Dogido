# 普段の追従も一度隣まで来る

後継: [0.7.5の修正](2026-10-17-body-call-release-floating.md)でCALLの到着保持を撤去し、通常移動・待機も穏やかな上下波へ変更。以下は0.7.4時点の記録。

日付: 2026-10-17
状態: 身体Mod 0.7.4の実装済み。全122件成功（失敗・除外0）と配布ビルドを確認済み。Minecraft終了確認後に導入済み。実ゲーム確認は未完了。

## 変更理由

ユーザーの「普段ついてきている時も遠巻きすぎる。距離ができたら一旦隣まで来てほしい」という指摘に対応する。0.7.3の通常FOLLOWは16block超で開始し、14block以内で停止していた。

音声で呼んだ場合は別の未接続箇所がある。同日04:43の「どぎど私の隣においで」は稼働サーバーの記録で`recall_mount`へ分類され、動物選択の会話が「了解や！すぐ行くで！」と返した。身体CALLは発行されていない。音声の`dogido_recall`は別チャットで学習候補を収集中であり、今回の修正対象は通常FOLLOWの実移動。

## 動作

- 追従開始は従来どおり3次元の距離16block超。一度始めたら14blockや5blockまで近づいても続ける。
- 既存の呼び寄せ用立ち位置を共有し、横／後ろの近い安全候補を選ぶ。既定の目標水平距離は1.75block。現在の目線付近の目標から0.2block以内、かつownerとの水平距離2block以内へ実際に到着したら待機する。
- 目標は毎tickの現在owner位置へ平行移動し、しゃがむなどの目線高さの変化も反映する。元の座標へ到着しただけでは追従を終えない。
- 非作業時はカメラ回転だけで周回しない。そのため選択後にplayerが振り向けば、到着位置が視線の正面になる場合はある。採掘中・作業観測なし／期限切れでは既存の作業正面回避を使い、横／後ろを選び直して正面を横切らずに寄る。
- 追いついた後は通常の待機・見回し・観察選択へ戻る。常に2blockを保つ密着追従にはしない。
- 敵・攻撃経路・生体衝突・危険物・読み込み範囲の検査は既存処理を通す。安全な隣位置が見つからない間は未到着のまま待ち、危険回避の終了後も接近を続ける。
- 24block超の距離ワープと次元移動は、3〜11blockの安全着地点へ移った後に隣への接近を再開する。同じ生存ownerが次元移動待ちの間に元の世界へ戻った場合も、未到着状態を引き継ぐ。死亡・切断・owner交代・明示mode変更では破棄する。
- 追従途中の観察MOVE_TOは受け付けない。CALLを受けた場合はCALL側の現在位置・作業観測・期限・到着確認を使う。
- `follow_distance`の調整は開始距離だけを変える。通常FOLLOWの到着上限は2block。呼び寄せの`call_distance`は従来どおり独立する。

## 検証と導入

- Body API v7は継続。adapter・Rust・分類器・プロンプトの変更はない。
- 自動検査は、14blockを通過して隣へ実移動すること、player衝突と浮遊揺れ、現在位置・目線高さ、カメラ回転、採掘正面の迂回、安全候補の再選択、危険優先、ワープ後の追従再開を確認する。
- Javaの移動検査とコードレビューは、Minecraft実機の描画・次元転送そのものの確認とは分ける。
- 変更前のHEAD・差分・対象ファイルと今回だけの差分は`.dogido_tools/checkpoints/2026-10-17-follow-beside/`へ保持する。別作業の未コミット変更を含めたコミットは作らない。

実機確認は、開けた場所で16blockを超えて離れ、追いかけ始めてからさらに少し歩き、現在の隣まで寄ることを確認する。遠距離ワープ後・採掘中も確認する。音声経路と切り分けて明示CALLを試す場合は`/dogidobody call`を使う。

配布ファイルは`animation/cube_dogido/cube-dogido-lab/build/libs/cube-dogido-lab-0.7.4.jar`。SHA-256は`4d6ad794792d3df58a805a48354a646dbbe46b7409dacd4189c1cae964fb4aca`。既存0.7.3との公開APIクラス37個の一致を確認し、現在のadapterを継続できる。

Minecraftの終了を2回確認して0.7.4を配置し、配置先のSHA-256と旧0.7.3の退避先を再照合した。adapterは変更していない。導入記録は上記チェックポイントの`installed.json`、旧版は`mods/`にある。ゲーム・常駐サーバーの停止や再起動は行っていない。
