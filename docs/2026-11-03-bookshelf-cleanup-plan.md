# 本棚の試験データ・未成立の発句・旧ビルドの清掃計画

2026-11-03。書類側mainの本体、本棚のSSD正本、Minecraftの撮影・接続ログ、発句ログを読み取り照合した。**これは実行前の計画**。ここに記す件数は調査時点のもの。新しいプレイ記録を削除対象に加えない。画像の紐付けや内部表現の自動整理は、既存データの清掃と分けて後で実装する。

## 1. 何を消し、何を残すか

| 対象 | 処置と根拠 |
|---|---|
| SSDの旅100件 | **試験81件を削除し、Minecraftの接続IDまで一致した実プレイ19件を残す**。81件は模擬接続の記録・台本・短い接続時間と照合済み。名前が「試験」かどうかだけでは選ばない。途中保存は同じ旅IDへの上書きなので、似た本文を理由に別の旅を消さない。 |
| SSDのセッション80フォルダ | 試験旅とセッションIDが一致する7フォルダは各1行の短期戦闘記録だけで、句・編集・メモ等からの参照はない。これらも削除する。実接続の66フォルダ、由来未確定の7フォルダは保持する。未確定のうち1つには本棚登録済みの11句があり、他の6つも短文というだけでは試験と断定しない。 |

| 未登録の川柳写真14枚 | 14枚とも撮影ジョブを特定。10回は取消、4回は生成不成立で、対応する完成句は0。本人が別途貼った写真でないことも直前に確認し、`unlinked-poem-images` 内の該当PNGと付随する移行用JSONを削除する。近い時刻の別の句には貼らない。一般のスクリーンショットは対象外。 |

削除候補の各要求は、`hidden.f32` とその要求のマニフェストを一組として扱う。受箱そのもの、共通の `_identities`、モデルが使うMac側の採取先リンクは残す。単発試験のうち1件は過去のJ-lens精度検証の元数値で、削除するとその**同じ数値での再計測**はできなくなる。保存句のJ-lens候補・訳・検証結果・設定は残す。隔離試験で完成した句の3要求は、試験専用の記録と依存を確認し、残す記録が参照切れを起こす場合は一式で整理するか保留し、本棚へ付け替えない。

## 2. 自動テストの保存先を分離する

**AGENTS.mdには原則を短く書き、実際の強制はテストの共通起動処理で行う。** 次の文を「作業範囲と完了報告」のテスト配置ルール付近に追加する案：

> 自動テスト・模擬接続は試験ごとの一時ディレクトリを使う。旅、句、短期記録、本棚台帳、画像、内部表現、評価ログを個人のSSD・Minecraft・本体の既定保存先に書かない。保存先を隔離できない試験は起動しない。

- [模擬サーバーの共通起動](../dogido-rust/tests/python/check_dialogue.py)で、試験用の親ディレクトリを作って `memory_dir` 等を明示し、明示された上書き先もその配下に限る。パスを解決して、シンボリックリンク経由でも本番へ出ないことを確認する。引数省略・異常終了時にも既定の本体フォルダへ戻さない。
- 親から本番保存先やSSDの識別設定（`DOGIDO_ACTIVE_PRIMARY_ROOT` / `ID`）、写真・採取先、`DOGIDO_EPISODE_MEMORY_DIR` を持ち込まない。子プロセスに渡す保存先を試験用に組み立て、本棚の写真庫、撮影元、評価ログにも適用する。SSD運用の試験だけは一時フォルダ内に模擬保管庫を作る。
- 共通関数を通らないRust/Pythonの模擬起動、サンプル、試験用の本棚・Fabric経路も確認する。通常の自動試験は模擬モデル・採取なし。内部表現の採取を試す場合は、**モデル側も**一時採取先を使う専用の接続先にする。Rust側だけ変更して常用モデルの受箱に書かせない。これらは試験側の変更とし、実プレイの保存先・発句・会話は変えない。

## 3. 清掃の実行順

1. 先に試験の保存先を分離して、一時データで確認する。本番での清掃を練習台にしない。修正前に試験を走らせる場合も、元の本番設定を渡さない。
2. 実行時にSSDの保管庫IDを確認し、削除候補を個別に列挙した**ローカル専用の照合表**を作る。種別、相対パス、旅・セッション・句・撮影ジョブ・モデル応答などのID、理由、サイズ、ハッシュ、参照元を記録する。保持側も句・編集・旅・メモ・写真配置・使用中の内部表現について基準を取る。個人のID、対話本文、画像、数値ファイルはGitに入れない。
3. プレイや採取、非同期の句保存、本棚の保全書込みが終わった静止点で、照合表を再確認する。`complete` はモデルの1要求が終わった印で、句の保存完了とは限らない。当初の固定IDに限り処理し、増えたもの・変わったもの・他で参照されるもの・SSD切断や保存失敗は保留する。
4. 旅・セッション、画像、内部表現を別々に処理する。旧パスと戻し先を記録して、同じボリューム内の本棚が読まない作業場所に候補を一時移動する。起動時に自動再登録されないことと保持側の読み戻しを確認してから、その候補だけを削除して空き容量を測る。照合不一致なら削除せず、移動したものを元のパスへ戻す。空になった日時フォルダのみ整理する。
5. 今後、本当に誤結合が見つかった場合は、撮影命令の句IDまたは同じセッションの発句ジョブから保存句まで追跡し、画像ハッシュ・既存の配置と整合するときだけ修正する。自動撮影の紐付けと、本人が手動で貼った写真・図鑑での再利用は別扱いにする。現在の34枚にはこの修正を適用しない。

| MinecraftのModバックアップ3か所 | ドギド関係の旧JARは9個（約6.6 MB）。個々のMod ID・ハッシュ・由来、配布・復旧手順や明示保持の記録を照合し、参照のない旧コピーを削除する。Minecraftのワールドバックアップは対象外。 |
| 書類側 `dogido-rust/target` | 調査時はdebug約72 GiB（うち依存・試験バイナリ類約57 GiB、増分キャッシュ約14 GiB）。ここが主な容量回収候補。実行中のCargo・テスト・他担当の使用がない時間に、再生成可能なdebug成果物を整理する。**releaseは丸ごと消さない**。本体・音声workerはここから稼働し、相談室・配布もreleaseを参照する。debugを整理した場合、次の開発テストでは再ビルドが必要。 |

| `.dogido_tools` の採取物・チェックポイント | 試験専用のGGUF・MLX採取物は、試験結果・fixture・復旧手順から参照されないものだけ整理する。公開プレビュー、研究用Git書き出し、意図して保持したJAR、チェックポイント、評価の根拠ログは「古い」だけで消さない。特に研究用書き出し内の70要求は個人棚の数値と同内容だが、独立した研究成果としてこの清掃から除外する。 |

| 不成立・取消時の整理（将来のコード） | 一時保管庫で「同時刻に近い別ジョブ」「取消直後に次の句が成功」「保存や保全に失敗」「まだ採取・保存中」を試す。成功分は元ジョブの句だけに結合。終了が確定した失敗ジョブの専有物だけ整理。出自不明・保存未確定・SSD切断は保持する。画像・内部表現のこのコード変更は**今回まだ行わない**。 |

## 6. 実行結果

2026-11-03、保存先の隔離後に清掃を実施した。恒久的なコード変更は自動試験の保存先と試験用設定に限定した。画像の紐付け処理と内部表現の自動削除処理は今後の作業として残る。

- Pythonの共通模擬起動は記憶・撮影・採取・評価ログ・HOMEを一時領域へ向け、親の本番設定を除外する。外部保存先、外へ出るシンボリックリンク、追加引数による保存設定の上書きは起動前に拒否する。Rust単体試験の既定記憶先も試験ごとの一時領域へ変更した。AGENTS.mdへ同じ運用方針を明記した。
- SSDの試験旅81件・関連短期記録7件、Macに別に残っていた試験旅1件・評価ログのfixture 1,843行を削除した。会話プレビュー1,358行は元の順序と内容で残した。
- 未登録画像14枚、内部表現29要求と、それらのうち3要求を参照する隔離試験専用の句記録2ファイルを削除した。29要求の数値は合計920,494,080 B。既存の登録画像には誤結合がなく、貼り直しは0件。
- 現用Mod・配布JAR・releaseをハッシュで保護し、旧JAR9本と未使用のビルド8か所を削除した。ビルドの割当容量は合計100.815 GiB。削除処理の前後でMacの空き容量は94,395,801,600 B（約87.9 GiB）増えた。これらの値は同時刻の他プロセスのディスク利用も受ける。
- 隔離の回帰テスト10件、既存Rustテスト8件、撮影の模擬確認17項目、内部表現採取の模擬確認6項目が通った。本体と相談室のreleaseビルド、通常起動の本体・音声設定チェックも通った。
- 削除前と削除後の両方で、通常の本棚APIから131句すべてが編集可能、実プレイ19旅の全文が一致、登録写真34枚の実バイトのハッシュが一致、内部表現70要求のマニフェストを読めることを確認した。個人の句・旅・台帳・設定と保存ファイルも直接照合した。
- 本体・音声入力・本棚を通常の書類側の入口で再起動した。Minecraft実プレイ、実LLMの生成、マイクからの発話・スピーカー再生は今回の検証には含めていない。

個別の削除ID・パス・復元用の照合表はローカル専用に保管し、この文書へ含めていない。
