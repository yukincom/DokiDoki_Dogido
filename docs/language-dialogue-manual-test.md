# あなたが操作する、ドギド独立テキスト試験

**状態: 終了（2026-10-03）—旧Pythonの独立テキスト試験ランチャーの運用。**

以下の台本・結果は当時の試験記録として保持します。記載されたPython CLI・ランチャーは現在の起動手順ではありません。本体の国語・Webの判断はRustへ接続済みで、現行入口は [Rust本体](../dogido-rust/README.md)、会話・音声の確認は [実機チェック](../dogido-rust/manual-dialogue-check.md)、契約は [本体会話統合](main-dialogue-integration.md) が後継です。旧試験の成功を、Rust変更後の実Minecraft・実音声の確認済みとは扱いません。

**音声・STT・自己音の試験は [独立音声テスト](language-dialogue-voice-test.md) を使う。この台本・ランチャーは文字入力専用。**

2026-09-09作成。これは**手動入力用の台本**。台本や正解をモデルへまとめて渡さず、各行をあなたが入力する。
ドギドの返答が出て、`あなた >` に戻ってから次の行へ進む。全文を一括で貼り付けない。

## 起動

リポジトリのルートから、ターミナルで実行する。

```bash
zsh dev_tools/language_dialogue/start_language_web_test.command
```

既存のローカル会話モデルを使い、実際のGoogle Chromeにつながる `--web --interactive` で起動する。
モデルの読み込み後に `あなた >` が出れば入力開始。Chromeは最初から開かず、Webへの同意と模擬音声完了の後に開く。
普段のChromeとは別の専用プロフィール。ログイン状態も共有しない。
モデル・依存の自動導入、サーバー起動、Minecraft起動、録音・TTS再生はしない。

準備だけ見る場合は `zsh dev_tools/language_dialogue/start_language_web_test.command --check`。
これはローカルの依存・設定・実行ファイルの確認であり、モデルの実ロードやChrome実接続を検証するものではない。

今回手動で試すのは**国語・言葉の理解、Webへの同意、Google AI概要の取得と対話への引き継ぎ、中断・復帰**。
AEC、実音声の聞き取り、実ゲームの前面検知、戦闘・川柳編集は、このテキスト試験では確認できない。

## 1. 資料で答えられる質問と、直前の話の保持

1行ずつ入力する。

```text
「きょう」は何音？
じゃあ、「きょ」だけなら何音？
さっきの「きょう」と、どこが違うの？
/cancel
「三」という漢字は何年生で習うの？
```

見るところ：2音／1音を混同しない。「三」は小学1年。
直前の対象を取り違えず、資料で答えられる質問で不要なWeb同意へ進まないか。
誤答や不要検索が出たら、文面を言い換えて成功させる前に、そのまま記録する。

## 2. 曖昧な言い方を確認してから説明する

```text
/cancel
本があついって、どういう意味？
ページがたくさんあって、ぶあついっていう意味だよ。
じゃあ、熱いお茶の「あつい」と同じなの？
```

見るところ：最初から「熱い」「厚い」を決めつけず、必要な確認をするか。
こちらの説明後は「厚い」を扱い、後の「熱い」と比較できるか。意味説明の正しさも読む。
Web同意の質問へ進んでしまった場合は「やめとく」と返してから次へ。

## 3. 普通のゲームの話を、国語質問にせず通常会話へ渡す

```text
/cancel
石炭を見つけたよ。これを掘ってから家に帰ろう。
```

見るところ：国語解説や検索を始めず、既存 `player_chat` の短い関西弁で返すか。
この独立試験にはMinecraftの現在観測がないので、石炭を実際に見た、現在地が洞窟だ、所持品がある、という事実を勝手に足さない。実操作は本体未接続の範囲で行わない。

## 4. Webを断る／条件付きの返事では開かない

```text
/cancel
金床って、なんで「かなとこ」って読むの？ 調べてみて。
やめとく
/speech-completed
```

見るところ：Web同意を尋ねた後、断れば開かない。後から完了通知を送っても開かない。

続けて条件付きの返事も試す。

```text
/cancel
金床の読み方の由来を調べてみて。
安全なら開いてもいいけど、まだちょっと迷ってる。
/speech-completed
やめとく
```

見るところ：条件付きの返事を勝手に承諾へ変えず、再確認する。この段階でもChromeを開かない。

## 5. 同意した後でも撤回できる

```text
/cancel
金床の読み方の由来を調べてみて。
ええで
開かないで
/speech-completed
```

見るところ：「ええで」の後に「ほな一緒にいこか！」が出るが、まだ開かない。
撤回したら古い完了通知は無効。`stale_playback` 等で終わり、新しいタブが増えない。

## 6. 案内音声が失敗・中断したら開かない

```text
/cancel
金床の読み方の由来を調べてみて。
ええで
/speech-failed
/speech-completed
```

見るところ：模擬音声失敗の後に完了を送っても開かない。
同じ手順で `/speech-failed` を `/speech-cancelled` に変えると、模擬再生中止も試せる。
これは音声配送の制御試験で、実際には何も読み上げない。

## 7. 優先割込みと再開

```text
/cancel
金床の読み方の由来を調べてみて。
ええで
/interrupt
/speech-completed
今は話せる？
/release
/speech-completed
/cancel
「きょう」は何音？
```

見るところ：割込み中は `paused` 等で待ち、検索しない。`/release` だけでは勝手に喋らない。
割込み前のWeb起動権限が復活しない。新しい通常入力ではまた対話できる。
この操作は返答と返答の間に入力するもの。生成中に即時中断するUIではない（停止はCtrl+C）。

## 8. 実Chromeで調べる本線

ここから実際にGoogleへ質問を送る。個人情報を含む質問は使わない。
テキスト試験なので、音声の正常終了だけは `/speech-completed` であなたが明示する。

```text
/cancel
金床って、なんで「かなとこ」って読むの？ 調べてみて。
ええで
```

**ここで一度止まる。**「ほな一緒にいこか！」が出ても、まだ検索していないことを確認する。
準備ができたら次の1行を入力。

```text
/speech-completed
```

見るところ：専用の実ChromeにGoogle検索が開く。検索文は、質問を
「キッズに聞かれてんねん」「geminiはん、…教えてやってくれへんか？」という依頼文で包んだもの。
Geminiアプリ自体を操作する機能ではなく、**Google検索のAIによる概要**を使う。

Chromeを見て、AI概要が完成したか、普通の検索結果だけかを確認する。
初回の概要読み取り要求は15秒目の1回で、その処理内で本文の安定も確認する。必ず15秒で終わるという意味ではない。未完成でも同じタブの自動再取得はしない。
概要がなかったり未完成でも、それを「読めた」と扱わないかを見る。

**ロボット確認／CAPTCHAが出たら、その回のWeb試験はそこで終了。**
同じ質問を連打したり、再起動して再検索を繰り返したりしない。回避する試験ではない。
`/quit` で終え、画面に出た状況を知らせる。

## 9. 戻って、同じ概要をもとに話す

ケース8でページを開けた場合だけ続ける。最初に次を入力して「ゲームから離れた」を模擬する。

```text
/minecraft-away
```

Chromeで実際に表示された内容を読む。別ページへ進むと、その内容は自動追跡されないので、今回は同じ検索タブで試す。
読み終えたらターミナルへ戻り、次を入力する。実Minecraftを起動する必要はない。

```text
/minecraft-active
```

見るところ：「おかえり！ どうやった？」が先に出る。
初回に概要が取れていなかった場合だけ、同じ検索タブを一度再読する。別タブや新しい検索は増やさない。

次は**画面に実際にあった内容**を1つ、自分の言葉で入力する。以下は形の例なので、内容を置き換える。

```text
読んできたよ。概要には「ここを実際の説明に置き換える」って書いてあった。
今の説明のうち、どこがその話につながってるの？
ちょっと難しい。もう少しやさしく言って。
```

見るところ：同じ概要と直前の会話を踏まえて返すか。取得できていない内容や由来を作らないか。
実際に読んだAI概要とドギドの説明の一致を見る。引用が一致しても、意味が正しいとは限らない。

まだ引っかかる場合の対話も試す。

```text
まだちょっと、もやっとするなあ。
もう少し一緒に考えたい。
わかった。いったん冒険に戻ろう。
```

見るところ：納得したことを勝手に決めず、続けたい意思を尊重する。最後の明示復帰は `handoff`／通常モードへ。
再び `/minecraft-active` を入力しても、終わった調査への歓迎を繰り返さないか確認する。

## 終了と知らせてほしいこと

```text
/quit
```

試験の専用Chrome/MCP接続が終了する。普段のChromeは終了しない。
開始時に表示した `logs/language-dialogue/manual-web-日時-PID/` に、`transcript.md`、`turns.jsonl`、`run.json` を残す。
ログには入力・応答・取得した概要本文等が入る。実在する子どもの個人情報や機密事項は入力しない。

報告は「ケース番号／入力した文／ドギドの返答／Chromeで起きたこと／気になった点」で十分。
成功したことに合わせて文章を直す必要はない。違和感もそのまま残す。

任意で時間切れも試せる：Web同意待ちで5分以上入力せず、古い続行・完了を送っても検索しないか。
読書中の文脈は別に30分の期限を持つため、同じ5分試験と混同しない。
同時入力のbusy・重複イベントID・不正JSONはこの手入力UIでは再現しにくく、自動試験側の範囲。

AECを後で実マイクで試す際の短い文：**「石炭」「うん」「いいね」「ちょっと待って」「今の説明をもう一度お願い」**。
ただし、この起動方法ではマイクを使わないため、AECの合否は出ない。[別の実音声試験](voice-echo-cancellation.md)を参照。
