# 身体から見たものを対話と次の川柳に渡す（2026-11-03）

[通常起動と実機の確認手順](../dev_tools/実機確認_20261102/手順.md)。11月2日のA〜F統合版を11月3日に本線へ採用した。Minecraftでの体験は本人確認待ち。

- 原木・板・羊毛・石炭・雪を探す「周辺資源」と、落下物の専用一覧をFabricとRustから外した。一般のブロック視認、＋の一点、画像、実音、匂い、ホットバーはそれぞれ元の出典を保つ。雪ブロックが見えても降雪とはしない。モデルが多数の観測を自分で選別できるようになれば、外した一覧を再検討する。
- 混雑や走査の一部失敗だけで感覚を一式取り下げない。身体の視界・プレイヤーの位置は専用の身体観測に残す。敵・非敵対モブへ先に視線を配り、天候・バイオームを確保し、収まる実音・地形・匂いを残す。途中までの一覧には部分取得の印を付ける。同じ身体・世界が確かめられないときは現在値を補わない。
- 地点の降水は、ドギド地点のバイオーム、ワールドの天候・次元、必要な地点ではドギドの足元の高さから、雨／雪／降水なし／不明に決める。屋根や木の葉で濡れないこと、地面に積雪があることは別の事実。
- ドギド自身の視認が通ったブロックを一地点ずつ種類別に数え、少ない順に最大2種類の表示名を「今いる場所にある少し特別なもの」として通常会話・環境反応に渡す。同数は種類ID順、1種類なら1件。視認が途中のときや件数のない旧観測から順位は作らない。
- 混雑時はこのブロック欄を丸ごと省く。基準は話題で絞る前の個体状態・モブ種類・ブロック種類・音の合計が20行を超えたとき。種類表の欠測時や身体の送信枠を超えたときにも候補を省く。種類の全一覧と直前の差分は内部の比較に使い、対話には載せない。＋の対象や身体の操作候補はそれぞれの用途で扱う。混雑時のモブは個体・種類各8、音は4まで。
- 添付する新しい側の画像と、同じ返答の観測・視認変化の時間差を秒で示す。移動・旋回も直近の一回分を短く表す。撮影後にプレイヤーが動いても画像を捨てず、写った時点の事実として渡す。
- 体の操作が可能な通常会話では、同じ返答で「そばへ行く／留まる」を選ぶ。移動は既存の呼び寄せで、受付を到着とは言わない。遅い入力・別の世代や別の身体へは適用しない。
- ＋で示した実物は従来の向き直りを使う。向き直りが成功し、ドギドの眼から同じ個体・同じ位置のブロックへ視線が通ったときだけ、その表示名を最新一件保持する。次の発句に一度だけ過去の共同体験として提示し、句に採用するかはモデルが決める。聞こえただけ・指しただけ・同種の別個体では共同視認にしない。

**Minecraftで見る場面**

1. ドギドの左前で少し離れ、視野から出る。直前の緑枠と現在の位置を混同せず、見えていない相棒の居場所を取り違えないか。
2. 安全な場所で「一緒に行こ」と話す。そばへ行く選択なら実際に移動し、留まる選択ならその場に残るか。到着を言う時刻も見比べる。
3. ＋で羊か落ちている物を示して「あれ見て」。実際に振り向き、自分の眼から見えたあと、次の川柳の候補に一度だけ残るか。壁で遮った場合も試す。必ず羊を詠むことは合格条件にしない。
4. 石の多い場所で、ドギドから見える位置にポピーとタンポポを少しずつ置く。通常のモデル入力には花の表示名だけが載るか、多種類のブロック・モブで混雑すると欄が消えるかを見比べる。


**実機前の確認**

- Fabricの自動試験354件が通過。Rustのライブラリ全体は985件通過、26件失敗、2件無視。失敗した26件は変更前の統合版と同じテスト。別の川柳準備の統合試験でも2件が変更前から失敗している。
- 個数順の選択と、身体の模擬観測から通常会話・環境反応の実際のモデル入力までを確認。普段は2種類、ブロック・モブが多い場面と順位未取得の場面では0件。
- 場所・天候の統合試験7件が通過。模擬接続では本文の生成を遅らせても接近命令が先に届き、待機・取消時には接近しないことを確認した。
- 普段のGGUFへの文章入力では「いっしょに行こ、こっち来て！」に接近、「そこで待ってて。」に待機を選んだ。この2例はMinecraftへ命令を送っていない。画面に映る振り向き・実移動・次の一句は実機確認の対象。
