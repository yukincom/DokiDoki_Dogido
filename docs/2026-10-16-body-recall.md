# 身体の呼び寄せ・立ち位置・FOLLOW開始

後継: 通常FOLLOWの停止距離は[0.7.4の修正](2026-10-17-body-follow-beside.md)で隣まで接近する形へ変更。CALLの到着保持は[0.7.5の修正](2026-10-17-body-call-release-floating.md)で撤去し、到着後すぐ通常動作へ戻す。以下の16/14block・20tick/100tick・導入版は0.7.3当時の記録。

日付: 2026-10-16
状態: 0.7.3 / Body API v7の実装済み。身体117件・adapter184件の検査とビルド済み。Minecraft終了確認後に身体Modと対応adapterを導入済み。ゲーム内確認は未完了。

## 今回の範囲

既存の`/dogidobody call`とCALL移動を拡張する。通常の距離FOLLOWは16block超で開始・14block以内で停止、24block超で安全な場所へのワープを試す従来の設定を維持する。

| 場面 | 動作 |
|---|---|
| 所有する身体が読込み済み | その個体を呼ぶ。ローカルFOLLOWを開始し、現在のownerへ接近する |
| 所有登録なし、8block以内の未所有個体が一体 | その個体を既存bind処理で登録して呼ぶ |
| 所有登録なし、近くに未所有個体なし | 安全な位置に一体生成・登録し、END_RODパーティクルを出す |
| 所有台帳あり、個体が未ロード | 新しい個体を作らず`body_chunk_not_loaded`。現在の台帳はUUIDだけであり、未ロード個体のチャンクを強制読込みする機能は含まない |
| 未所有候補が複数 | `multiple_unbound_bodies`。既存bindコマンドで一体を指定する |
| DOWNED・所有者不在・安全位置なし | 既存個体を置き換えず失敗／待機を返す |

生成・登録は論理サーバーの同じスレッドで実行する。生成失敗時は今回の個体とそのUUIDの所有登録だけを取り消す。出現演出は生成成功後だけであり、接近完了の証拠ではない。

## 呼ばれた後の立ち位置

- 既定の水平距離上限は2block。目標は1.75block、到着許容は0.2blockにし、上限の内側へ寄る。
- 通常は現在の視線の正面を優先。塞がれていれば斜め・横・後ろから安全な候補を探す。
- 採掘中は横・後ろだけを候補にし、接近中も正面を横切る経路を避ける。高さは従来の目線付近を基準に、上下の空きも確認する。
- 呼ばれた瞬間の座標へ固定せず、毎server tickで現在位置・向き・作業情報から目標を選び直す。
- 20tick連続して到着位置に収まったときに一度だけ`SUCCEEDED/arrived`。到着後も100tick落ち着くまでは再接近し、プレイヤーが動けば安定時間を測り直す。
- 危険回避を優先し、その時間を連続到着に含めない。候補なしでは到着成功にしない。呼び寄せ全体の上限は従来どおり400tick。
- ローカルCALLの距離ワープ・同一ownerの次元移動では、新しい身体世代で再照合して接近を継続する。元の開始時刻を保ち、ワープで期限を延長しない。切断・死亡・owner交代の旧CALLは再実行しない。

20tickは通常動作時の約1秒。ゲームのポーズ・サーバーの遅延で実時間は変わる。

## 作業情報の流用

正本はadapterの`PlayerObserver`が既に通常観測へ送っている`player.block_breaking_active`。既存の`interactionManager.isBreakingBlock()`を共有メソッドへまとめ、通常観測と身体への配送で同じ取得処理を使う。

- 5client tickごとに既存の身体bridgeへ現在値を送る。`false`も送り、採掘終了を伝える。
- `OwnerWorkObservation(context, observedServerTick, working)`は同じowner・body・epoch・dimensionへ束縛する。serverの受理は観測tickから20tick以内。同じtickの再送・古い値・未来・世代違い・working欠損で状態や期限を更新しない。
- 未観測・期限切れは、配置判断だけ横／後ろへ寄せる。「作業中を観測した」という事実には昇格させない。初回出現も正面を空け、その後の新しい観測で正面へ寄る。
- 設置中・クラフト中の専用観測は現行adapterにないため、今回の判定には含まない。過去10秒の破壊履歴や、屋内・道具などを合わせたRustの「採掘中」場面投影を、瞬間的な作業状態へ置き換えない。
- APIはv7へ更新。HTTPの`body_observation` v3と`body_autonomy` v1は継続する。

## FOLLOWの開始と保存

初回登録・呼び寄せ・古い保存データからの読込み・復活時にFOLLOWを開始する。毎回`/dogidobody follow`を打つ必要はない。明示したローカルFOLLOW／HOLD／DIRECT／EXPLOREは`DogidoLocalMode`へ保存する。一回の移動・休息・CALL、外部leaseと作業観測は保存しない。外部lease失効時に自動FOLLOWへ切り替えない。

## 音声と分類器

`dogido_recall`は別作業の分類候補として記録された段階で、現行モデルには未採用。今回の変更は身体側までであり、音声「こっちへおいで」の自動配送は未接続。分類器が採用された段階で、本人の明示依頼を既存の呼び寄せ処理へ接続する。「出て来いドギド！」専用の語句判定や別の召喚処理は追加していない。

試験入口は`/dogidobody call`。現行の身体なしでは通常のActionRequestが持つbody contextもないため、将来の分類器接続時は通常ActionRequestの世代検証を緩めず、同じ`BodyManager.recall`の所有解決へ接続する。

実機確認項目:

1. 登録済み身体で再入場し、FOLLOWの追加入力なしで通常追従する。
2. `/dogidobody call`後に少し移動しても、現在の正面2block以内まで寄り直す。
3. 採掘しながら呼び、横か後ろに収まる。採掘開始／終了の切替も見る。
4. 身体未登録の別の検証用ワールドで呼び、一体だけ出現しパーティクルが出る。再度呼んでも増えない。
5. 遠距離・別次元からの呼び寄せ、明示HOLDの保存、再読み込み、危険中断を確認する。
