# 川柳相談の文ごとの音声（2026-11-02）

川柳WSの会話返答は、全文生成と全文の読み補正を待たず、確定した一文から読み補正・VOICEVOX合成・再生へ進める。通常雑談の既存処理を `speech_stream_runtime/pipeline.rs` にまとめ、文境界、JSON途中の本文抽出、読み辞書、一文先の合成、順次再生、取消と回収を共有する。

## 返答と操作

`respond / explain / ask / compare / show_current / acknowledge_meaning` のactionとspeechの文境界が確定した順で発声する。actionが後置された場合は、その確定を待つ。JSONのキー、reasoning、native toolの名前と引数は読まない。文境界は既存の「。」「！」「？」・改行等を使う。

native toolは、同じChat Completions要求をstreamで受信し、Rigが引数を組み立て終えた呼出しを一度だけ既存の相談処理へ返す。道具だけの応答も、台詞が空のまま受理する。編集・新案・採否・lesson解除は従来の実行と保存を通し、結果文を返す。一度発話へ渡した本文は別の生成で置き換えず、後半の通信・形式・音声が失敗した場合は残りを止める。語句の品質検査や追加モデル呼出しは増やさない。

全文が受理されるまでは、部分本文を全文として表示・履歴へ確定しない。受理後は既存の表示確認または全音声の成功で相談履歴を一度だけ確定し、後段で全文を再合成・再生しない。評価記録も一度だけ保存する。取消された前半入力の引継ぎとBERTの行分類は今回の変更範囲外。

## 戦闘・取消

既存の川柳相談の所有者を使う。音声中の戦闘pauseでは合成済みの音声を保持し、未完了の文だけ再生し直す。生成中に戦闘で中断された返答は、開始済みの生成を受け取り、既存の未発話記録へ戻す。古い操作の適用、追加推論、二重保存は行わない。明示停止・voice off・接続終了では生成・合成・playerを取消して回収する。

## 検証

`dogido-rust/tests/python/check_workshop_sentence_audio.py` は一文目より後ろのLLM応答を停止できる固定応答を使い、全文受信前の再生、action後置、native toolの分割受信、編集と保存の一度実行、後半失敗、明示停止を検査する。実モデル・実VOICEVOX・スピーカーは使わない。通常雑談の `check_sentence_audio.py` と、川柳の既存の相談・戦闘中断試験も共通処理の回帰確認に使う。

通常起動用の本体で、川柳相談の模擬通信6件・通常雑談の音声試験20件が成功した。音声ありと文字のみの両方で、上五・中七・下五の変更がそれぞれ指定行だけを更新し、編集履歴を一件ずつ追記した。応答の後半を止めた試験では、相談の台詞は一文目から再生し、分割した編集指示は完成するまで発声・保存せず、完成後に一度だけ保存した。修正後の実モデル・実音声は未確認。
