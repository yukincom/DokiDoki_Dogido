# 家庭内の別Macで、一人用のドギドを動かす

**2026-10-03: 旧Python本体の配布・起動と、起動時のconfig/audio書換えは終了。現行はRust本体・Rust音声入力へ統一する。起動の正本は[本体の起動手順](../dogido-rust/README.md)、家庭用の操作は[同梱案内](../scripts/family-client/はじめに.md)。今回の家庭用Rustセットの実機確認は未実施。**

親子はそれぞれのMinecraftアカウントとシングルプレイのワールドで遊ぶ。
各Macに一つずつのドギド本体と記憶を置き、親Macの共有Qwenだけを借りる。
息子側に既にあるVOICEVOXを使い、Whisper・AEC・マイク・再生も息子側で動かす。
MinecraftのLAN公開や、一つのドギドサーバーでの同時マルチセッションは使わない。
既存の[テナンシー計画](multi-user-tenancy.md)を実装したものではない。

## 接続

息子Macの `127.0.0.1:8080` から、親Macの専用SSH（家庭内IPv4・22080番）へ接続し、
親Mac内の `127.0.0.1:22081` にある限定HTTP窓口へ転送する。
窓口は固定の共有Qwen `127.0.0.1:8080` にだけ接続する。
既存の[共有プロファイル](shared-llm-profile.md)でchat / haikuともに `default_model` を使う。
共有Qwenを起動・停止・切り替えず、内部MLXへのfallbackも作らない。
VOICEVOXは息子Macの `127.0.0.1:50021`、ドギドとFabricは既定で同じMacの `127.0.0.1:5055` を使う。
本体と音声入力は同じ設定のbind_host/bind_portを読み、5056へ固定しない。ポートを変更するときはFabricの接続先も合わせる。

親Macは通常ユーザーで専用sshdを前面起動する。OSのリモートログイン、ファイル共有、
アカウント、管理者権限には変更を加えない。専用鍵も通常の `authorized_keys` には追加しない。
親Macのパスワードを息子Macで入力する手順は廃止した。

- 鍵認証だけを許可し、専用の親ホスト鍵を子側に同梱して照合する。
- `MaxSessions 0` でシェル・コマンド・SFTPを拒否し、転送先も固定窓口一つに限定する。
- Qwenの生APIはモデル指定から別モデルや追加コードを読めるため、直接は公開しない。
  固定モデル・文字列メッセージ・既存のtemperature/max_tokensをコードで検証・再構築して送る。
  任意URL、モデル/adapter切替、tools、追加テンプレート、他のAPIを受け付けない。
- デバッグログ用POSTはsourceと文字列行だけを受け取る。クライアントはファイルパスを指定できない。
  ターミナル制御文字を除去し、親が選んだ一つの起動別JSONLに保存する。ログをQwenへ送らない。
- Ctrl+C/SIGHUPでは専用sshdの子接続も停止する。OpenSSHの子は別プロセスグループへ移る場合があるため、
  listenerのグループだけを停止せず、専用プロセスの子孫を止める。既存SSH・Qwenには触れない。

## 小さな接続更新セット

作成器は `scripts/build_family_link.py`、ソースは `scripts/family-link/`。
[親向けの手順](../scripts/family-link/はじめに.md)に従い、親が `親Macで起動.command` を開く。
そのとき初めて専用鍵を作り、同じフォルダに `息子Macへ渡す.zip` を生成する。
配布ビルド時には鍵を作らない。親のログイン用秘密やOS設定をコピーしない。

息子Macの適用先は、Rust本体と必要な補助・資料を備えたドギドフォルダ。
旧Python本体の残るセットやRust部品が不足したセットは、鍵・ファイルへの初回書込み前に拒否する。
小さな接続更新ZIPは本体の移行用ではない。
固定リストの起動スクリプト・確認ツール・案内文だけを更新し、
既存ファイルを控えに残す。全更新対象を先に検査し、余計なファイルやリンクがあれば書き込み前に拒否する。
本体・.env・Python環境・記憶・ワールドは更新対象外。設定メモには受取先の実パスを記入する。
MacのZIP展開で日本語ファイル名の濁点が分解される場合も、NFC正規化して同じ固定リストへ照合する。
Finderの `.DS_Store`・AppleDouble・`__MACOSX` は適用対象にしない。未知の実ファイルの拒否は維持する。

## 親側デバッグログ

親の専用接続画面にSSH接続/切断、Qwen開始/終了/所要時間/usage、息子側02/03の標準出力・エラーを表示する。
保存先は `~/Library/Application Support/Dogido-Qwen-Link/logs/` の起動別JSONL。
息子側にも `logs/family-client/` にログを保存する。発話・句など既存の出力を含み、録音データは転送しない。
Minecraft/Fabric自身のログは対象外。

子側は非同期・有界キューで転送し、通信断時も本体を待たせない。長い通信断・混雑・終了直前には
親へ届かない行があり得るため、完全な調査には息子側のログも使う。親のログには混雑による省略行数を通知する。

## 導入セット

作成器は `scripts/build_family_client.py`、セットの起動・導入スクリプトは
`scripts/family-client/`。操作手順は[同梱する案内](../scripts/family-client/はじめに.md)を参照。
作成器の入力は `--help` で確認できる。入力の本体は実プレイに使っているメインの作業ツリーを指定する。
出力は未使用のフォルダに限定し、既存セットを上書きしない。

- Apple Silicon用のビルド済みRust本体、設定・辞書・端末AI・Chrome・AECのPython補助、
  現行カタログ、国語資料とsource_cards、必要な既定値JSON、出典・ライセンス、定型音声、
  2D UIを含むビルド済みFabric MODを同梱する。Rustコンパイラは受取先へ導入しない。
- 旧Python本体のあるsourceからの作成は拒否する。削除済みの本体を再梱包しない。
- Whisperの実行ファイルと依存ライブラリはコピーしたものだけの参照先を相対化して署名し直す。
  Kotoba Whisperの量子化モデルとSilero VAD、AECのネイティブ実行ファイルも同梱する。
- uvを同梱し、息子MacでPython 3.11と必要な依存を取得する。MLX/Qwenは導入しない。
- 個人の `.env`・仮想環境・記憶・ログ・名前音声・アカウント情報・セーブデータをコピーしない。
- Fabric公式のランチャー用ZIPから既知の2ファイルだけを取り出し、バージョンを配置する。
  同版で起動内容が一致する既存設定は再利用する。公式APIの生成日時とインストーラの日時差、
  空のダミーJARと既存ゲームJARの差では停止せず、既存ファイルを変更しない。
  ランチャーの起動構成は人が専用ゲームディレクトリを指定して作る。既存のアカウントや起動構成を編集しない。
- すべての起動は可視ターミナルの前面プロセス。常駐登録やバックグラウンド起動をしない。

## 記憶とワールド

新規セットの記憶の既定は `.dogido_memory`。既存セットの保存先は `.env` の
`DOGIDO_MEMORY_DIR` を優先する。以前のRust保存先 `.dogido_memory/rust-migration` も指定できる。
起動や接続更新では、記憶・ワールドを移動・削除・コピーせず、複数の記憶を自動統合しない。
旧PythonとRustの別々の保存先がある場合は、使用する正本を明示する。

## 確認範囲

2026-09-18の旧Python配布セットでは、隔離した導入・Fabric配置と既存設定保持、
親Mac内での専用SSH・固定Qwen転送・ログ転送・所有プロセス停止を確認した。
これは過去版の記録であり、今回のRust配布セットの実機確認には数えない。

今回の変更は、Rust以外をhealth確認で受理しないこと、部品不足を更新前に拒否すること、
設定済みポートを使うこと、起動順と所有した子だけの停止を自動試験の対象にする。
録音・モデル生成・サーバー起動のない導入確認は `client_tools/check.py`。
`--network` は既存APIへの応答確認、`--server` はRust本体の準備完了確認に分かれる。

息子Macの家庭内LAN接続、OS音声権限、Minecraftと2D UI、実際の再生、8GBでのメモリ余裕、
親子同時使用時の待ち時間は実機確認が必要。

## 一括起動

息子側は「ドギドを起動.command」一つで専用SSH→Qwen確認→VOICEVOX確認/起動→Rust本体→healthz確認→Rust音声入力へ進む。
`client_tools/start_client.py` を一つの正本として使い、commandに同じPython本文を埋め込まない。
本体のhealthは `runtime=rust` と `dialogue_ready=true` まで確認し、旧Pythonや接続試験だけの本体を採用しない。
一つのターミナルが所有した子だけを停止し、既存01/02の接続や本体は自動停止・流用しない。
本体がまだ準備中なら03を開始しない。設定ミス・子終了時も所有した残りを終了する。

**終了した仕様:** `voicevox_prewarm_enabled` を追加するため旧config.py/audio.pyを起動時に修正する処理は撤去。
変更先はRustの音声配送と、この文書の現行起動経路。既存音源は保持する。
