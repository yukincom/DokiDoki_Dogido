# 身体視点の追加撮影を変化量で絞る

2026-10-27。通常撮影の閾値変更。10秒の静止更新と、明示注視後の一枚は維持する。

## 変更理由

身体の待機浮遊は振幅0.18 block、上下端の差は0.36 block。従来の通常撮影は0.02 block・0.5度の変化で予約を進めていたため、浮遊の折返しや細かな向き直しでも撮影が続いていた。保存済み画像にも約3秒ごとの浮遊による視点差と、1.147秒の間の4枚の向き微調整があった。

## 現在の判定

- 既存の `BodyViewMotion` で、2 client tick静止した現在姿勢を観測基準と比較する。位置の3次元距離が0.5 block以上、またはyaw／pitchのいずれかが10度以上なら通常観測番号を進める。yawは最短の角度差を使う。
- 基準は直前に通常観測番号を進めた姿勢、または明示注視の撮影開始時の観測姿勢。画像の保存成功を待つ番号ではなく、従来の撮影予約用の番号である。
- 閾値未満では基準と10秒の時計を更新しない。小刻みな移動・旋回も基準からの差が閾値に達すれば拾う。途中で閾値を超えても、停止時に元の視点へ戻っていれば追加撮影は起こさない。
- 初回と200 client tick（通常10秒）の静止更新は残す。通常撮影の2 tick静止確認、画像比較用の0.02 blockの移動記録も維持する。
- 明示注視は変化量と静止の条件を使わず、既存の撮影処理で一枚を取得して基準と時計を更新する。同じ方向への再依頼も一枚取得する。

固定の最短撮影間隔は追加しない。短時間でも大きく視点が変われば撮影し、10秒更新では周囲だけの変化も確認する。閾値は今回の浮遊と微調整の記録を踏まえた初期値であり、視覚認識に最適な値と検証したものではない。共有フレームバッファの撮影方法は同じなので、撮影時の画面ノイズ自体を取り除く変更ではない。

## 検証

- `BodyViewMotionTest` 13件成功。浮遊の上下端、小刻みな移動・yaw／pitchの累積、閾値の境界、角度の折返し、停止前の往復、10秒更新、明示撮影の基準と時計の更新を確認した。
- 13:03:27.660〜28.806の保存済み4枚の姿勢を停止姿勢列として旧・新判定へ入力すると、追加撮影の判定は4回から1回になった。その後の大きな旋回は新判定でも対象になる。保存していないtick間の動きや、新しい10秒更新の撮影時点まで再現した結果ではない。
- Java 21で `./gradlew --offline test build` が成功。adapter全333件成功、失敗・skipなし。明示注視の同方向再依頼・遅延予約・番号の単調性の既存検査も含む。配布jarを生成済み。
- 同日、検査済みadapter jarをMinecraftのmodsへ配置し、ビルド元とのSHA-256一致とadapterの重複なしを確認した。旧jarと配置記録は `.dogido_tools/deployments/20261027-body-view-motion-thresholds/` に保持。ゲーム・常駐サービスの起動や再起動は行わず、次回のMinecraft起動から使用する。撮影頻度、画面ノイズの減少、10度未満で変わる近距離の見え方は実機未確認。

現行仕様は[静止時の視覚](2026-10-22-stop-vision.md)、明示注視の契約は[移動と注視の並行](2026-10-26-look-capture-and-darkness.md)を参照。
