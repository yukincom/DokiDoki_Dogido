# 履歴の発話契機（パート2）

入力受付と配送確定の既存処理から、短期履歴へ次の情報を記録する。

| 項目 | 記録内容 |
| --- | --- |
| `occurred_at` | 入力は受付時刻、ドギドの発話は最初の配送確認時刻。RFC3339形式 |
| `utterance_kind` | `player_input`（入力）、`reply`（返答）、`spontaneous`（自発）、`warning`（警告） |
| `reply_to_turn_id` | 返答元の入力ID。対象なし・元IDを保持していない経路はnull |

通常返答の対象は、その返答処理が所有する入力IDを使う。直近の発言やIDの文字列から推測しない。警告・環境反応は、生の`Delivery`があるqueue登録時に契機を保持する。戦闘・環境の緊急発話は警告、環境の通常発話、川柳の前置き、戦闘後の相談の自動再開案内は自発。固定返答の経路は元入力IDを保持しないため、返答先は不明のままとする。

音声完了と表示ACKは既存の共通確定処理を通す。再通知は最初の時刻・契機・返答先を上書きしない。表示確認を音声再生完了へ置き換えず、失敗・取消・旧世代を発話済みにしない。沈黙・相談等の出来事をassistant発話へ変更しない。

生成・操作後に追加する入力にも、元の受付台帳の`created_at`を引き継ぐ。復元では保存済みの3項目だけを戻し、欠落項目へ現在時刻や推測値を足さない。

履歴の保持数・圧縮条件・モデル向け表示は変更しない。表示と対応プロンプトの変更はパート3で扱う。

受入条件は `dogido-rust/tests/acceptance/history_metadata.rs` の13件。実行結果は同ディレクトリの `history_metadata/RESULTS.md` を参照。実機・実音声・実モデルの結果とは区別する。
