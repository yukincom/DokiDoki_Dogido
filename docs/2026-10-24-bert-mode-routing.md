# 川柳と通常対話のBERT分離（2026-10-24）

**状態: 本体の切替を実装。川柳424件版seed42と通常16分類seed48-mobを採用済み。実Minecraftは未確認。** 誤発火が多いというユーザー報告を受け、川柳用とそれ以外のBERTを分ける。掛け軸を対話モードの目印とし、一つの入力を両方へ渡さない。

現行本体は既存workshop状態から配送先を決め、[川柳専用8分類](2026-10-24-senryu-classifier-colab.md)のseed42を使用する。通常側は全16分類のseed48-mobを設定済み。通常モデル未設定の入力には `classifier_model_unavailable` を返し、旧23分類へ戻さない。明示停止と危険警告は既存のコード処理を維持する。

## 切替の基準

掛け軸とBERTの配送先を、Rust本体が持つ同じ「川柳相談の受付状態」から決める。画面のピクセルやフェードの不透明度から逆算せず、既存workshopの開始・終了・戦闘中断・再開を利用する。モデルにモードを選ばせない。

| 本体の状態 | 掛け軸の表示方針 | 新しい入力の配送先 |
|---|---|---|
| 現在のworkshopが開き、相談を受付可能 | 表示 | 川柳BERTのみ |
| workshopなし／終了済み | 非表示 | 通常BERTのみ |
| 戦闘中断中 | 一時非表示、句・未採用案は保持 | 通常BERTのみ。川柳操作は再開後 |
| 観測から安全な再開をコードで確定 | 同じ句を再表示 | 次の入力から川柳BERTのみ |
| 接続・入力対象・観測の有効性を確認できない | 既存の非表示・受付停止条件に従う | どちらにも渡さない |

F1、メニュー／チャット画面、`/dogidoscrollhide`、表示アニメーションは見た目だけの変更として扱い、モードを変えない。表示取得だけの失敗も通常BERTへの切替理由にしない。これにより、文字入力のためにチャット画面を開いただけで、川柳の入力が通常側へ流れることを防ぐ。

現状の [掛け軸API](adapter-api.md#25-ゲーム内の川柳掛け軸) は約400ms周期の読み取り専用snapshotで、表示ACKはない。通常の出現・終了には1秒のフェードがあり、Fabric側の危険検知では本体の更新より先に隠れることもある。そのため、この方針は**画面に実際に描かれたフレームとの厳密な同期を保証しない**。切替時点は本体の状態確定時とし、表示がその状態を追う。

## 入力を片方へ限定する

1. 既存の共通受付で、原文・入力元・接続・入力世代と、その時点のモード／川柳の対象を一度だけ結び付ける。再生待ちの入力も、待ち列に入った時点の対象を保つ。
2. 選んだBERTだけへ現在発話を渡す。履歴を分類入力へ加えず、両方への並列配送、比較推論、もう片方への再分類は行わない。
3. `not_target` は選択した側で操作対象外として扱い、既存の相談・通常会話へ渡す。もう片方のBERTを呼ぶ合図にも、川柳を終了する根拠にもしない。
4. 分類の失敗・タイムアウト・モデル未準備でも、もう片方や旧23分類、LLM分類、語句分類へ流さない。既存の分類失敗として扱い、操作を実行しない。
5. 内部再送・FIFO・戦闘保留からの再受付では、同じ入力に結び付いた有効な結果だけを再利用する。別モードで同じ原文を分類し直さない。

二つのモデルをメモリに載せることと、二つへ入力を渡すことは分ける。既存の共有worker／排他制御を起点に、**両BERTを合わせた実行中の分類を最大1件**にする。切替前の処理を取消・終了確認してから、切替後の処理へ進む。モデルごとに独立した入力受付を増設しない。

## 切替途中の入力と結果

開始・終了・中断・再開・句の入替え・再接続を、入力と結果の照合境界に含める。同じ原文でも、別の句や別のモードに対する結果を現在の操作へ使わない。既存の入力世代、接続instance、workshop IDと取消処理を再利用し、必要な境界情報を共通受付にまとめる。

- 切替前に始まった分類の遅延結果は、切替後の操作へ反映しない。別のBERTへ自動再投入もしない。
- 戦闘前に受付済みの川柳入力を保持する場合は、同じ句・版・接続に対する保留入力として保持する。有効性を再照合して再開後に一度だけ処理し、通常側へ転用しない。成立しなければ取消として扱う。
- 録音・STTが切替をまたぐ場合も、録音開始時の対象を遅れた認識結果へ引き継ぐ。既存の `voice_generation` と受付側の照合を揃え、古い録音を新モードへ付け替えない。
- 危険警告と既存の明示停止はコードが優先する。BERTの完了を待って警告したり、BERTで戦闘後の安全を判定したりしない。

## 分離に伴う操作範囲

川柳側は行指定3種・具体変更3種・終了・対象外の8分類を使う。行指定だけで編集せず、終了だけで未採用案を採用・保存しない。現在句・版・保存整合性の検証は既存コードが担当する。2026-10-28以降、具体変更の語句はLLMの解釈を使い、認識原文との文字列一致では拒否しない。

通常側は川柳操作を含まない16分類の専用モデルを使う。採用したseed48-mobはモブ情報・剣・乗用動物・身体操作など全16分類を扱い、モブ情報と関連対比例の学習中の提示回数を増やした一つのモデルである。現行23分類の出力から川柳ラベルを隠すだけでは、専用モデルへの分離完了としない。

ユーザー確認（2026-10-24）: 「それでいいよ！川柳相談中はそんなことしない！」。川柳相談中は川柳専用に固定し、剣・視線等の通常操作を受け付けない方針で確定した。川柳モード中の入力を通常BERTへ回さない。また、戦闘中断中に新しく発した川柳終了依頼を川柳BERTへ回すこともできない。旧23分類からの操作範囲の変更として、この受付仕様に反映した。両方へ通す例外で埋め合わせない。

## ワールド再入場時の音声復旧（2026-10-25〜26）

ワールド退出後の接続登録が残り、再入場すると登録数が二つになるため、音声入力が休止したままになる不具合を修正した。録音先は登録数ではなく、既存の `Binding::capture` が現在観測を確認できる接続から一つだけ選ぶ。受信時刻と観測時刻の有効期限は既存の10秒を維持し、退出直後に二つが有効な間は待機する。音声contextの読み取りでは登録を削除しない。通常退出と、退出後に届いた旧世代の登録成功は、adapterから既存の接続終了APIを呼んで解放する。これにより再入場を繰り返しても接続数の上限を消費し続けない。

実際に二つの接続が有効なら録音を休止し、片方がvoice offでも他方へ勝手に切り替えない。録音開始時の接続IDと世代は従来どおり最終受付で照合し、退出前の認識結果を新しいワールドへ送らない。

検証状態: Rust全targetは931件成功・1件ignore。再入場、古い録音の拒否、複数の有効接続、voice off、観測時刻の失効を回帰検査した。Fabricは301件成功、配布jarをビルド済み。模擬HTTPでは10回の退出・再入場と、登録応答前の退出後に旧接続が解放されることを確認した。実マイクを使わない音声プロセス検査は35件、実HTTPと模擬モデル・再生による会話配送検査は18件成功。常駐反映後の実機確認は別に記録する。
