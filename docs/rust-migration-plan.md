2026-09-26実装（段階5b）: 安全な新規snapshotと通常会話の実再生完了境界から、自動発句を起動する。通常10分周期・30秒の静けさを維持し、会話中は実再生済みの直近3往復だけをsoft材料へ渡す。生成された見どころを先に再生し、その完了後に同じ観測・材料で句を生成・検査する。発句中の非敵対ambientは抑止し、新入力、敵対観測、雷等の優先警告、観測の失効、次元移動、停止で未完成ジョブを取り消す。途中取消は発句周期をリセットせず、helperとplayerは所有者が終了まで待つ。

検証: Rust231件、既存Python音声入力／AEC37件と5 subtests、Pythonの実処理との区切り27件・Whisper出力11件の比較、release版の実プロセス／HTTP24件を確認。模擬の録音子・Whisper・VADと一時ポートで、部分読み、受付拒否、UTF-8、空認識再試行、VAD失敗時の継続、最新の待機入力だけの処理、期限切れ、SIGINT／SIGTERM、AEC途絶、子プロセス・一時WAVの回収が通過した。Clippy・release build・起動前の非録音確認も通過。実モデル・録音・再生は行わず、試験プロセスは全て回収済み。実マイクでの短い返事・自己音・停止／再起動は未確認で、手順を `dogido-rust/manual-dialogue-check.md` に記載。

## 移行中の構成と切替

```text
既存Fabric／UI ─┬─ Python版ドギド（比較基準）
                └─ Rust版ドギド（移植する機能を順次増やす）
                         │
                         ├─ RigのLLM接続 → 既存MLX API
                         ├─ 既存VOICEVOX API・音声素材
                         └─ 比較用の記憶・ログ

既存のマイク入力 → Rust版の互換API（段階3〜7）
Rustのマイク制御 → 同じ録音／認識エンジン（段階8以降）
```

- 移植用ブランチ `codex/rust-migration` と専用worktreeを作成済み。出発点は `c1891a6` と、SHA-256付きで別途保全した現行差分63ファイル。未関連の差分はこの移植のコミットへ混ぜず、worktree内に引き継いでいる。Python側の新しい修正は、対応する比較ケースと一緒に取り込む。
- 試験時は接続先・ログ・記憶ディレクトリを分ける。実Minecraftに対して発声・操作・正本保存する実装は一つだけ。切替はsessionを閉じた境界で行い、会話途中で両実装に所有権を分けない。
- 比較器は保存済みのLLM応答を再利用し、外部操作を記録に置き換える。要求のkind・messages・設定・呼出順も比較し、別の要求へ同じ応答を流用して不一致を隠さない。既存replayの `--no-audio` だけで、LLM呼出や記憶書込みまで止まるとは扱わない。
- 実モデルの速度比較は同時に走らせず交互に行う。二重の生成負荷をRust移植の遅延として数えない。
- 既存のHTTP・JSON・JSONLとデータIDを維持する。保存はコピーで往復互換性を確かめ、旧版へ戻すために本番データの巻き戻しが必要な方式を避ける。
- エージェントが起動した試験サーバーは、その試験の終了時に停止し、所有する子プロセスの終了も確認する。既存の共有MLXやユーザーが起動したプロセスは試験終了の対象に含めない。

### Rigを使う範囲

当初案の「既存APIへ直接接続」を改め、**RigのLLM接続を先に試し、互換性が確認できたら共通の接続基盤として採用する**。公式READMEではprovider層の `rig-core` とagent実行部分の `rig-agent` が分かれており、[単一のcompletionを直接呼ぶ方法](https://book.rig.rs/playbook/rig-api-call.html#calling-completion-models-directly)も提供されている。まず通常雑談、会話修復の抽出、川柳の生成・検査から共通利用する。

段階1で確認したのは次の三点。現在のMLXとの実接続は成功。比較14件は接続層の検証であり、ドギド全体の状態遷移や会話品質の比較ではない。

1. 接続先を既存MLXに向け、**Chat Completions**を明示して同じモデルへ送れること。OpenAI providerの現在の既定経路であるResponses APIをそのままMLXへ送らない。
2. messages、温度、トークン上限、`chat_template_kwargs.enable_thinking` 等を維持し、返答本文・終了理由・生成トークン数を取り出せること。
3. 単一呼出の回数・再試行・timeoutを把握でき、現在のJSON検査とfallbackへ接続できること。ストリーミングを有効にする変更は後で別に測る。

ゲーム状態、発話の優先、正本・未採用案・保存の判断はドギドのコードが担当する。Rigのagent実行部分を使うなら、段階6の共同編集で既存の有界stepを表現できるかを個別に評価する。毎ターンの再計画や検査回数を増やすことはRig導入の前提にしない。構造化出力の便利機能を使う場合も、既存の意味検証を保持する。

必要な送受信項目がRigの固定した版で扱えない場合は、その不足だけを薄い接続コードで補うか、該当経路の直接HTTPを選ぶ。理由を記録して移植を続け、Rigへの全面適合を着手条件にしない。Vector DB追加やMLXエンジン変更は別計画とする。

UniDic／MeCabの読み、Pythonの正規表現・Unicode処理、端末AIのSDK、Chrome用MCP、AECラッパーは、単純な構文置換では移らない。これらの対応方式の詳細確認は未完了で、段階1のLLM接続とは分け、各機能へ着手するときに行う。読みは同じ辞書・同じ出力で検証する。必要なら機能を絞ったPython helperを一時的に残し、担当機能・呼出形式・撤去条件を記録する。helperが残る段階を「Python不要」とは呼ばない。STT・AECの計算エンジンを独自に再実装することは目標にしない。

## 何を測って合格にするか

| 確認方法 | 対象と判断 |
|---|---|
| 同一入力・同一応答の比較 | 状態遷移、観測の根拠、採否、保存、発話順、割り込み、UI状態。時計・乱数を固定し、IDは対応表で比較する。順序や意味の差を単なる表記差として除外しない |
| 実モデル比較 | 同一のモデル・量子化・プロンプト・生成条件で、日本語の自然さ、訂正理解、観測との整合、川柳の品質、呼出回数を確認。自由文の完全一致は要求しない |
| 実機比較 | 実マイク→STT→判断→LLM→TTS→再生→表示。模擬の再生完了と実際の音声を分ける。無言時の途切れ、周囲の声、敵の割り込みも区別する |
| 保存の互換性 | 現在の記憶をコピーしてRustで読む／追加する→旧Pythonで読む。句、revision、critique、lesson、読み訂正、既存IDを維持する |
| 起動と終了 | 起動中・利用可能・接続失敗を表示し、必要な音声の初回合成を全件事前生成へ戻さない。終了後に今回起動したプロセスが残らない |

音声の体感速度は、**人が話し終えてから返答が聞こえ始めるまで**を主指標とする。サーバー受信からだけの数値で置き換えない。

記録する区間は、発話終了→区切り確定→STT完了→入力受付→判断／各LLM呼出→TTS準備完了→再生開始。各LLM呼出のkind・回数・待ち時間・終了理由・生成トークン数も記録する。並行区間は単純加算せず、同じturnの時刻から待ち時間を求める。再生プロセスの `started` は音が耳に届いた時刻の近似なので、実機では聴取や音声の時刻測定で別に確認する。

通常雑談、訂正、川柳生成、workshop相談を分け、初回／温まった状態／共有MLXが混雑した状態を混ぜない。中央値と遅い側の分布を示す。p95は十分な反復数を確保してから用い、少数の試行では各値と範囲を出す。Rustの速度計測はreleaseビルドで行う。

基準値と許容差は各機能の比較を始めるときに決め、段階0の長い事前作業にしない。現状が遅い経路は既知課題として残し、「旧版と同じだから実用速度に達した」とは扱わない。接続再利用・不要なコピー・待ち列など、測定で見つかった箇所を一つずつ改善する。プロンプト短縮、LLM呼出削減、ストリーミング導入、状態更新の並行化は、それぞれ移植との差を測れる別変更にする。

## 必ず持ち越す具体的なケース

- 「違う」「そういう意味じゃない」からの聞き返しと直後の説明。原文・訂正注記・世界観測を混同しない。
- 猫について尋ねたのに過去のヤギの話へ逸れない。現在見えていない敵を「隠れている」と補作しない。
- 通常の返答を周囲の声で切った場合、取消・失敗した本文を会話済みとして確定しない。
- 情景の生成文を先に発声し、UIの都合で「あっ……ちょっと待って」という固定導入へ差し替えない。
- 句の完成時からworkshop開始。検査が途切れた場合の再照合と、内容不合格による再生成を区別する。
- 検査は合否を先に返し、理由は不合格行だけ。検査内の短い番号はその要求内で元の出典IDへ戻す。検査上限512を維持する。
- 「終了でいいよ」、採用と終了の同時意思、引用・否定・条件を含む発言。正本と未採用案、保存前後を取り違えない。
- 戦闘中断、敵離脱／撃破／爆散後の再開、古い生成結果の取消、句とpendingの保持。
- セッション再接続、UTF-8境界のSTTエラー、AEC停止、不要な全件音声生成の再導入を確認する。

既存の実装に不具合が見つかったときは、そのまま正解データにせず、Rust側で修正してよい。旧版との違いが意図した修正か移植ミスかを区別して記録し、旧Python版を先に直すことは必須にしない。
