# ドギドの視覚入力を時系列フレームにする（2026-11-02）

決定仕様。今回は仕様とソースコメントを変更し、実行時の入力はまだ切り替えない。A・B・Cの変更は完了との本人報告があり、次は視覚入力を優先する。

## Gemmaに見せる内容

既存の身体撮影と会話・環境反応の生成要求を使う。[Gemmaの動画入力](https://ai.google.dev/gemma/docs/capabilities/vision/video)にならい、長辺192pxのドギド視点を撮影順に並べる。ローカルのChat Completionsでは、最後のuserメッセージ内に比較元と今回のPNGを順番に置く（`image_url`）。2枚では各画像の直前に先頭からの相対時刻を付ける。例：撮影間隔が12秒なら `00:00 [比較元の画像] → 00:12 [今回の画像]`。1枚には時刻ラベルは不要。静止画を動画ファイルに変換したり、中間フレームを補ったりしない。

| 撮影の結果 | Gemmaへの入力 |
|---|---|
| 変わった。実際の比較元がある | 比較元と今回の2枚を古い順に送り、「変わった」。変化の内容はGemmaが両方の画から読む。 |
| 変わらない | 今回の1枚と「変わらない」。 |
| 初回・比較不能・比較元を照合できない | 今回の1枚。比較については何も付けない。 |
| 今回の画像を取得できない | 通常会話は既存の観測と履歴を使い、明示注視は既存の画像欠落時の扱いに従う。 |

向きの変化はコードが伝える。比較の両端で撮影した**ドギドの身体**の水平向きを世界の八方位で比較し、例えば北から東に変わったら「体が東向きに変わったで」と一度添える。`BodyViewCamera` は身体のyawから描画時の向きを取り、`BodyViewCapture` はその値を `camera_yaw` として記録している。この値をそのフレームに結び付ける。向きが同じ、または対応する姿勢が取れないときは省く。判定は画素差とは独立で、角度の折返しを扱う。撮影後の最新姿勢、プレイヤーの向き、首だけの動きで身体の旋回を代用しない。向いたことは事実として渡し、画面内の変化がすべて旋回のせいだとは決めない。

実際に緑枠を描いたフレームにだけ「緑のPLAYER枠はプレイヤーの位置やで」と添える。枠が過去の画像だけにある場合も、その一枚への説明にする。モデルにはマス目の読み方、マスの行列番号・明暗の列挙、画像ハッシュ、PNG形式、寸法、撮影ID、身体ID、処理番号、絶対時刻、枠が出なかった内部理由を渡さない。画像の識別・形式・時刻・所有者は引き続きコードが照合する。

## 比較元と生成の責務

Fabricの既存比較が選ぶのは、同じ身体世代で途中に位置移動がなく、画面比率が一致する4枚前。前後は **その比較元の実画像** と今回の実画像を組にする。Fabric→Rustは既存の一撮影一画像の配送とサイズ上限を保つ。Rustの既存セッションの画像保持を直近4枚＋今回までに広げ、Fabricが指定した撮影ID・時刻・ハッシュと世代で受理済み画像を引く。比較元の再送・再撮影・ファイル探索・代わりの一枚で穴を埋めない。枠を付ける前に変化を判定し、送るフレームには各撮影時の枠を使う。接続・世界・身体が変わったら以前の組は引き継がない。古い方だけ欠けた場合も、今回の正当な画像は使う。保持はセッション内だけで、PNGを会話履歴やエピソードに保存しない。

生成は通常会話（文ごとの音声を含む）・画像付き環境反応などの既存の1回に載せる。変化通知は同じ変化で一度だけ。明示撮影は身体の移動と並行し、撮影後の姿勢で破棄しない。新しい入力・接続へ古い画像を転用しない。画像内の場所への身体操作は今回のフレームを基準にする。古い画像のPLAYER枠や対象を、今の移動先や現在の視認にはしない。

## 入力をさらに絞る候補

通常会話では `chat_prompt.rs` が同じ種類の辞書描写をsystemとuserに二重掲載する。必要な回に一度で足りる。環境観測は `world_context` 全体を文字列化しており、`revision` など照合用の値はコード側へ残せる。村人の日課・一般知識は、その話題や反応に関係する場合にだけ渡す候補とする。これらは画像以外の別提案。実際の要求で重複と削減量を確認してから変える。現在の視認・音・過去の視認・プレイヤーの発言の区別と、直前の会話は答えに必要な情報である。

## 確認すること

- 変化あり・なし・未比較・参照欠落で送った枚数と順序を調べる。2枚なら既存の比較元と一致し、新旧どちらにPLAYER枠があるかを個別に照合する。LLMへ実際に送ったsystem・user・画像パートを確認し、内部ID・ハッシュ・セル説明が別の観測欄や共通指示に残っていないこと、診断側の照合は働いていることを確かめる。
- 保存した画像で「ドギドだけが旋回」「パンダが画面外へ移動」「両方が起きた」を比べる。向きの一文とGemmaの実際の答えを別々に確認し、時刻順を逆転させない。通常・音声先行・環境反応の入力を照合する。
- 同じ発話・観測・履歴で、画像枚数、画像を含む入力全体、発声開始までを測る。既測の86／172は現設定の192×108で画像の区切り込みのトークン数。画像を読めなかった原因や応答時間の改善は未確認。
