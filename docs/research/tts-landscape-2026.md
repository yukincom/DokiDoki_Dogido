## 1. ひとことで

| 問い | 答え |
|---|---|
| 世間は TTS をやっていない？ | **やっている。** LLM ほど一般ニュースに出ないだけ |
| VOICEVOX は古い技術？ | **製品として成熟した世代。** 隣で次世代が動いている |
| 最新＝ドギドに最適？ | **微妙。** 適性・権利・遅延・固定キャラで別評価 |

**盛り上がり ≠ このプロジェクトへの適合。**  
権利（声優・学習データ・キャラ利用規約）もセットで難しい。

## 2. なぜ LLM ばかり更新されて見えるか

| | 言語モデル | 音声合成 |
|---|---|---|
| 話題の単位 | モデル名が一気に変わる | エンジン＋話者＋API＋規約がバラける |
| メディア | 一般ニュースになる | 開発者・同人・AITuber 内で回る |
| 評価 | ベンチ・チャット一発 | **耳**なので比較が拡散しにくい |
| 表の顔 | Chat 製品 | VOICEVOX アプリなど（長く同じ顔） |

「VOICEVOX は昔からある＝技術が止まっている」ではない。  
**表の入口が長く、裏の世代交代が見えにくい。**

## 3. 実際に動いている波（おおよそ 2024〜2026）

日本語ローカル勢でよく挙がる流れ:

| 時期 | 出来事 | ざっくり意味 |
|---|---|---|
| 〜継続 | **VOICEVOX** | 無料・手軽・キャラ多・CPU 可。中品質の定番 |
| 2024 前半 | Style-Bert-VITS2 / JP-Extra | 日本語特化の自然さ・スタイル制御が話題 |
| 2024 後半 | **AivisSpeech** | VOICEVOX 互換 API ＋新しい合成系。乗り換えしやすい、という評価が多い |
| 2025 後半 | CosyVoice 系 | 中国発・多言語。日本語も視野 |
| 2026 初 | **Qwen3-TTS** 等 | 数秒クローン・多言語・ストリーミングが話題 |

世間が「色々盛り上がって見える」のはこの層。  
一方で **用途・環境・権利** が合わないと、ドギドには乗らない。

### ざっくり位置づけ（主観の整理）

| 系統 | 向くこと | 向かないこと（しばしば） |
|---|---|---|
| VOICEVOX | 手軽、短文セリフ、キャッシュ、速度スケール、固定話者 | 感情・自然さの天井 |
| Style-Bert-VITS2 / Aivis | 日本語品質・演技寄りのキャラ | 導入・GPU・運用の重さ |
| Qwen3-TTS 等・最新 OSS | クローン、多言語、研究フロンティア | 固定「相棒声」、関西弁、規約・VRAM |
| クラウド TTS（OpenAI 等） | 指示で話し方、API 一本 | ネット遅延、従量、声の一貫性、権利感 |

## 5. ドギドへの適性（盛り上がりと別軸）

ドギドが TTS に求めるもの:

| 要件 | 重要度 |
|---|---|
| 日本語の短文が自然 | 最高 |
| **固定キャラの声**（毎回別人に聞こえない） | 最高 |
| 速度・間の制御（#13） | 高 |
| 低遅延 or キャッシュ | 高 |
| ローカルで遊べる | 中〜高 |
| 演技・抑揚の幅 | 中（先に「間」） |
| コスト・権利が説明できる | 高 |

ここから見えること:

1. **最新エンジン祭りの勝者 ≠ ドギド最適**  
2. VOICEVOX は「最先端」ではないが、**要件の多くに今も合う**  
3. Aivis 等は「品質を上げたいときの第2候補」になりやすい（互換 API の話がある）  
4. クローン系・有名声の学習は **権利リスクが別問題**（次節）  
5. #13（速度・間）は **エンジン差し替えより先にやる価値がある**

実装上は `SpeechBackend` があるので、本線を捨てずに横に足す設計は可能。

## 6. 権利・倫理（難しいところ）

世間でチラつく論点（プロジェクトとして雑に扱わない）:

| 論点 | 注意 |
|---|---|
| **声優・実在の声のクローン** | 同意のない学習・再現は炎上・法的リスク。ドギドではやらない前提が安全 |
| **キャラクター声の利用規約** | VOICEVOX 各話者・Aivis モデル・配布モデルごとに条件が違う。商用/改変/クレジット要確認 |
| **「AIの声」への社会の温度** | 表現の自由と権利保護が同時に議論されている。プロダクト説明では透明性を |
| **OpenAI 等クラウド TTS** | 利用規約・データの扱い・声の同一性。クレジット実験と本線は分けてよい |
| **cue mp3（悲鳴等）** | 素材のライセンス（現状 cue ディレクトリの由来を守る） |

方針メモ（このリポ向けの当面の態度）:

- **同意のない有名声クローンはしない**
- 話者・モデルを足すなら **利用規約を README / docs に残せるものだけ**
- 品質実験は **ローカル許可モデル or 公式 API** で、本線切り替えは別判断
- LLM クレジットと TTS クラウド課金は目的を分ける（まず言い回し LLM、声は慎重に）

権利は「技術が新しいか」より **「その声を使ってよいか」** が先。
